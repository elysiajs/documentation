<h1 id="_top">Compilación AOT</h1>

Elysia genera una función optimizada por cada ruta para que tu app sea más rápida. La compilación ocurre una sola vez, cuando llega la primera petición a cada ruta. Esto se llama compilación Just-in-time (JIT).

Pero también puedes usar la compilación Ahead-of-time (AOT) para eliminar ese overhead y mantener la app rápida, moviendo la compilación al paso de build.

<span id="export-your-app"></span>
## Exporta tu app

Para usar el plugin de AOT, exporta tu instancia de Elysia.

Crea `build.ts` con la misma ruta de entrada en `entrypoints` y en `aot()`.

<span id="build-and-run"></span>
### Haz el build y ejecútalo

Ejecuta el build desde la raíz de tu proyecto y luego arranca el bundle generado:

```sh
bun run build.ts
bun dist/index.js
```

<span id="multiple-apps"></span>
### Varias apps

El plugin de AOT compila tu app principal: el export `app`; si no existe, el export `default`; y si tampoco existe, la única instancia de Elysia que exporte la entrada.

Cualquier otra instancia de Elysia exportada que tenga un `name` y al menos una ruta recibe su propio manifiesto de rutas compiladas, identificado por ese nombre:

```ts title="src/index.ts"
import { Elysia, t } from 'elysia'

export const api = new Elysia({ name: 'api', prefix: '/api' })
	.post('/state', {
		body: t.Object({ theme: t.String() })
	}, ({ body }) => body)

export const app = new Elysia({ name: 'app' }).use(api)

export default app
```

Tanto `app.handle()` como `api.handle()` responden desde su propio manifiesto.

Cualquier otra instancia de Elysia del bundle que construya su propio router tiene que tener nombre y exportarse desde la entrada. Es decir, cualquier instancia en la que llames a `.handle()`, `.listen()` o `.compile()`, de la que leas `.fetch` o que montes con `.mount(sub.fetch)` o `.mount(sub.handle)`. Si no, el build termina sin problemas, pero el bundle lanza un error en runtime:

```text
[elysia-aot] App "<name>" has no AOT manifest. Name and export it, .mount() ones too
```

Los plugins que solo se componen con `.use()` no necesitan ni nombre ni export. Tampoco `.mount()` con una función normal, como el `auth.handler` de [Better Auth](/integrations/better-auth/).

Cuando el build compila más de una app, la app principal también tiene que tener nombre, y cada nombre tiene que ser único.

Usa nombres estáticos para las apps, iguales en el build y en runtime. No saques el nombre de una variable de entorno.

<span id="benefits-of-aot"></span>
## Ventajas de AOT

Mover la compilación al paso de build le da a tu app:

- **Arranque y primeras peticiones más rápidos.** Los route handlers y los esquemas se compilan antes de que arranque el servidor.
- **Menor pico de uso de memoria.** El servidor se ahorra las reservas de memoria temporales que necesita la compilación en runtime.
- **Menos código en runtime.** AOT detecta los módulos de Elysia que no se usan y puede eliminar TypeBox por completo cuando todos los esquemas de TypeBox se pueden compilar.
- **Fusión de valores por defecto más rápida.** AOT precalcula cómo se fusionan los valores por defecto de los esquemas, así que hay menos trabajo al rellenar los valores que faltan.

El código que se genera para las rutas y los esquemas puede aumentar el tamaño del bundle y la memoria retenida al arrancar. Consulta el [resumen de AOT de Elysia 2.0](/blog/elysia-20#ahead-of-time-compilation) para más detalles.

<span id="detect-aot-build"></span>
## Detectar un build de AOT

Puedes detectar desde el código si la app se está ejecutando en un build de AOT. Úsalo para inicializar de forma condicional los servicios externos que no hacen falta durante el build, como conexiones a bases de datos o APIs de terceros.

```ts
import { inAotBuild } from 'elysia'

if (!inAotBuild()) {
	// Initialize external services here.
}
```

<span id="bundler-and-runtime"></span>
## Bundler y runtime

AOT es un plugin de bundler que genera código para tu app de Elysia. Es compatible con Bun, Vite, esbuild, Rspack y unplugin.

#### Target

Si quieres optimizar para un runtime concreto, pon en el `target` del plugin de AOT el runtime que va a ejecutar el bundle:

```ts
aot('src/index.ts', { target: 'bun' })
aot('src/index.ts', { target: 'node' })
aot('src/index.ts', { target: 'workerd' })
```

Para Cloudflare Workers, usa `target: 'workerd'` y sigue la [integración con Cloudflare Workers](/integrations/cloudflare-worker/) para configurar el despliegue.
