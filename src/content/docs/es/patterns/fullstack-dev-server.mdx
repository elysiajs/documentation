<h1 id="_top">Dev server fullstack de Bun</h1>

El [dev server fullstack](https://bun.com/docs/bundler/fullstack) de Bun genera el bundle de los assets del frontend y admite hot module replacement (HMR). Esta guía usa Bun 1.3 o superior y el plugin static de Elysia v2.

Así podemos usar React directamente, sin ningún bundler como Vite o Webpack.

Si no, instálalo a mano:

<InteractiveDoc steps={setupSteps}>

<InteractiveStep>

<span id="set-up-the-server"></span>
## Configura el servidor

Instala el plugin static de Elysia v2:

```bash
bun add elysia@rc @elysia/static@next react react-dom
bun add -d @types/react @types/react-dom
```

:::tip

Configura `bunFullstack: true` y usa await con `staticPlugin()` antes de arrancar el servidor. Por defecto, el plugin sirve archivos estáticos normales; hacer solo el await no activa el bundler de HTML.

:::

</InteractiveStep>

<InteractiveStep>

<span id="create-the-html-entry-point"></span>
### Crea el punto de entrada HTML

Crea `public/index.html` y carga `public/index.tsx` como módulo.

</InteractiveStep>

<InteractiveStep>

<span id="create-the-react-app"></span>
### Crea la app de React

Crea `public/index.tsx` con un componente de contador.

</InteractiveStep>

<InteractiveStep>

<span id="enable-jsx"></span>
### Activa JSX

Activa JSX en `tsconfig.json`.

Abre `http://localhost:3000/public` para ver el resultado.

Bun se encarga del bundle del frontend junto a la API, así que no necesitas un proceso de bundler aparte.

El repositorio de ejemplo combina HMR, [Tailwind](#tailwind-css), TanStack Query, [Eden Treaty](/eden/) y alias de ruta. Usa versiones compatibles con tu versión de Bun y de Elysia.

</InteractiveStep>

<InteractiveStep>

<span id="custom-prefix-path"></span>
## Prefijo de ruta personalizado

Podemos cambiar el prefijo `/public` por defecto pasándole la opción `prefix` a `staticPlugin`.

Así los archivos estáticos se sirven en `/` en lugar de en `/public`.

Consulta el [plugin static](/plugins/static/) para ver más opciones de configuración.

</InteractiveStep>

</InteractiveDoc>

<span id="build-for-production"></span>
## Build para producción

Puedes hacer el build de un servidor fullstack como si fuera un servidor Elysia normal.

```bash
bun build --compile --target bun --outfile server src/index.ts
```

Esto crea un ejecutable llamado `server`. Prueba tanto el build de producción como el HMR en desarrollo.

Cuando arranques el ejecutable **server**, asegúrate de incluir la carpeta **public**, igual que en el entorno de desarrollo.

Consulta [Deploy en producción](/patterns/deploy) para más información.
