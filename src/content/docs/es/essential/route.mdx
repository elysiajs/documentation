<h1 id="_top">Enrutamiento</h1>

Una [API REST](https://es.wikipedia.org/wiki/Transferencia_de_Estado_Representacional) usa la ruta y el método de cada petición para decidir qué handler ejecutar.

<CodePlayground elysia={demo1}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/', 'Elysia')
    .get('/hi', 'Hello!')
    .listen(3000)
```

</CodePlayground>

> Al llamar a `.listen` se inicia un servidor web en el puerto 3000.

Podemos entrar a nuestro servidor desde http://localhost:3000.

- `/` con el método `GET` devuelve `Elysia`.
- `/hi` con el método `GET` devuelve `Hello!`.
- Cualquier otra ruta devuelve un `404`.

Cuando visitas una URL en tu navegador, este envía una petición `GET`.

## Ruta estática

Una ruta estática coincide de forma exacta, sin sorpresas.

- `/` coincide solo con `/`
- `/hi` coincide solo con `/hi`

</InteractiveStep>

<InteractiveStep>

## Ruta dinámica

Agrega `:` seguido de un nombre para capturar su valor.

`/user/:id` coincide con `/user/42`, `/user/abc` y `/user/hello-world`.

</InteractiveStep>

<InteractiveStep>

### Acceder a los parámetros

Lee el valor capturado desde `params` en tu handler.

Cuando `/user/42/profile` coincide con `/user/:id/profile`, `params.id` vale `42`. El handler lo devuelve como respuesta.

</InteractiveStep>

<InteractiveStep>

### Parámetros opcionales

Agrega `?` después del nombre de un parámetro para que sea opcional.

`/user/:id?/profile` coincide tanto con `/user/42/profile` como con `/user/profile`.

Si el parámetro no está presente, su valor será `undefined`.

</InteractiveStep>

<InteractiveStep>

## Comodín

Si agregas `*` al final de una ruta, coincidirá con cualquier ruta que venga después.

`/user/*` coincide con rutas de varios segmentos, como `/user/hello-world/profile`. En este ejemplo, `/user/42` sigue yendo a `/user/:id`, porque las rutas dinámicas tienen prioridad sobre los comodines (consulta la [prioridad de rutas](#prioridad-de-rutas)).

Para `/user/hello-world/profile`, `params['*']` vale `hello-world/profile`.

</InteractiveStep>

## Verbos HTTP

Los [verbos HTTP](https://developer.mozilla.org/es/docs/Web/HTTP/Reference/Methods) son los métodos de las peticiones, como `GET`, `POST` o `PUT`.

<div class="routing-methods">

<Card className="routing-method-card">

<CardTitle>GET</CardTitle>

<Card className="routing-method-card">

<CardTitle>HEAD</CardTitle>

Parecido a **GET**, pero solo devuelve los headers, sin el body.

</Card>

<Card className="routing-method-card">

<CardTitle>POST</CardTitle>

</Card>

</Card>

<Card className="routing-method-card">

<CardTitle>DELETE</CardTitle>

</Card>

Para definir un método estándar, usa el método correspondiente de la instancia de Elysia:

```ts
import { Elysia } from 'elysia'

new Elysia()
	.get('/', 'Hi GET!')
	.post('/', 'Hi POST!')
	.put('/', 'Hi PUT!')
	.patch('/', 'Hi PATCH!')
	.delete('/', 'Hi DELETE!')
	.listen(3000)
```

</section>

<section class="content-layout">

### Método personalizado

Usa `.method` con el nombre del método como primer argumento. El resto funciona igual que con los demás métodos.

```ts
import { Elysia } from 'elysia'

new Elysia()
	.method('PROPFIND', '/', 'Hi PROPFIND!')
	.listen(3000)
```

### Todos los métodos

Captura todos los métodos con `.all`:

```ts
import { Elysia } from 'elysia'

new Elysia()
	.all('/', 'Hi ALL!')
	.listen(3000)
```

## Grupos

Puedes agrupar varias rutas que comparten el mismo prefijo con `.group`:

<CodePlayground elysia={demo3}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .group('/user', (app) =>
        app
            .post('/sign-in', 'Sign in')
            .get('/profile', 'Profile')
    )
    .listen(3000)
```

</CodePlayground>

Es como escribir `/user/sign-in` y `/user/profile` por separado.

### Prefijo

Si toda la instancia comparte el mismo prefijo, podemos definirlo en el constructor:

<CodePlayground elysia={demo4}>

```ts
import { Elysia } from 'elysia'

new Elysia({ prefix: '/user' })
    .post('/sign-in', 'Sign in')
    .get('/profile', 'Profile')
```

</CodePlayground>

La diferencia con `.group` es que el prefijo se aplica a todas las rutas de la instancia, mientras que el grupo solo se aplica a las rutas dentro del callback.
