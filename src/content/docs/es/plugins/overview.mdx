<h1 id="_top">Resumen de plugins</h1>

Elysia está diseñado para ser modular y ligero.

Sigue la misma idea que Arch Linux (uso Arch, btw):

> Las decisiones de diseño se toman caso por caso, por consenso entre los desarrolladores

La idea es que acabes teniendo justo el servidor web eficiente que quieres crear. Además, Elysia incluye plugins ya preparados para los patrones más comunes, para que te resulte más cómodo:

:::note[Versiones de los plugins]

Usa versiones de los plugins cuya peer dependency de Elysia coincida con la de tu aplicación. Las ramas de los plugins para Elysia 2 usan versiones prerelease; las versiones más antiguas de los plugins pueden depender de APIs de Elysia 1 que ya no existen. La lista de plugins de la comunidad de abajo es un directorio, no una garantía de compatibilidad.

:::

## Plugins de la comunidad

-   [Create ElysiaJS](https://github.com/kravetsone/create-elysiajs) - ¡crea la base de tu proyecto de Elysia y su entorno fácilmente (con ayuda para ORM, linters y plugins)!

-   [Remix](https://github.com/kravetsone/elysia-remix) - ¡usa [Remix](https://remix.run/) con soporte para `HMR` (gracias a [`vite`](https://vitejs.dev/))! Cierra una petición de plugin que llevaba muchísimo tiempo abierta: [#12](https://github.com/elysiajs/elysia/issues/12)

-   [Connect middleware](https://github.com/kravetsone/elysia-connect-middleware) - ¡plugin que te permite usar middleware de [`express`](https://www.npmjs.com/package/express)/[`connect`](https://www.npmjs.com/package/connect) directamente en Elysia!

-   [OAuth2](https://github.com/bogeychan/elysia-oauth2) - maneja el flujo de código de autorización de OAuth 2.0
-   [OAuth2 Resource Server](https://github.com/ap-1/elysia-oauth2-resource-server) - un plugin para validar tokens JWT de proveedores OAuth2 contra endpoints JWKS, con soporte para verificar issuer, audience y scope
