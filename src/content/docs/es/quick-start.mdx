<h1 id="_top">Inicio rápido</h1>

Elysia es un framework de backend en TypeScript optimizado para Bun. También puedes ejecutarlo en Node.js o en cualquier entorno de ejecución compatible con Request de Web Standard.

<PageTabs label="Entorno de ejecución">
<TabItem label="Bun">

## Bun

Instala Bun con el comando correspondiente a tu sistema operativo.

<FileCodeBlock label="Sistema operativo para Bun">
<TabItem label="macOS / Linux">

```bash
curl -fsSL https://bun.com/install | bash
```

</TabItem>
<TabItem label="Windows (PowerShell)">

```powershell
powershell -c "irm bun.sh/install.ps1 | iex"
```

</TabItem>
</FileCodeBlock>

Abre una nueva terminal y comprueba la instalación:

```bash
bun --version
```

<PageTabs label="Método de instalación con Bun">
<TabItem label="Instalación automática">

### Instalación automática

Puedes crear un proyecto con `bun create elysia`.

La plantilla usa `latest`, pero aquí queremos usar la versión `rc` de Elysia v2.

```bash
bun create elysia
cd app
bun add elysia@rc
```

Inicia el servidor:

```bash
bun run dev
```

Abre [localhost:3000](http://localhost:3000). Deberías ver `Hello Elysia`.

:::tip[Mantén el servidor en ejecución]

La opción `--watch` reinicia tu servidor cuando cambian los archivos. `dev` es un script que añades al proyecto, no un comando incluido en el propio paquete de Elysia.

:::

</TabItem>
<TabItem label="Instalación manual">

### Instalación manual

Si prefieres empezar con tus propios archivos, crea un proyecto vacío e instala Elysia:

```bash
mkdir app
cd app
bun init -y
bun add elysia@rc
bun add -d @types/bun typescript
```

Crea `src/index.ts`:

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/', () => 'Hello Elysia')
    .listen(3000, ({ hostname, port }) => {
        console.log(`Elysia is running at ${hostname}:${port}`)
    })
```

Incorpora estos scripts a tu `package.json`:

```json
{
    "scripts": {
        "dev": "bun --watch src/index.ts",
        "build": "bun build src/index.ts --target bun --outdir ./dist",
        "start": "NODE_ENV=production bun dist/index.js",
        "test": "bun test"
    }
}
```

| Script | Qué hace |
| --- | --- |
| `bun run dev` | Inicia el servidor y lo recarga cuando cambia el código. |
| `bun run build` | Empaqueta el servidor para producción. |
| `bun run start` | Ejecuta el paquete generado previamente. |
| `bun run test` | Ejecuta las pruebas con el ejecutor de pruebas de Bun. |

Mantén `strict` activado en `tsconfig.json` para que Elysia pueda inferir tus tipos correctamente:

```json
{
    "compilerOptions": {
        "strict": true
    }
}
```

Incorpora esta opción a la configuración que creó `bun init` y conserva los demás ajustes. Ejecuta `bun run dev` y abre [localhost:3000](http://localhost:3000).

## Node.js

Usa una versión de Node.js compatible con el adaptador de Node. Elysia 2 requiere Node `22.18` o posterior. Elige una versión LTS que siga recibiendo mantenimiento en la [página de descargas de Node.js](https://nodejs.org/en/download).

Si ya usas un gestor de paquetes del sistema, estos son los comandos de instalación correspondientes:

<FileCodeBlock label="Sistema operativo para Node.js">
<TabItem label="macOS (Homebrew)">

```bash
brew install node
```

</TabItem>
<TabItem label="Windows (Chocolatey)">

```powershell
choco install nodejs
```

</TabItem>
<TabItem label="Debian / Ubuntu (apt)">

```bash
sudo apt install nodejs npm
```

</TabItem>
<TabItem label="Arch Linux (pacman)">

```bash
sudo pacman -S nodejs npm
```

</TabItem>
</FileCodeBlock>

Después, comprueba la versión con `node --version`. El paquete predeterminado de tu distribución puede ser anterior a la versión que requiere Elysia. Si es necesario, usa un instalador de una versión compatible.

<PageTabs label="Lenguaje para Node.js">
<TabItem label="TypeScript">

### Configuración de TypeScript

Empieza en un nuevo directorio de proyecto con un `package.json`. Puedes crearlo con `npm init -y`. Elige los comandos de tu gestor de paquetes:

<FileCodeBlock>
<TabItem label="Bun">

```bash
bun add elysia@rc @elysia/node@rc
bun add -d tsx @types/node typescript
```

</TabItem>
<TabItem label="pnpm">

```bash
pnpm add elysia@rc @elysia/node@rc typebox exact-mirror openapi-types
pnpm add -D tsx @types/node typescript
```

</TabItem>
<TabItem label="npm">

```bash
npm install elysia@rc @elysia/node@rc
npm install --save-dev tsx @types/node typescript
```

</TabItem>
<TabItem label="Yarn">

```bash
yarn add elysia@rc @elysia/node@rc typebox exact-mirror openapi-types
yarn add -D tsx @types/node typescript
```

</TabItem>
</FileCodeBlock>

Los comandos de pnpm y Yarn enumeran explícitamente las dependencias pares que Elysia necesita en tiempo de ejecución. Así también funcionan cuando la instalación automática de estas dependencias está desactivada. Elysia v2 usa `typebox`, no `@sinclair/typebox`.

`tsx` ejecuta TypeScript durante el desarrollo y ofrece un modo que detecta cambios en los archivos. TypeScript se encarga de la comprobación de tipos y genera el JavaScript para producción.

Crea `src/index.ts`:

```ts
import { Elysia } from 'elysia'
import { node } from '@elysia/node'

new Elysia({ adapter: node() })
    .get('/', () => 'Hello Elysia')
    .listen(3000, ({ hostname, port }) => {
        console.log(`Elysia is running at ${hostname}:${port}`)
    })
```

Configura el paquete para usar módulos ES y añade estos scripts:

```json
{
    "type": "module",
    "scripts": {
        "dev": "tsx watch src/index.ts",
        "build": "tsc -p tsconfig.json",
        "start": "node dist/index.js"
    }
}
```

Crea una configuración de TypeScript con `npx tsc --init` y luego configura estas opciones en `tsconfig.json`:

```json
{
    "compilerOptions": {
        "target": "ES2022",
        "module": "NodeNext",
        "moduleResolution": "NodeNext",
        "lib": ["ESNext", "DOM", "DOM.Iterable"],
        "types": ["node"],
        "rootDir": "src",
        "outDir": "dist",
        "strict": true,
        "skipLibCheck": true
    },
    "include": ["src/**/*.ts"]
}
```

El script de compilación lee esta configuración, incluidas la opción `strict` y el directorio de salida. Usa la extensión `.js` al importar tus propios módulos con NodeNext, incluso desde archivos de código fuente TypeScript.

Inicia el servidor de desarrollo:

```bash
npm run dev
```

También puedes usar `bun run dev`, `pnpm dev` o `yarn dev`. Abre [localhost:3000](http://localhost:3000) para ver `Hello Elysia`.

| Script | Qué hace |
| --- | --- |
| `dev` | Ejecuta TypeScript y lo reinicia automáticamente cuando hay cambios. |
| `build` | Comprueba los tipos y genera JavaScript en `dist`. |
| `start` | Ejecuta el JavaScript generado con Node.js. |

Configura `NODE_ENV=production` en tu entorno de despliegue antes de ejecutar `start`. En una shell POSIX puedes usar `NODE_ENV=production npm run start`. En PowerShell, configura primero `$env:NODE_ENV = 'production'`.

### Configuración de JavaScript

También puedes usar JavaScript. El procesamiento de las solicitudes es el mismo. TypeScript añade inferencia de esquemas y comprobación de tipos de extremo a extremo mientras escribes código.

Elige tu gestor de paquetes:

**Bun**

```bash
bun add elysia@rc @elysia/node@rc
```

**pnpm**

```bash
pnpm add elysia@rc @elysia/node@rc typebox exact-mirror openapi-types
```

**npm**

```bash
npm install elysia@rc @elysia/node@rc
```

**Yarn**

```bash
yarn add elysia@rc @elysia/node@rc typebox exact-mirror openapi-types
```

Crea `src/index.js`:

```js
import { Elysia } from 'elysia'
import { node } from '@elysia/node'

new Elysia({ adapter: node() })
    .get('/', () => 'Hello Elysia')
    .listen(3000, ({ hostname, port }) => {
        console.log(`Elysia is running at ${hostname}:${port}`)
    })
```

Añade compatibilidad con módulos ES y los siguientes scripts a `package.json`:

```json
{
    "type": "module",
    "scripts": {
        "dev": "node --watch src/index.js",
        "start": "node src/index.js"
    }
}
```

Ejecuta `npm run dev` para desarrollar con reinicios automáticos. En producción, usa `npm run start` con `NODE_ENV=production` configurado en el entorno.

:::tip[Puedes añadir tipos más adelante]

JavaScript funciona sin un paso de compilación. Si quieres comprobaciones más estrictas en el editor, empieza con la configuración de TypeScript anterior. Ambos ejemplos exponen la misma ruta.

:::

### ¿No aparece en la lista?

Exporta `app.fetch` y pásale las solicitudes entrantes mediante la API de servidor de tu entorno de ejecución:

```ts
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', () => 'Hello Elysia')

export default app.fetch
```

No llames a `.listen()` cuando el framework que aloja tu aplicación se encarga del servidor. Una solicitud directa a este manejador devuelve el mismo saludo:

```ts
const response = await app.fetch(new Request('http://localhost/'))
console.log(await response.text()) // Hello Elysia
```

La compatibilidad de las solicitudes y respuestas es el punto de partida. Consulta la guía de integración para conocer la configuración específica de cada entorno de ejecución y las funciones que admite.
