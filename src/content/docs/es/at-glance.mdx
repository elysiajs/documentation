## TypeScript

Elysia está diseñado para ayudarte a escribir menos TypeScript. Infiera tipos de tus rutas para que puedas concentrarte en la lógica de negocio en lugar de repetir declaraciones.

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

El segmento `:id` se convierte en `params.id` tanto en tiempo de ejecución como en los tipos del handler, sin una declaración manual. Su tipo es `string`.

TypeScript es recomendado, pero no es necesario para usar Elysia. La inferencia de tipos ayuda mientras escribes código; usa un esquema cuando también necesites validación en tiempo de ejecución.

## Integridad de tipos

Importa `t` de Elysia para definir un esquema que valide valores en tiempo de ejecución y proporcione sus tipos de TypeScript. Eso le da a tu input una fuente única de verdad.

Cambiemos el parámetro de ruta de string a number:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```
El esquema viene antes del handler en Elysia 2. Una petición a `/user/123` le da al handler el número `123`; `/user/abc` falla la validación. Pasa el cursor sobre `id` en tu editor para ver el tipo inferido `number`.

El mismo esquema describe la verificación en tiempo de ejecución y el input de TypeScript del handler.

## Esquema estándar

Elysia da soporte a [Standard Schema](https://github.com/standard-schema/standard-schema), por lo que puedes usar versiones compatibles de tu biblioteca de validación preferida.

El ecosistema incluye integraciones con Zod, Valibot, ArkType, Effect Schema, Yup, Joi y [otras implementaciones](https://github.com/standard-schema/standard-schema). Verifica que la biblioteca o adaptador que uses implemente la interfaz Standard Schema.

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilit')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

Aquí Zod convierte el parámetro de ruta a un número, mientras que Valibot requiere `?name=Lilit`. Elysia infiere los tipos validados de ambos esquemas.

## OpenAPI
Elysia usa estándares como OpenAPI, WinterTC y Standard Schema para que puedas conectarlo a herramientas que ya usas.

Agrega el [plugin OpenAPI](/plugins/openapi/) para generar documentación de API a partir de tus rutas y esquemas:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```
 El plugin provee una página de documentación que puedes compartir con tu equipo. Usa una versión compatible con Elysia 2; consulta la referencia del plugin para instalación y configuración.

## OpenAPI Type Gen

Elysia también soporta generar esquemas OpenAPI a partir de tipos TypeScript con `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

Esto aporta un enfoque similar a FastAPI para TypeScript: usa los tipos de tu código como entrada para la generación de documentación en lugar de duplicarlos en anotaciones manuales. Consulta [OpenAPI from types](/patterns/openapi/#openapi-from-types) para su configuración y tipos soportados.

## End-to-end type safety

Type safety doesn't stop at the server. Elysia's client library, **Eden**, lets your frontend use the server's types, in a workflow similar to tRPC.

Export the type of your server from `server.ts`, then import it in `client.ts`:

<FileCodeBlock>
<TabItem label="server.ts">

```ts
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)

export type App = typeof app
```

</TabItem>
<TabItem label="client.ts">

```ts
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

// Request /user/617
const { data } = await app.user({ id: 617 }).get()

console.log(data)
```

</TabItem>
</FileCodeBlock>

Eden uses the existing Elysia types without a separate client code-generation step. The client imports only the server's type, keeping server implementation code out of its bundle.

Elysia is here to help you build a confident backend, and everything you connect to it.

## Type soundness

Successful responses are only part of an API. Elysia can infer **all possible response types**, including errors, so your client can handle them safely.

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

Here, Elysia can return a `number` for a successful request but also infer `401` or `420` error in type-level so client can handle all three cases with type safety.

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

The client can handle the typed success and error results. See [Eden](/eden/) for the client API and [macros](/patterns/macro/) for reusable route behavior.

## Platform agnostic

Elysia is optimized for Bun's native features, but it isn't limited to Bun. Its [WinterTC-compatible](https://wintertc.org/) Request/Response interface makes other runtime integrations possible.

You can use Elysia with:

- Bun.
- [Node.js](/integrations/node/).
- [Deno](/integrations/deno/).
- [Cloudflare Workers](/integrations/cloudflare-worker/).
- [Vercel](/integrations/vercel/).
- [Expo](/integrations/expo/) API routes.
- [Next.js](/integrations/nextjs/) API routes.
- [Astro](/integrations/astro/) API routes.

Each integration describes its adapter and deployment setup. The integrations section has more supported environments.

We want Elysia to feel friendly and welcoming, with a bright, playful design and our hand-drawn anime mascot, *Elysia chan*.

Technology can be approachable and bring a little joy to people's lives. We still take the framework seriously: reliability and performance matter when you're trusting it with your next project.
