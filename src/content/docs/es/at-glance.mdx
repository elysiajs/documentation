## TypeScript

Elysia está pensado para que escribas menos TypeScript. Infiere los tipos desde tus rutas para que te enfoques en la lógica de negocio en vez de andar repitiendo declaraciones.

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

El segmento `:id` se convierte en `params.id` tanto en runtime como en los tipos del handler, sin que tengas que declararlo a mano. Su tipo es `string`.

TypeScript es recomendado, pero no es obligatorio para usar Elysia. La inferencia de tipos te ayuda mientras escribes código; usa un schema cuando también necesites validación en runtime.

## Integridad de tipos

Importa `t` desde Elysia para definir un schema que valide valores en runtime y que además te dé sus tipos de TypeScript. Así tu input tiene una sola fuente de verdad.

Cambiemos el path parameter de string a number:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

El schema va antes del handler en Elysia 2. Una request a `/user/123` le pasa al handler el número `123`; `/user/abc` falla la validación. Pasa el mouse por `id` en tu editor para ver el tipo `number` inferido.

El mismo schema describe la validación en runtime y el input de TypeScript del handler.

## Standard Schema

Elysia soporta [Standard Schema](https://github.com/standard-schema/standard-schema), así que puedes usar versiones compatibles de tu librería de validación favorita.

El ecosistema incluye Zod, Valibot, ArkType, Effect Schema, Yup, integraciones de Joi y [otras implementaciones](https://github.com/standard-schema/standard-schema). Asegúrate de que la librería o el adapter que uses implemente la interfaz de Standard Schema.

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

Aquí Zod convierte el path parameter a number, mientras que Valibot pide `?name=Lilith`. Elysia infiere los tipos ya validados desde ambos schemas.

## OpenAPI

Elysia se lleva bien con estándares como OpenAPI, WinterTC y Standard Schema, así que puedes conectarlo con las herramientas que ya usas.

Agrega el [plugin de OpenAPI](/plugins/openapi/) para generar documentación de la API a partir de tus rutas y schemas:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

El plugin te da una página de documentación que puedes compartir con tu equipo. Usa una release compatible con Elysia 2; revisa la referencia del plugin para la instalación y configuración.

## OpenAPI Type Gen

Elysia también soporta generar schemas de OpenAPI a partir de tipos de TypeScript con `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

Esto trae a TypeScript un enfoque al estilo FastAPI: usa los tipos de tu código como input para generar la documentación, en vez de duplicarlos en anotaciones a mano. Mira [OpenAPI from types](/patterns/openapi/#openapi-from-types) para la configuración y los tipos soportados.

## Type safety de punta a punta

El type safety no se queda solo en el servidor. **Eden**, la librería de cliente de Elysia, deja que tu frontend use los tipos del servidor, en un flujo parecido a tRPC.

Exporta el tipo de tu servidor desde `server.ts` y luego impórtalo en `client.ts`:

<FileCodeBlock>
<TabItem label="server.ts">

```ts
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)

export type App = typeof app
```

</TabItem>
<TabItem label="client.ts">

```ts
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

// Request /user/617
const { data } = await app.user({ id: 617 }).get()

console.log(data)
```

</TabItem>
</FileCodeBlock>

Eden usa los tipos que ya existen de Elysia, sin un paso aparte de generación de código del cliente. El cliente solo importa el tipo del servidor, así que el código de implementación del server no termina en su bundle.

Elysia está aquí para ayudarte a construir un backend en el que puedas confiar, y todo lo que conectes con él.

## Solidez de tipos

Las respuestas exitosas son solo una parte de una API. Elysia puede inferir **todos los tipos de respuesta posibles**, incluidos los errores, para que tu cliente los maneje de forma segura.

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

Aquí Elysia puede devolver un `number` cuando la request sale bien, pero también infiere el error `401` o `420` a nivel de tipos, así el cliente puede manejar los tres casos con type safety.

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

El cliente puede manejar los resultados tipados, tanto de éxito como de error. Mira [Eden](/eden/) para la API del cliente y [macros](/patterns/macro/) para comportamiento de rutas reutilizable.

## Agnóstico de plataforma

Elysia está optimizado para las features nativas de Bun, pero no está limitado a Bun. Su interfaz Request/Response [compatible con WinterTC](https://wintertc.org/) hace posibles otras integraciones de runtime.

Puedes usar Elysia con:

- Bun.
- [Node.js](/integrations/node/).
- [Deno](/integrations/deno/).
- [Cloudflare Workers](/integrations/cloudflare-worker/).
- [Vercel](/integrations/vercel/).
- API routes de [Expo](/integrations/expo/).
- API routes de [Next.js](/integrations/nextjs/).
- API routes de [Astro](/integrations/astro/).

Cada integración explica su adapter y cómo desplegarla. La sección de integraciones tiene más entornos soportados.
