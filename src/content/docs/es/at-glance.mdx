<h1 id="_top">A primera vista</h1>

Elysia es un framework web ergonómico para crear servidores backend. Está diseñado para ofrecer simplicidad y seguridad de tipos, con una API familiar, amplio soporte para TypeScript y optimizaciones para Bun.

Empecemos con un pequeño servidor.

## TypeScript

Elysia está diseñado para ayudarte a escribir menos TypeScript. Infiere tipos de tus rutas para que puedas concentrarte en la lógica de negocio en lugar de repetir declaraciones.

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

El segmento `:id` se convierte en `params.id` tanto en tiempo de ejecución como en los tipos del handler, sin una declaración manual. Su tipo es `string`.

TypeScript es recomendado, pero no es necesario para usar Elysia. La inferencia de tipos ayuda mientras escribes código; usa un esquema cuando también necesites validación en tiempo de ejecución.

## Integridad de tipos

Importa `t` de Elysia para definir un esquema que valide valores en tiempo de ejecución y proporcione sus tipos de TypeScript. Así, tus datos de entrada tienen una única fuente de verdad.

Cambiemos el parámetro de ruta de string a number:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```
El esquema viene antes del handler en Elysia 2. Una petición a `/user/123` le da al handler el número `123`; `/user/abc` falla la validación. Pasa el cursor sobre `id` en tu editor para ver el tipo inferido `number`.

El mismo esquema describe la validación en tiempo de ejecución y los tipos de entrada del handler en TypeScript.

## Standard Schema

Elysia da soporte a [Standard Schema](https://github.com/standard-schema/standard-schema), por lo que puedes usar versiones compatibles de tu biblioteca de validación preferida.

El ecosistema incluye integraciones con Zod, Valibot, ArkType, Effect Schema, Yup, Joi y [otras implementaciones](https://github.com/standard-schema/standard-schema). Verifica que la biblioteca o adaptador que uses implemente la interfaz Standard Schema.

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

Aquí Zod convierte el parámetro de ruta a un número, mientras que Valibot requiere `?name=Lilith`. Elysia infiere los tipos validados de ambos esquemas.

## OpenAPI
Elysia usa estándares como OpenAPI, WinterTC y Standard Schema para que puedas conectarlo a herramientas que ya usas.

Agrega el [plugin OpenAPI](/plugins/openapi/) para generar documentación de API a partir de tus rutas y esquemas:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```
 El plugin provee una página de documentación que puedes compartir con tu equipo. Usa una versión compatible con Elysia 2; consulta la referencia del plugin para instalación y configuración.

## Generación de tipos OpenAPI

Elysia también soporta generar esquemas OpenAPI a partir de tipos TypeScript con `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

Esto aporta un enfoque similar a FastAPI para TypeScript: usa los tipos de tu código como entrada para la generación de documentación en lugar de duplicarlos en anotaciones manuales. Consulta [OpenAPI from types](/patterns/openapi/#openapi-from-types) para su configuración y tipos soportados.

## Seguridad de tipos de extremo a extremo

La seguridad de tipos no termina en el servidor. La biblioteca cliente de Elysia, **Eden**, permite que tu frontend use los tipos del servidor en un flujo de trabajo similar a tRPC.

Exporta el tipo de tu servidor desde `server.ts` y luego impórtalo en `client.ts`:

<FileCodeBlock>
<TabItem label="server.ts">

```ts
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)

export type App = typeof app
```

</TabItem>
<TabItem label="client.ts">

```ts
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

// Request /user/617
const { data } = await app.user({ id: 617 }).get()

console.log(data)
```

</TabItem>
</FileCodeBlock>

Eden usa los tipos existentes de Elysia sin un paso separado de generación de código para el cliente. El cliente importa solo el tipo del servidor, por lo que el código de implementación del servidor queda fuera de su bundle.

Elysia te ayuda a construir un backend confiable y todo lo que conectes a él.

## Solidez de tipos

Las respuestas exitosas son solo una parte de una API. Elysia puede inferir **todos los tipos de respuesta posibles**, incluidos los errores, para que tu cliente pueda manejarlos de forma segura.

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

Aquí, Elysia puede devolver un `number` para una petición exitosa, pero también inferir los errores `401` o `420` a nivel de tipos para que el cliente pueda manejar los tres casos con seguridad de tipos.

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

El cliente puede manejar los resultados tipados de éxito y error. Consulta [Eden](/eden/) para la API del cliente y [macros](/patterns/macro/) para el comportamiento reutilizable de las rutas.

## Independiente de la plataforma

Elysia está optimizado para las características nativas de Bun, pero no se limita a Bun. Su interfaz Request/Response [compatible con WinterTC](https://wintertc.org/) permite integraciones con otros runtimes.

Puedes usar Elysia con:

- Bun.
- [Node.js](/integrations/node/).
- [Deno](/integrations/deno/).
- [Cloudflare Workers](/integrations/cloudflare-worker/).
- [Vercel](/integrations/vercel/).
- Rutas API de [Expo](/integrations/expo/).
- Rutas API de [Next.js](/integrations/nextjs/).
- Rutas API de [Astro](/integrations/astro/).

Cada integración describe su adaptador y configuración de despliegue. La sección de integraciones incluye más entornos compatibles.
