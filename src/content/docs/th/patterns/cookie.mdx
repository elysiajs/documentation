<h1 id="_top">Cookie</h1>

อ่านและอัปเดต cookie ได้ผ่าน object `cookie` ใน handler

ดึง cookie ที่ต้องการออกมาตามชื่อ แล้วใช้ `.value` เพื่ออ่านหรือเปลี่ยนค่า
```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/', ({ cookie: { name } }) => {
        // Get
        name.value

        // Set
        name.value = "New Value"
    })
```

Elysia จะ encode และ decode ค่าที่เป็น object ให้เอง คุณจึงใช้งาน cookie เหมือนเป็น object ได้เลย

:::note[cookie อาจไม่มีค่า]

การอ่าน cookie ตามชื่อจะได้ object `Cookie` กลับมาเสมอ แม้ request จะไม่มี cookie ชื่อนั้นก็ตาม และ `.value` ของมันอาจเป็น `undefined` ได้ ใช้ [schema ของ cookie](#cookie-schema) เพื่อกำหนดหน้าตาของค่า และให้ TypeScript ยังช่วยตรวจให้ได้ต่อไป

:::

## Reactivity
แค่เปลี่ยนค่าหรือ attribute ของ cookie ก็จะมี header `Set-Cookie` เตรียมไว้ใน response ให้แล้ว ไม่ต้องประกอบ header เอง

cookie jar เป็น proxy เมื่ออ่านชื่อไหนก็จะได้ object `Cookie` กลับมา และเมื่ออ่าน `.value` ก็จะได้ค่าของมัน ส่วนการวนลูปใน jar จะไล่ผ่านเฉพาะชื่อ cookie ที่มีอยู่จริง

## การจัดการ cookie
จัดการ cookie ได้ 2 วิธี:

1. กำหนด property โดยตรง
2. ใช้ `set` หรือ `update` เพื่ออัปเดตหลาย property พร้อมกัน

ดูรายละเอียดเพิ่มเติมได้ที่ [การตั้งค่า attribute ของ cookie](#config)

## สเปกของ cookie

cookie คือค่าเล็ก ๆ ที่เบราว์เซอร์เก็บไว้ แล้วส่งไปพร้อมกับ request ที่ตรงเงื่อนไข เหมาะกับ state ที่ต้องติดตัว client ไปด้วย เช่น session identifier

`fetch` ในเบราว์เซอร์จะจัดการ header `Cookie` เอง ถ้า request ต้องใช้ cookie ของเบราว์เซอร์ ให้ใส่ `credentials`:

```ts
fetch('http://localhost:3000/cookie', {
    credentials: 'include'
})
```

กฎเรื่อง cookie และ cross-origin ของเบราว์เซอร์ก็ยังมีผลเหมือนเดิม

## t.Cookie

`t.Cookie()` ใช้กำหนด object ของค่า cookie และรับ [ตัวเลือกเฉพาะของ cookie](#config) เป็น argument ตัวที่สอง:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/cookie', {
        cookie: t.Cookie({
            name: t.String()
        }, {
            secure: true,
            httpOnly: true
        })
    }, ({ cookie }) => cookie.name.value)
```

`secure` และ `httpOnly` ใช้ตั้งค่า cookie ที่เซิร์ฟเวอร์ส่งออกไป ไม่ใช่ property ที่จะพิสูจน์ได้จาก string ของ cookie ที่ส่งเข้ามา

## Codec ของ cookie

Elysia อ่าน cookie จาก request และเขียนกลับไปด้วย ดังนั้น codec ของ field ใน cookie ต้องทำงานได้ทั้งสองทาง ให้ใช้ `t.Codec` โดย decode จะทำงานกับค่าที่ส่งเข้ามา ส่วน encode จะทำงานตอนที่คุณกำหนด `.value`:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/cookie', {
        cookie: t.Object({
            visit: t.Optional(
                t.Codec(t.String())
                    .Decode((value) => new Date(value))
                    .Encode((date) => date.toISOString())
            )
        })
    }, ({ cookie: { visit } }) => {
        const last = visit.value // Date | undefined

        visit.value = new Date() // sent as an ISO string

        return last
    })
```

`t.Encode` และ `t.Decode` ทำงานทางเดียว: `t.Encode` จะ throw เมื่อ request ส่ง cookie นั้นมา และ `t.Decode` จะ throw เมื่อคุณกำหนดค่าให้มัน

การเซ็นไม่ได้เข้ารหัสค่านั้น client ยังอ่านเนื้อหาข้างในได้อยู่

## Config
ใช้ตัวเลือกเหล่านี้ได้ใน constructor หรือใน `t.Cookie` และทุกตัวยกเว้น `secrets` กับ `sign` ยังส่งตอนอัปเดต attribute ของ cookie ได้ด้วย เพราะการเซ็นต้องตั้งค่าที่ระดับแอปหรือ route ไม่ใช่ตอนเขียน cookie แต่ละครั้ง

### secrets
key ที่ใช้เซ็นและตรวจสอบ cookie ชื่อตัวเลือกคือ `secrets` ไม่ใช่ `secret`

รับได้ทั้ง string หรือ array ของ string ถ้าเป็น array จะเปิดใช้ [การหมุนเวียน key](#cookie-rotation) ได้ ใน constructor `secrets` จะเป็น `null` หรือมีค่านี้ปนอยู่ด้วยก็ได้ เพื่อยอมรับ cookie ที่ไม่ได้เซ็นในช่วงเปลี่ยนผ่าน แต่ `t.Cookie` จะไม่รับ `null`

### domain
กำหนดค่าให้กับ [attribute Domain ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.3)

โดยค่าเริ่มต้นจะไม่ได้ตั้ง domain ไว้ และ client ส่วนใหญ่จะถือว่า cookie นี้ใช้ได้เฉพาะ domain ปัจจุบันเท่านั้น


### encode

Elysia 2 ไม่มีตัวเลือก `encode` สำหรับกำหนดวิธี encode cookie เอง Elysia จะ encode ค่าของ cookie ให้ตอน serialize ให้กำหนดค่าผ่าน `.value` ได้เลย

### expires
กำหนด object Date ที่จะใช้เป็นค่าของ [attribute Expires ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.1)

โดยค่าเริ่มต้นจะไม่ได้ตั้งวันหมดอายุไว้ และ client ส่วนใหญ่จะถือว่าเป็น "non-persistent cookie" แล้วลบทิ้งเมื่อเกิดเหตุการณ์อย่างการปิดเบราว์เซอร์

:::tip

[สเปกของ cookie storage model](https://tools.ietf.org/html/rfc6265#section-5.3) ระบุว่าถ้าตั้งทั้ง `expires` และ `maxAge` ไว้ `maxAge` จะมีผลก่อน แต่ client บางตัวอาจไม่ทำตามนี้ ถ้าตั้งทั้งคู่ จึงควรให้ชี้ไปที่วันและเวลาเดียวกัน

:::

### httpOnly
ค่าเริ่มต้น: `false`

กำหนดค่า boolean ให้กับ [attribute HttpOnly ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.6)

ถ้าเป็น truthy จะตั้ง attribute HttpOnly ไว้ ถ้าไม่ใช่ก็จะไม่ตั้ง

โดยค่าเริ่มต้นจะไม่ได้ตั้ง attribute HttpOnly ไว้

:::tip

เมื่อ `httpOnly` เป็น `true` JavaScript ฝั่ง client จะอ่าน cookie ผ่าน `document.cookie` ไม่ได้

:::

### maxAge
ค่าเริ่มต้น: `undefined`

กำหนดตัวเลข (หน่วยเป็นวินาที) ที่จะใช้เป็นค่าของ [attribute Max-Age ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.2)

ตัวเลขที่ส่งมาจะปัดเศษลงเป็นจำนวนเต็ม โดยค่าเริ่มต้นจะไม่ได้ตั้งอายุสูงสุดไว้

:::tip

[สเปกของ cookie storage model](https://tools.ietf.org/html/rfc6265#section-5.3) ระบุว่าถ้าตั้งทั้ง `expires` และ `maxAge` ไว้ `maxAge` จะมีผลก่อน แต่ client บางตัวอาจไม่ทำตามนี้ ถ้าตั้งทั้งคู่ จึงควรให้ชี้ไปที่วันและเวลาเดียวกัน

:::

### path
กำหนดค่าให้กับ [attribute Path ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.4)

ถ้าไม่ได้ระบุ `path` Elysia จะตั้งเป็น `Path=/` ทำให้ cookie ใช้ได้ทั้งเว็บไซต์

### priority
กำหนด string ที่จะใช้เป็นค่าของ [attribute Priority ของ Set-Cookie](https://tools.ietf.org/html/draft-west-cookie-priority-00#section-4.1)
`low` จะตั้ง attribute Priority เป็น Low
`medium` จะตั้ง attribute Priority เป็น Medium ซึ่งเป็น priority เริ่มต้นเมื่อไม่ได้ตั้งค่าไว้
`high` จะตั้ง attribute Priority เป็น High

ดูรายละเอียดเพิ่มเติมของ priority แต่ละระดับได้ใน [สเปก](https://tools.ietf.org/html/draft-west-cookie-priority-00#section-4.1)

:::tip

client แต่ละตัวรองรับ attribute นี้ไม่เหมือนกัน ลองตรวจดูการทำงานในเบราว์เซอร์ที่แอปของคุณรองรับด้วย

:::

### sameSite
กำหนด boolean หรือ string ที่จะใช้เป็นค่าของ [attribute SameSite ของ Set-Cookie](https://tools.ietf.org/html/draft-ietf-httpbis-rfc6265bis-09#section-5.4.7)
`true` จะตั้ง attribute SameSite เป็น Strict เพื่อบังคับ same-site แบบเข้มงวด
`false` จะไม่ตั้ง attribute SameSite
`'lax'` จะตั้ง attribute SameSite เป็น Lax เพื่อบังคับ same-site แบบผ่อนปรน
`'none'` จะตั้ง attribute SameSite เป็น None เพื่อระบุชัดว่าเป็น cookie แบบ cross-site
`'strict'` จะตั้ง attribute SameSite เป็น Strict เพื่อบังคับ same-site แบบเข้มงวด
ดูรายละเอียดเพิ่มเติมของการบังคับแต่ละระดับได้ใน [สเปก](https://tools.ietf.org/html/draft-ietf-httpbis-rfc6265bis-09#section-5.4.7)

:::tip

client แต่ละตัวรองรับ attribute นี้ไม่เหมือนกัน ลองตรวจดูการทำงานในเบราว์เซอร์ที่แอปของคุณรองรับด้วย

:::

### secure
กำหนดค่า boolean ให้กับ [attribute Secure ของ Set-Cookie](https://tools.ietf.org/html/rfc6265#section-5.2.5) ถ้าเป็น truthy จะตั้ง attribute นี้ไว้ ถ้าไม่ใช่ก็จะไม่ตั้ง โดยค่าเริ่มต้นจะไม่ได้ตั้งไว้

:::tip

ระวังตอนตั้งค่านี้เป็น true ด้วยนะ เพราะ client ที่ทำตามสเปกจะไม่ส่ง cookie กลับมาที่เซิร์ฟเวอร์อีก ถ้าเบราว์เซอร์ไม่ได้เชื่อมต่อผ่าน HTTPS

:::
