<h1 id="_top">WebSocket</h1>

WebSocket จะเปิด connection ค้างไว้ ให้ client กับเซิร์ฟเวอร์ส่งข้อความหากันได้ ต่างจากการยิง HTTP request ซ้ำ ๆ ตรงที่แต่ละข้อความไม่ต้องรับส่ง request และ response ใหม่ทุกครั้ง

Elysia ใช้ WebSocket ของ Bun ซึ่งสร้างอยู่บน [uWebSockets](https://github.com/uNetworking/uWebSockets) ส่วน Socket.IO ใช้โปรโตคอลของตัวเองซ้อนอยู่บน transport อีกชั้น ดังนั้นให้ใช้ WebSocket client มาตรฐานกับ route เหล่านี้

## การตรวจสอบข้อความ WebSocket

WebSocket route รับ schema สำหรับข้อมูล request และ response ได้เหมือนกับฝั่ง HTTP ใส่ตัวเลือกไว้ก่อน message handler:

```ts
import { Elysia, t } from 'elysia'
import { websocket } from 'elysia/websocket'

const app = new Elysia()
    .use(websocket())
    .ws('/ws', {
        body: t.Object({ message: t.String() }),
        query: t.Object({ id: t.String() }),
        response: t.Object({
            id: t.String(),
            message: t.String(),
            time: t.Number()
        })
    }, ({ query, body }) => ({
        id: query.id,
        message: body.message,
        time: Date.now()
    }))
    .listen(3000)
```

เชื่อมต่อไปที่ `ws://localhost:3000/ws?id=42` แล้วส่ง `{"message":"Hello"}` ไป response จะมีข้อความนั้น `id` จาก query และ timestamp ปัจจุบัน

property ของ context อย่าง `query` และ `params` จะอยู่บน argument ของ socket โดยตรงใน Elysia 2 ให้ใช้ `ws.query` ไม่ใช่รูปแบบเก่าอย่าง `ws.data.query`

| Property ของ schema | ตรวจสอบ |
| --- | --- |
| `body` | ข้อความที่ส่งเข้ามา |
| `query` | query string ของ URL ที่ใช้เชื่อมต่อ |
| `params` | parameter ใน path |
| `headers` | header ของ upgrade request |
| `cookie` | cookie ของ upgrade request |
| `response` | ข้อความที่ handler return, yield หรือส่งออกไป |

Elysia จะ parse ข้อความที่หน้าตาเป็น JSON ก่อนตรวจสอบ และยังรู้จัก boolean, `null` และ string ตัวเลขที่แปลงได้อย่างปลอดภัยด้วย ข้อความอื่นจะยังเป็น string และข้อความ binary ก็ยังเป็น binary เหมือนเดิม

## การตั้งค่า

ส่งตัวเลือกของ WebSocket ที่ใช้ทั้งเซิร์ฟเวอร์เข้าไปใน `websocket()`:

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket({ idleTimeout: 30 }))
    .ws('/ws', ({ body }) => body)
    .listen(3000)
```

วิธีนี้ใช้แทนตัวเลือก `websocket` แบบเก่าใน constructor โดย Bun adapter ของ Elysia จะใช้ [การตั้งค่า WebSocket ของ Bun](https://bun.sh/docs/api/websockets) ค่าเริ่มต้นด้านล่างนี้เป็นค่าเริ่มต้นของ Bun

### perMessageDeflate

ค่าเริ่มต้น: `false`

เปิดการบีบอัดให้ client ที่รองรับ ถ้าไม่ได้เปิดเอง การบีบอัดจะปิดอยู่

### maxPayloadLength

ขนาดสูงสุดของข้อความที่ส่งเข้ามา หน่วยเป็นไบต์ ค่าเริ่มต้นของ Bun คือ `16 * 1024 * 1024` (16 MiB)

### idleTimeout

ค่าเริ่มต้น: `120` วินาที

ปิด connection ที่ไม่มีการใช้งาน เมื่อไม่มีข้อความหรือ ping เข้ามาเกินเวลานี้

### backpressureLimit

ค่าเริ่มต้น: `16 * 1024 * 1024` ไบต์ (16 MiB)

จำนวนไบต์สูงสุดที่ buffer ไว้ได้ต่อหนึ่ง connection

### closeOnBackpressureLimit

ค่าเริ่มต้น: `false`

ปิด connection เมื่อถึงขีดจำกัด backpressure

## Methods

ใช้ `.ws()` เพื่อลงทะเบียน WebSocket route โดย argument ของ socket จะมี method อย่าง `send`, `publish`, `subscribe` และ `close` ให้ใช้ พร้อมกับ property ของ context ของ route

## ws

`.ws(path, handler)` ใช้ลงทะเบียน message handler ถ้าต้องการ schema หรือ lifecycle hook ด้วย ให้ใช้ `.ws(path, options, handler)`

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', ({ body }) => body)
    .listen(3000)
```

จะใช้แบบ 2 argument ที่ส่ง object ก็ได้เหมือนกัน:

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        message(ws, message) {
            ws.send(message)
        }
    })
    .listen(3000)
```

- `path` คือ route ที่เปิดให้ WebSocket client เชื่อมต่อ
- `options` ใช้ตั้งค่า schema และ lifecycle callback
- `handler` จัดการแต่ละข้อความที่เข้ามา ถ้าส่ง handler แยกไว้แล้ว ไม่ต้องใส่ `options.message` ซ้ำ

ถ้าทำได้ ให้ return หรือ yield ค่าออกไป เพื่อให้ infer type ของ response ได้ แต่ถ้าต้องการส่งเองก็ยังใช้ `ws.send()` ได้อยู่

## WebSocketHandler

ตัวเลือกของ route ใส่ได้ทั้ง callback ของ connection และของข้อความ, schema และตัวเลือกสำหรับปรับแต่ง WebSocket ซึ่ง callback เหล่านี้จะได้รับ socket wrapper ของ Elysia ที่มี context ของ request อยู่ที่ระดับบนสุด

หัวข้อต่อไปนี้จะอธิบาย callback เหล่านั้น

## open

ทำงานเมื่อ connection เปิดขึ้น โดยจะได้รับ argument ของ socket

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        open(ws) {
            console.log('Connected', ws.id)
        },
        message: ({ body }) => body
    })
```

`ws.id` ใช้ระบุ connection ส่วน property อื่นของ socket ก็มี `remoteAddress`, `readyState` รวมถึง `query`, `params` และค่าที่ derive ไว้ของ route

## message

ทำงานทุกครั้งที่มีข้อความเข้ามา ค่าที่ parse และตรวจสอบแล้วจะอยู่ใน `ws.body` และเป็น argument ตัวที่สองของ callback ด้วย

```ts
import { Elysia, t } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        body: t.String(),
        message(ws, message) {
            return message.toUpperCase()
        }
    })
```

schema `body` เป็นตัวกำหนด type ของข้อความ ถ้าไม่มี schema ให้ถือว่าค่าที่ parse แล้วเป็น unknown อย่าเพิ่งคิดเอาเองว่าทุกข้อความเป็น string

## close

ทำงานเมื่อ connection ปิดลง โดยจะได้รับ socket, close code และ reason

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        close(ws, code, reason) {
            console.log('Disconnected', ws.id, code, reason)
        },
        message: ({ body }) => body
    })
```

## drain

ทำงานเมื่อ socket รับข้อมูลเพิ่มได้อีกครั้งหลังเกิด backpressure โดยจะได้รับแค่ socket ส่วน close code และ reason เป็นของ `close` ไม่ใช่ `drain`

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        drain(ws) {
            console.log('Ready for more data', ws.id)
        },
        message: ({ body }) => body
    })
```

## parse

hook `parse` ของ WebSocket จะประมวลผลแต่ละข้อความหลังการ parse ตามค่าเริ่มต้น และก่อนตรวจสอบข้อความ โดยได้รับ socket และค่าที่ parse แล้ว ให้ return ค่าใหม่เพื่อแทนที่ หรือ return `undefined` เพื่อใช้ค่าเดิม

```ts
import { Elysia, t } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        body: t.String(),
        parse(_ws, message) {
            if (typeof message === 'string') return message.trim()
        }
    }, ({ body }) => body)
```

hook นี้ต่างจาก HTTP body parser ของ upgrade request

## beforeHandle

ทำงานก่อน connection จะ upgrade และยังมีส่วนในการจัดการข้อความก่อนถึง message handler ด้วย ถ้า return status กลับไป ก็จะปฏิเสธการ upgrade ก่อนที่ socket จะเปิด

```ts
import { Elysia, status } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        beforeHandle() {
            return status(403, 'This socket is closed to new connections')
        }
    }, ({ body }) => body)
```

ถ้าต้องยืนยันตัวตน ให้ตรวจ credential ของ connection ที่นี่ ส่วนการตรวจสอบข้อความให้ไปใส่ใน schema `body`

## transform

ทำงานก่อน validation ใน lifecycle ของ WebSocket ปัจจุบัน hook นี้จะทำงานตอน upgrade และทำงานอีกครั้งกับทุกข้อความ จึงอย่าคิดว่ามันจะทำงานแค่ครั้งเดียวต่อ connection

## transformMessage

ตัวเลือก `transformMessage` แบบเก่าไม่มีในตัวเลือกของ WebSocket route ใน Elysia 2 แล้ว ให้ใช้ [`parse`](#parse) เพื่อแปลงแต่ละข้อความก่อน validation

## upgrade

ใช้ `upgrade` เพื่อเพิ่ม header ของ response ให้กับ handshake ของ WebSocket รับได้ทั้ง object แบบ static หรือฟังก์ชันที่รับ context ของการ upgrade

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'

new Elysia()
    .use(websocket())
    .ws('/ws', {
        upgrade: { 'x-powered-by': 'Elysia' }
    }, ({ body }) => body)
```

ถ้าต้องการตรวจสอบ header ของ request ที่เข้ามา ให้ใช้ schema `headers` แทน
