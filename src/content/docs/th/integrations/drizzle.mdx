<h1 id="_top">Drizzle</h1>

Drizzle ORM คือ TypeScript ORM แบบ headless ที่เน้น type safety และประสบการณ์ของนักพัฒนา

สำหรับแอป Elysia v2 ให้[ตรวจสอบข้อมูลที่ขอบเขตของฐานข้อมูล](#ตรวจสอบข้อมูลที่ขอบเขตของฐานข้อมูลใน-v2)ด้วย schema ของ Elysia เอง ส่วนสูตรแบบเดิมของ v1 จะแปลง Drizzle schema เป็น validation model ของ Elysia ด้วย `drizzle-typebox`

:::caution[ความเข้ากันได้ของ TypeBox]

Elysia v2 ใช้แพ็กเกจ `typebox` 1.x ส่วนสูตร `drizzle-typebox` ด้านล่างใช้กับ `@sinclair/typebox` 0.x รวมถึง symbol `Kind` และ type `BuildSchema` ของมัน การ pin แพ็กเกจรุ่นเก่านั้นไม่ได้ทำให้เข้ากันได้กับ v2 ให้เก็บสูตรนี้ไว้เป็นข้อมูลอ้างอิงสำหรับแพ็กเกจเวอร์ชันเหล่านั้น สำหรับแอป v2 ให้ใช้ generator ที่สร้าง schema ที่เข้ากันได้ หรือประกาศ validation schema ของ Elysia ไว้ที่ขอบเขตของฐานข้อมูล

:::

### Drizzle TypeBox
[`t` ของ Elysia](/essential/validation/#typebox) ขยายมาจาก TypeBox ความเข้ากันได้ของ schema ขึ้นอยู่กับเวอร์ชันของ TypeBox ที่ generator ใช้

เราแปลง Drizzle schema เป็น TypeBox schema ได้ด้วย ["drizzle-typebox"](https://npmjs.org/package/drizzle-typebox) แล้วนำไปใช้ใน schema validation ของ Elysia v1 ได้โดยตรง

### สูตรของ v1 ทำงานอย่างไร:
1. ประกาศ schema ของฐานข้อมูลใน Drizzle
2. แปลง Drizzle schema เป็น validation model ของ Elysia ด้วย `drizzle-typebox`
3. ใช้ validation model ของ Elysia ที่แปลงแล้วในการตรวจสอบ type
4. OpenAPI schema จะถูกสร้างจาก validation model ของ Elysia
5. เพิ่ม [Eden Treaty](/eden) เพื่อเพิ่ม type-safety ให้ frontend

```text
                                                    * ——————————————— *
                                                    |                 |
                                               | -> |  Documentation  |
* ————————— *             * ———————— * OpenAPI |    |                 |
|           |   drizzle-  |          | ——————— |    * ——————————————— *
|  Drizzle  | —————————-> |  Elysia  |
|           |  -typebox   |          | ——————— |    * ——————————————— *
* ————————— *             * ———————— *   Eden  |    |                 |
                                               | -> |  Frontend Code  |
												    |                 |
												    * ——————————————— *

```

## การติดตั้ง
ติดตั้ง Drizzle ด้วยคำสั่งต่อไปนี้:

```bash
bun add drizzle-orm drizzle-typebox
```

สำหรับสูตรแบบเดิม การ pin `@sinclair/typebox` ช่วยเลี่ยงการชนกันระหว่าง schema symbol ของ 0.x ที่ generator ใช้กับ Elysia v1 ส่วน Elysia v2 ประกาศ `typebox >= 1.3.0` เป็น peer dependency แทน

สำหรับโปรเจกต์ v1 ที่มีอยู่ ให้ตรวจสอบ dependency ของ TypeBox ก่อนเลือกเวอร์ชันที่จะ pin:
```bash
grep "@sinclair/typebox" node_modules/elysia/package.json
```

รายการ `overrides` แบบเดิมมีหน้าตาแบบนี้ เวอร์ชันที่แสดงเป็นของสูตรต้นฉบับ อย่าใช้เพื่อทับ dependency `typebox` ของ Elysia v2:
```json
{
  "overrides": {
  	"@sinclair/typebox": "0.32.4"
  }
}
```

## ตรวจสอบข้อมูลที่ขอบเขตของฐานข้อมูลใน v2

คุณยังใช้ Drizzle สำหรับ query ฐานข้อมูลได้ ในขณะที่อธิบาย request ด้วย schema ของ Elysia เอง วิธีนี้เลี่ยงการใช้แพ็กเกจ TypeBox ต่างรุ่นปนกัน:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .post('/sign-up', {
        body: t.Object({
            username: t.String(),
            password: t.String(),
            email: t.String({ format: 'email' })
        })
    }, ({ body }) => {
        // Hash the password and insert the validated fields with Drizzle.
        return { username: body.username }
    })
```

ส่วนที่เหลือเก็บสูตรการสร้าง schema ของ v1 และ utility ของมันไว้สำหรับ generator เวอร์ชันที่เข้ากันได้

## Drizzle schema
สมมติว่าเรามี table `user` ใน codebase ดังนี้:


```ts title="src/database/schema.ts"
import {
    pgTable,
    varchar,
    timestamp
} from 'drizzle-orm/pg-core'

import { createId } from '@paralleldrive/cuid2'

export const user = pgTable(
    'user',
    {
        id: varchar('id')
            .$defaultFn(() => createId())
            .primaryKey(),
        username: varchar('username').notNull().unique(),
        password: varchar('password').notNull(),
        email: varchar('email').notNull().unique(),
        salt: varchar('salt', { length: 64 }).notNull(),
        createdAt: timestamp('created_at').defaultNow().notNull(),
    }
)

export const table = {
	user
} as const

export type Table = typeof table
```


## drizzle-typebox
เราแปลง table `user` เป็น TypeBox model ได้ด้วย `drizzle-typebox`:


```ts title="src/index.ts"
import { Elysia, t } from 'elysia'
import { Type } from '@sinclair/typebox'
import { createInsertSchema } from 'drizzle-typebox'
import { table } from './database/schema'

const _createUser = createInsertSchema(table.user, {
	// Replace email with an email type
	email: Type.String({ format: 'email' })
})

new Elysia()
	.post('/sign-up', {
		body: t.Omit(
			_createUser,
			['id', 'salt', 'createdAt']
		)
	}, ({ body }) => {
		// Create a new user
	})
```


ในแอป Elysia v1 วิธีนี้ทำให้เรานำ schema ของฐานข้อมูลกลับมาใช้ใน validation model ของ Elysia ได้

## Type instantiation is possibly infinite
ถ้าคุณเจอ error อย่าง **Type instantiation is possibly infinite** สาเหตุคือการอ้างอิงวนกลับหากันระหว่าง `drizzle-typebox` กับ `Elysia`

ถ้าเราซ้อน type จาก drizzle-typebox ไว้ใน schema ของ Elysia จะทำให้เกิด type instantiation วนไม่รู้จบ

วิธีป้องกันคือต้อง**ประกาศ type คั่นระหว่าง schema ของ `drizzle-typebox` กับ `Elysia` อย่างชัดเจน**:
```ts
import { Elysia, t } from 'elysia'
import { Type } from '@sinclair/typebox'
import { createInsertSchema } from 'drizzle-typebox'

import { table } from './database/schema'

const _createUser = createInsertSchema(table.user, {
	email: Type.String({ format: 'email' })
})

// ✅ This works, by referencing the type from `drizzle-typebox`
const createUser = t.Omit(
	_createUser,
	['id', 'salt', 'createdAt']
)

// ❌ This will cause an infinite loop of type instantiation
const createUserInline = t.Omit(
	createInsertSchema(table.user, {
		email: Type.String({ format: 'email' })
	}),
	['id', 'salt', 'createdAt']
)
```

ประกาศตัวแปรสำหรับ `drizzle-typebox` ไว้เสมอ แล้วอ้างอิงตัวแปรนั้นเมื่อต้องการใช้ type ของ Elysia

## Utility
เนื่องจากเรามักจะใช้ `t.Pick` และ `t.Omit` เพื่อตัดหรือเลือกบาง field การทำซ้ำขั้นตอนเดิมอาจยุ่งยาก:

ฟังก์ชัน utility เหล่านี้รักษา integration ของ `drizzle-typebox` ไว้สำหรับโปรเจกต์ที่ยังใช้ schema ของ `@sinclair/typebox` ให้ตรวจสอบหมายเหตุเรื่องความเข้ากันได้ด้านบนก่อนใช้กับ Elysia v2:


```ts title="src/database/utils.ts"
/**
 * @lastModified 2025-02-04
 * @see /integrations/drizzle/#utility
 */

import { Kind, type TObject } from '@sinclair/typebox'
import {
    createInsertSchema,
    createSelectSchema,
    BuildSchema,
} from 'drizzle-typebox'

import { table } from './schema'
import type { Table } from 'drizzle-orm'

type Spread<
    T extends TObject | Table,
    Mode extends 'select' | 'insert' | undefined,
> =
    T extends TObject<infer Fields>
        ? {
              [K in keyof Fields]: Fields[K]
          }
        : T extends Table
          ? Mode extends 'select'
              ? BuildSchema<
                    'select',
                    T['_']['columns'],
                    undefined
                >['properties']
              : Mode extends 'insert'
                ? BuildSchema<
                      'insert',
                      T['_']['columns'],
                      undefined
                  >['properties']
                : {}
          : {}

/**
 * Spread a Drizzle schema into a plain object
 */
export const spread = <
    T extends TObject | Table,
    Mode extends 'select' | 'insert' | undefined,
>(
    schema: T,
    mode?: Mode,
): Spread<T, Mode> => {
    const newSchema: Record<string, unknown> = {}
    let table

    switch (mode) {
        case 'insert':
        case 'select':
            if (Kind in schema) {
                table = schema
                break
            }

            table =
                mode === 'insert'
                    ? createInsertSchema(schema)
                    : createSelectSchema(schema)

            break

        default:
            if (!(Kind in schema)) throw new Error('Expect a schema')
            table = schema
    }

    for (const key of Object.keys(table.properties))
        newSchema[key] = table.properties[key]

    return newSchema as any
}

/**
 * Spread a Drizzle Table into a plain object
 *
 * If `mode` is 'insert', the schema will be refined for insert
 * If `mode` is 'select', the schema will be refined for select
 * If `mode` is undefined, the schema will be spread as is, models will need to be refined manually
 */
export const spreads = <
    T extends Record<string, TObject | Table>,
    Mode extends 'select' | 'insert' | undefined,
>(
    models: T,
    mode?: Mode,
): {
    [K in keyof T]: Spread<T[K], Mode>
} => {
    const newSchema: Record<string, unknown> = {}
    const keys = Object.keys(models)

    for (const key of keys) newSchema[key] = spread(models[key], mode)

    return newSchema as any
}
```


ฟังก์ชัน utility นี้จะแปลง Drizzle schema เป็น plain object ซึ่งคุณเลือก field ตามชื่อ property ได้:
```ts
// ✅ Using spread utility function
const user = spread(table.user, 'insert')

const createUser = t.Object({
	id: user.id, // { type: 'string' }
	username: user.username, // { type: 'string' }
	password: user.password // { type: 'string' }
})

// ⚠️ Using t.Pick
const _createUser = createInsertSchema(table.user)

const createUserPicked = t.Pick(
	_createUser,
	['id', 'username', 'password']
)
```

### Table singleton
เราแนะนำให้ใช้รูปแบบ singleton ในการเก็บ schema ของ table วิธีนี้ทำให้เข้าถึง schema ของ table ได้จากทุกที่ใน codebase:


```ts title="src/database/model.ts"
import { table } from './schema'
import { spreads } from './utils'

export const db = {
	insert: spreads({
		user: table.user,
	}, 'insert'),
	select: spreads({
		user: table.user,
	}, 'select')
} as const
```


วิธีนี้ทำให้เราเข้าถึง schema ของ table ได้จากทุกที่ใน codebase:


```ts title="src/index.ts"
import { Elysia, t } from 'elysia'
import { db } from './database/model'

const { user } = db.insert

new Elysia()
	.post('/sign-up', {
		body: t.Object({
			id: user.id,
			username: user.username,
			password: user.password
		})
	}, ({ body }) => {
		// Create a new user
	})
```


### Refinement

ถ้าต้องการ refine type ให้ใช้ `createInsertSchema` และ `createSelectSchema` เพื่อ refine schema โดยตรง


```ts title="src/database/model.ts"
import { Type } from '@sinclair/typebox'
import { createInsertSchema, createSelectSchema } from 'drizzle-typebox'

import { table } from './schema'
import { spreads } from './utils'

export const db = {
	insert: spreads({
		user: createInsertSchema(table.user, {
			email: Type.String({ format: 'email' })
		}),
	}, 'insert'),
	select: spreads({
		user: createSelectSchema(table.user, {
			email: Type.String({ format: 'email' })
		})
	}, 'select')
} as const
```


ในโค้ดด้านบน เรา refine schema ของ `user.email` ให้มี property `format`

ฟังก์ชัน utility `spread` จะข้าม schema ที่ refine แล้ว คุณจึงใช้ได้ตามเดิม
