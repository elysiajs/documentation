<h1 id="_top">Drizzle</h1>

Drizzle ORM เป็น TypeScript ORM แบบ headless ที่เน้นเรื่อง type safety และ developer experience

สำหรับแอป Elysia v2 ให้ [ตรวจสอบข้อมูลตรงรอยต่อกับฐานข้อมูล](#validate-a-v2-database-boundary) ด้วย schema ของ Elysia เอง ส่วนวิธีแบบเดิมสำหรับ v1 จะแปลง Drizzle schema เป็น validation model ของ Elysia ด้วย `drizzle-typebox`

:::caution[ความเข้ากันได้ของ TypeBox]

Elysia v2 ใช้แพ็กเกจ `typebox` 1.x ส่วนวิธีใช้ `drizzle-typebox` ด้านล่างเขียนไว้สำหรับ `@sinclair/typebox` 0.x รวมถึง symbol `Kind` และ type `BuildSchema` ของมัน การล็อกเวอร์ชันแพ็กเกจเก่านั้นไว้ไม่ได้ทำให้ใช้กับ v2 ได้ ให้ถือว่าวิธีนี้เป็นข้อมูลอ้างอิงสำหรับแพ็กเกจเวอร์ชันเหล่านั้น ส่วนแอป v2 ให้ใช้ generator ที่สร้าง schema ที่เข้ากันได้ หรือกำหนด validation schema ของ Elysia ไว้ตรงรอยต่อกับฐานข้อมูล

:::

### Drizzle TypeBox
[`t` ของ Elysia](/essential/validation/#typebox) ต่อยอดมาจาก TypeBox ความเข้ากันได้ของ schema จึงขึ้นอยู่กับเวอร์ชันของ TypeBox ที่ generator ใช้

เราแปลง Drizzle schema เป็น TypeBox schema ได้ด้วย ["drizzle-typebox"](https://npmjs.org/package/drizzle-typebox) แล้วนำไปใช้ใน schema validation ของ Elysia v1 ได้โดยตรง

### หลักการทำงานของวิธีแบบ v1:
1. กำหนด schema ของฐานข้อมูลใน Drizzle
2. แปลง Drizzle schema เป็น validation model ของ Elysia ด้วย `drizzle-typebox`
3. ใช้ validation model ของ Elysia ที่แปลงแล้วเพื่อตรวจสอบ type
4. OpenAPI schema จะสร้างขึ้นจาก validation model ของ Elysia
5. เพิ่ม [Eden Treaty](/eden) เพื่อให้ frontend ของคุณ type-safe ด้วย

```text
                                                    * ——————————————— *
                                                    |                 |
                                               | -> |  Documentation  |
* ————————— *             * ———————— * OpenAPI |    |                 |
|           |   drizzle-  |          | ——————— |    * ——————————————— *
|  Drizzle  | —————————-> |  Elysia  |
|           |  -typebox   |          | ——————— |    * ——————————————— *
* ————————— *             * ———————— *   Eden  |    |                 |
                                               | -> |  Frontend Code  |
												    |                 |
												    * ——————————————— *

```

## การติดตั้ง
ติดตั้ง Drizzle ด้วยคำสั่งนี้:

```bash
bun add drizzle-orm drizzle-typebox
```

สำหรับวิธีแบบเดิม การล็อกเวอร์ชัน `@sinclair/typebox` ช่วยไม่ให้ schema symbol ของ 0.x ที่ generator ใช้ไปชนกับของ Elysia v1 ส่วน Elysia v2 จะประกาศ `typebox >= 1.3.0` เป็น peer dependency แทน

ถ้าเป็นโปรเจกต์ v1 ที่มีอยู่แล้ว ให้ดู dependency ของ TypeBox ก่อนเลือกเวอร์ชันที่จะล็อก:
```bash
grep "@sinclair/typebox" node_modules/elysia/package.json
```

รายการ `overrides` แบบเดิมจะหน้าตาแบบนี้ เวอร์ชันที่เห็นเป็นของวิธีต้นฉบับ อย่านำไป override dependency `typebox` ของ Elysia v2:
```json
{
  "overrides": {
  	"@sinclair/typebox": "0.32.4"
  }
}
```

## ตรวจสอบข้อมูลตรงรอยต่อกับฐานข้อมูลใน v2

คุณยังใช้ Drizzle query ฐานข้อมูลได้ตามเดิม แล้วระบุรูปแบบของ request ด้วย schema ของ Elysia เอง วิธีนี้ช่วยเลี่ยงการใช้แพ็กเกจ TypeBox ต่างรุ่นปนกัน:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .post('/sign-up', {
        body: t.Object({
            username: t.String(),
            password: t.String(),
            email: t.String({ format: 'email' })
        })
    }, ({ body }) => {
        // Hash the password and insert the validated fields with Drizzle.
        return { username: body.username }
    })
```

ส่วนที่เหลือของหน้านี้เก็บวิธีสร้าง schema แบบ v1 และ utility ที่เกี่ยวข้องไว้ สำหรับ generator เวอร์ชันที่เข้ากันได้

## Schema ของ Drizzle
สมมติว่าเรามีตาราง `user` ใน codebase แบบนี้:


```ts title="src/database/schema.ts"
import {
    pgTable,
    varchar,
    timestamp
} from 'drizzle-orm/pg-core'

import { createId } from '@paralleldrive/cuid2'

export const user = pgTable(
    'user',
    {
        id: varchar('id')
            .$defaultFn(() => createId())
            .primaryKey(),
        username: varchar('username').notNull().unique(),
        password: varchar('password').notNull(),
        email: varchar('email').notNull().unique(),
        salt: varchar('salt', { length: 64 }).notNull(),
        createdAt: timestamp('created_at').defaultNow().notNull(),
    }
)

export const table = {
	user
} as const

export type Table = typeof table
```


## drizzle-typebox
เราแปลงตาราง `user` เป็น TypeBox model ได้ด้วย `drizzle-typebox`:


```ts title="src/index.ts"
import { Elysia, t } from 'elysia'
import { Type } from '@sinclair/typebox'
import { createInsertSchema } from 'drizzle-typebox'
import { table } from './database/schema'

const _createUser = createInsertSchema(table.user, {
	// Replace email with an email type
	email: Type.String({ format: 'email' })
})

new Elysia()
	.post('/sign-up', {
		body: t.Omit(
			_createUser,
			['id', 'salt', 'createdAt']
		)
	}, ({ body }) => {
		// Create a new user
	})
```


ในแอป Elysia v1 วิธีนี้ทำให้เรานำ schema ของฐานข้อมูลกลับมาใช้ซ้ำใน validation model ของ Elysia ได้

## Type instantiation is possibly infinite
ถ้าเจอ error อย่าง **Type instantiation is possibly infinite** แสดงว่าเกิดจาก circular reference ระหว่าง `drizzle-typebox` กับ `Elysia`

ถ้าเราซ้อน type จาก drizzle-typebox ไว้ใน schema ของ Elysia จะทำให้เกิดการ instantiate type วนไม่รู้จบ

เพื่อป้องกันปัญหานี้ เราต้อง **ประกาศ type คั่นระหว่าง `drizzle-typebox` กับ schema ของ `Elysia` ให้ชัดเจน**:
```ts
import { Elysia, t } from 'elysia'
import { Type } from '@sinclair/typebox'
import { createInsertSchema } from 'drizzle-typebox'

import { table } from './database/schema'

const _createUser = createInsertSchema(table.user, {
	email: Type.String({ format: 'email' })
})

// ✅ This works, by referencing the type from `drizzle-typebox`
const createUser = t.Omit(
	_createUser,
	['id', 'salt', 'createdAt']
)

// ❌ This will cause an infinite loop of type instantiation
const createUserInline = t.Omit(
	createInsertSchema(table.user, {
		email: Type.String({ format: 'email' })
	}),
	['id', 'salt', 'createdAt']
)
```

ถ้าจะใช้ type ของ Elysia ให้ประกาศตัวแปรสำหรับ `drizzle-typebox` แล้วอ้างอิงตัวแปรนั้นเสมอ

## Utility
เรามักต้องใช้ `t.Pick` และ `t.Omit` เพื่อเลือกหรือตัด field บางตัวออก ซึ่งถ้าต้องทำซ้ำไปเรื่อย ๆ ก็อาจยุ่งยาก:

ฟังก์ชัน utility เหล่านี้เก็บไว้สำหรับการเชื่อมต่อกับ `drizzle-typebox` ในโปรเจกต์ที่ยังใช้ schema ของ `@sinclair/typebox` อยู่ อ่านหมายเหตุเรื่องความเข้ากันได้ด้านบนก่อนนำไปใช้กับ Elysia v2:


```ts title="src/database/utils.ts"
/**
 * @lastModified 2025-02-04
 * @see /integrations/drizzle/#utility
 */

import { Kind, type TObject } from '@sinclair/typebox'
import {
    createInsertSchema,
    createSelectSchema,
    BuildSchema,
} from 'drizzle-typebox'

import { table } from './schema'
import type { Table } from 'drizzle-orm'

type Spread<
    T extends TObject | Table,
    Mode extends 'select' | 'insert' | undefined,
> =
    T extends TObject<infer Fields>
        ? {
              [K in keyof Fields]: Fields[K]
          }
        : T extends Table
          ? Mode extends 'select'
              ? BuildSchema<
                    'select',
                    T['_']['columns'],
                    undefined
                >['properties']
              : Mode extends 'insert'
                ? BuildSchema<
                      'insert',
                      T['_']['columns'],
                      undefined
                  >['properties']
                : {}
          : {}

/**
 * Spread a Drizzle schema into a plain object
 */
export const spread = <
    T extends TObject | Table,
    Mode extends 'select' | 'insert' | undefined,
>(
    schema: T,
    mode?: Mode,
): Spread<T, Mode> => {
    const newSchema: Record<string, unknown> = {}
    let table

    switch (mode) {
        case 'insert':
        case 'select':
            if (Kind in schema) {
                table = schema
                break
            }

            table =
                mode === 'insert'
                    ? createInsertSchema(schema)
                    : createSelectSchema(schema)

            break

        default:
            if (!(Kind in schema)) throw new Error('Expect a schema')
            table = schema
    }

    for (const key of Object.keys(table.properties))
        newSchema[key] = table.properties[key]

    return newSchema as any
}

/**
 * Spread a Drizzle Table into a plain object
 *
 * If `mode` is 'insert', the schema will be refined for insert
 * If `mode` is 'select', the schema will be refined for select
 * If `mode` is undefined, the schema will be spread as is, models will need to be refined manually
 */
export const spreads = <
    T extends Record<string, TObject | Table>,
    Mode extends 'select' | 'insert' | undefined,
>(
    models: T,
    mode?: Mode,
): {
    [K in keyof T]: Spread<T[K], Mode>
} => {
    const newSchema: Record<string, unknown> = {}
    const keys = Object.keys(models)

    for (const key of keys) newSchema[key] = spread(models[key], mode)

    return newSchema as any
}
```


ฟังก์ชัน utility นี้จะแปลง Drizzle schema เป็น object ธรรมดา แล้วคุณก็เลือก field ได้ตามชื่อ property:
```ts
// ✅ Using spread utility function
const user = spread(table.user, 'insert')

const createUser = t.Object({
	id: user.id, // { type: 'string' }
	username: user.username, // { type: 'string' }
	password: user.password // { type: 'string' }
})

// ⚠️ Using t.Pick
const _createUser = createInsertSchema(table.user)

const createUserPicked = t.Pick(
	_createUser,
	['id', 'username', 'password']
)
```

### เก็บ schema ของตารางแบบ singleton
เราแนะนำให้ใช้ singleton pattern เก็บ schema ของตาราง จะได้เข้าถึง schema ของตารางได้จากทุกที่ใน codebase:


```ts title="src/database/model.ts"
import { table } from './schema'
import { spreads } from './utils'

export const db = {
	insert: spreads({
		user: table.user,
	}, 'insert'),
	select: spreads({
		user: table.user,
	}, 'select')
} as const
```


แบบนี้เราก็เข้าถึง schema ของตารางได้จากทุกที่ใน codebase:


```ts title="src/index.ts"
import { Elysia, t } from 'elysia'
import { db } from './database/model'

const { user } = db.insert

new Elysia()
	.post('/sign-up', {
		body: t.Object({
			id: user.id,
			username: user.username,
			password: user.password
		})
	}, ({ body }) => {
		// Create a new user
	})
```


### ปรับแต่ง schema

ถ้าต้องการปรับแต่ง type ให้ละเอียดขึ้น ใช้ `createInsertSchema` และ `createSelectSchema` เพื่อปรับแต่ง schema โดยตรงได้เลย


```ts title="src/database/model.ts"
import { Type } from '@sinclair/typebox'
import { createInsertSchema, createSelectSchema } from 'drizzle-typebox'

import { table } from './schema'
import { spreads } from './utils'

export const db = {
	insert: spreads({
		user: createInsertSchema(table.user, {
			email: Type.String({ format: 'email' })
		}),
	}, 'insert'),
	select: spreads({
		user: createSelectSchema(table.user, {
			email: Type.String({ format: 'email' })
		})
	}, 'select')
} as const
```


ในโค้ดด้านบน เราปรับแต่ง schema ของ `user.email` ให้มี property `format` เพิ่มเข้าไป

ฟังก์ชัน utility `spread` จะข้าม schema ที่ปรับแต่งแล้ว คุณจึงใช้ได้ตามเดิมเลย
