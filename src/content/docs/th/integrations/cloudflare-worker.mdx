<h1 id="_top">Cloudflare Worker</h1>

Elysia รันบน Cloudflare Workers ได้ด้วย request และ response แบบ Web Standard

สำหรับ Elysia v2 ไม่ต้องใช้ Cloudflare adapter คุณเลือกได้ว่าจะ:
1. คอมไพล์ route handler ตอนเริ่มทำงาน
2. คอมไพล์ route handler ตอน build

### คอมไพล์ตอนเริ่มทำงาน

วิธีที่ง่ายที่สุดในการเริ่มต้นคือคอมไพล์ตอนเริ่มทำงาน

1. เพิ่ม `compile` ก่อน export แอป:

```ts title="src/index.ts"
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', () => 'Hello Cloudflare Worker!')
    .compile()

export default {
    fetch: (request: Request) => app.handle(request)
}
```

แต่การคอมไพล์ handler ตอนเริ่มทำงานมีภาระเพิ่ม ซึ่งเลี่ยงได้ด้วยการคอมไพล์ตอน build

### คอมไพล์ตอน build

1. ใช้ [Wrangler](https://developers.cloudflare.com/workers/wrangler/install-and-update) ตั้งค่าโปรเจกต์:

```bash
wrangler init elysia-on-cloudflare
bun add elysia@rc
bun add -d esbuild
```

2. ประกาศแอป Elysia แล้ว export ทั้ง instance ของ Elysia และ fetch handler ของ Worker:

```ts title="src/index.ts"
import { Elysia } from 'elysia'

// export here for AOT
export const app = new Elysia()
    .get('/', () => 'Hello Cloudflare Worker!')

export default {
    fetch: (request: Request) => app.handle(request)
}
```

3. คอมไพล์ handler ของ Elysia สำหรับ `workerd` ระหว่าง build:

```ts title="build.ts"
import * as esbuild from 'esbuild'
import { aot } from 'elysia/plugin/aot/esbuild'

await esbuild.build({
    entryPoints: ['src/index.ts'],
    bundle: true,
    format: 'esm',
    outfile: 'dist/worker.js',
    conditions: ['workerd', 'worker', 'browser', 'import'],
    platform: 'browser',
    target: 'esnext',
    external: ['node:*', 'cloudflare:*'],
    plugins: [aot('src/index.ts', { target: 'workerd' })]
})
```

4. ชี้ Wrangler ไปยัง bundle ที่สร้างขึ้น เลือกใช้ JSONC หรือ TOML อย่างใดอย่างหนึ่ง:

```jsonc title="wrangler.jsonc"
{
    "$schema": "node_modules/wrangler/config-schema.json",
    "name": "elysia-on-cloudflare",
    "main": "dist/worker.js",
    "compatibility_date": "2025-09-06",
    "compatibility_flags": ["nodejs_compat"],
    "build": { "command": "bun build.ts" }
}
```

```toml title="wrangler.toml"
name = "elysia-on-cloudflare"
main = "dist/worker.js"
compatibility_date = "2025-09-06"
compatibility_flags = ["nodejs_compat"]

[build]
command = "bun build.ts"
```

compatibility date และ flag `nodejs_compat` ตรงกับ fixture ของ Cloudflare ใน Elysia v2 ให้คง flag นี้ไว้สำหรับการตั้งค่านี้ คำแนะนำของ v1 ที่ให้ตัด flag นี้ออกไม่ใช้กับกรณีนี้

5. เริ่ม development server:

```bash
wrangler dev
```

คำสั่งนี้จะเริ่ม Worker บนเครื่องที่ `http://localhost:8787` ถ้าต้องการ deploy ให้รัน `wrangler deploy`

### pnpm
ถ้าการตั้งค่า pnpm ของคุณไม่ได้ติดตั้ง peer dependency ให้ ให้เพิ่ม peer ที่ Elysia v2 ต้องใช้อย่างชัดเจน:

```bash
pnpm add typebox exact-mirror openapi-types
```

## ข้อจำกัด
ต่อไปนี้คือข้อจำกัดที่ทราบแล้วของการใช้ Elysia บน Cloudflare Workers:

1. `file()` และ[ปลั๊กอิน Static](/plugins/static) ต้องไม่สันนิษฐานว่าเข้าถึง filesystem ของเครื่องที่ใช้พัฒนาได้ Workers มี [virtual filesystem](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/) ให้ รวมถึงกับการตั้งค่า compatibility ด้านบน ให้ใช้ [static asset](#ไฟล์-static) สำหรับไฟล์ที่ต้องการเผยแพร่
2. สร้าง [OpenAPI type](/blog/openapi-type-gen/) ระหว่าง build เพราะ Worker ตรวจไฟล์ซอร์ส TypeScript ที่ไม่ได้อยู่ใน bundle ไม่ได้
3. หลีกเลี่ยงปลั๊กอินที่สร้าง object ที่ใช้ได้เฉพาะตอน runtime ระหว่าง build หรือตอน initialize โมดูล เพราะ Workers จำกัด operation บางอย่างที่อยู่นอกการจัดการ request
4. ใช้ handler แบบฟังก์ชันเมื่อคืนค่า เพื่อให้การสร้าง response เกิดขึ้นระหว่างจัดการ request:

```typescript
import { Elysia } from 'elysia'

new Elysia()
    .get('/', () => 'Hello Elysia')
```

## ไฟล์ static
ใช้[การให้บริการไฟล์ static ในตัวของ Cloudflare](https://developers.cloudflare.com/workers/static-assets/) เพื่อเผยแพร่ไดเรกทอรี `public` โดยไม่ต้องพึ่งปลั๊กอิน static ที่อาศัย filesystem

เพิ่มสิ่งต่อไปนี้ลงในการตั้งค่า wrangler:


```jsonc title="wrangler.jsonc"
{
    "$schema": "node_modules/wrangler/config-schema.json",
    "name": "elysia-on-cloudflare",
    "main": "dist/worker.js",
    "compatibility_date": "2025-09-06",
    "compatibility_flags": ["nodejs_compat"],
    "build": { "command": "bun build.ts" },
    "assets": { "directory": "public" }
}
```

```toml title="wrangler.toml"
name = "elysia-on-cloudflare"
main = "dist/worker.js"
compatibility_date = "2025-09-06"
compatibility_flags = ["nodejs_compat"]
assets = { directory = "public" }

[build]
command = "bun build.ts"
```


สร้างโฟลเดอร์ `public` แล้ววางไฟล์ static ไว้ในนั้น

ตัวอย่างเช่น ถ้าคุณมีโครงสร้างโฟลเดอร์แบบนี้:

<FileTree

คุณจะเข้าถึงไฟล์ static ได้จาก path ต่อไปนี้:
- **http://localhost:8787/kyuukurarin.mp4**
- **http://localhost:8787/static/mika.webp**

## Bindings
คุณใช้ binding ของ Cloudflare Workers ได้ด้วยการ import `env` จาก `cloudflare:workers` ให้ import ไว้ภายใน handler เพื่อให้ขั้นตอน build ไม่ต้อง resolve โมดูลที่ใช้ได้เฉพาะใน Worker

```ts title="src/index.ts"
import { Elysia } from 'elysia'

export const app = new Elysia()
    .get('/', async () => {
        const { env } = await import('cloudflare:workers')
        return `Hello ${await env.KV.get('my-key')}`
    })

export default {
    fetch: (request: Request) => app.handle(request)
}
```

ตั้งค่า binding `KV` ใน Wrangler แล้วสร้าง type ของ TypeScript ด้วย `wrangler types` ส่วน import ภายนอกแบบ `cloudflare:*` จะยังใช้ได้ใน runtime ของ Worker

ดูข้อมูลเพิ่มเติมเกี่ยวกับ binding ได้ที่ [Cloudflare Workers: Bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/#importing-env-as-a-global)

## การคอมไพล์แบบ AoT
ใน v1 นั้น Workers เดิมต้องใช้ `aot: false` ต่อมา Cloudflare เพิ่ม[การคอมไพล์ Function ระหว่างเริ่มทำงาน](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-eval-during-startup) และ Cloudflare adapter ของ Elysia 1.4.7 ก็ใช้ความสามารถนี้กับ compatibility date ตั้งแต่ `2025-06-01` ขึ้นไป

Elysia v2 ใช้ pipeline การคอมไพล์ที่ต่างออกไป ปลั๊กอิน `aot` สำหรับ build ด้านบนจะย้ายการสร้าง handler ไปไว้ในขั้นตอน build โดยใช้ `target: 'workerd'` เพื่อสร้างโค้ดสำหรับ Workers แม้ build จะรันบน Bun ก็ตาม

การเรียก `.compile()` เป็นการ warm up handler ของ Elysia ใน runtime ปัจจุบัน ไม่ได้มาแทนขั้นตอน build ของ Worker และ v2 ไม่มีตัวเลือก `aot: false` ใน constructor

```ts
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', () => 'Hello Elysia')
    .compile()
```

ตัวอย่างการ deploy และ binding ยังต้องทดสอบกับบัญชี Cloudflare และเวอร์ชันของ dependency ที่คุณเลือกใช้
