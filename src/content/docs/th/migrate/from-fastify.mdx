<h1 id="_top">ย้ายจาก Fastify มาใช้ Elysia</h1>

:::note[Elysia v2]

ตัวอย่างของ Elysia ในหน้านี้ใช้ v2: ตัวเลือกของ route อยู่ก่อน handler, method ของ lifecycle ใช้ชื่อตาม event และค่าที่ได้จาก request ใช้ `derive` ส่วนตัวอย่างของเฟรมเวิร์กอื่นจะแสดงการตั้งค่าแบบที่ใช้กันทั่วไปของเฟรมเวิร์กนั้น ๆ ซึ่งเป็นตัวอย่างสำหรับการย้ายโค้ด ไม่ใช่การรวบรวมทุกความสามารถที่มีในปัจจุบัน แพ็กเกจที่เชื่อมต่อกับเฟรมเวิร์กต่าง ๆ มีความเข้ากันได้กับแต่ละ release แยกกันไป ตอนย้ายแอปพลิเคชันจึงควรเช็กแพ็กเกจเหล่านั้นด้วย

:::

คู่มือนี้เหมาะสำหรับผู้ใช้ Fastify ที่อยากเห็นความแตกต่างระหว่าง Fastify กับ Elysia รวมถึง syntax และวิธีย้ายแอปพลิเคชันจาก Fastify มาเป็น Elysia ผ่านตัวอย่าง

**Fastify** เป็นเว็บเฟรมเวิร์กสำหรับ Node.js ที่เร็วและมี overhead ต่ำ ออกแบบมาให้เรียบง่ายและใช้งานง่าย สร้างอยู่บน module HTTP และมีชุดฟีเจอร์ที่ช่วยให้สร้างเว็บแอปพลิเคชันได้สะดวก

**Elysia** เป็นเว็บเฟรมเวิร์กที่เขียนสบายมือสำหรับ Bun, Node.js และ runtime ที่รองรับ Web Standard API ออกแบบมาให้ใช้ง่ายและเป็นมิตรกับนักพัฒนา โดยเน้นที่ **type safety ที่รัดกุม** และประสิทธิภาพ

## ประสิทธิภาพ
Elysia มีประสิทธิภาพเหนือกว่า Fastify อย่างเห็นได้ชัด เพราะทำงานบน Bun แบบ native และใช้ static code analysis

การเปรียบเทียบนี้ใช้ [ผลของ TechEmpower Round 22](https://www.techempower.com/benchmarks/#hw=ph&test=plaintext&section=data-r22) เมื่อวันที่ 2023-10-17 ในหมวด Plaintext ซึ่งเป็นข้อมูลย้อนหลัง ตัวเลขเหล่านี้คือผลที่บันทึกไว้ของชุดเฟรมเวิร์ก/runtime ในตอนนั้น ไม่ใช่ผลวัดของ Elysia v2

| เฟรมเวิร์ก | จำนวน request ต่อวินาที |
| --- | ---: |
| Elysia | 2,454,631 |
| Fastify | 415,600 |

## การกำหนด route

Fastify กับ Elysia กำหนด route ด้วยรูปแบบที่คล้ายกัน คือใช้ method `app.get()` และ `app.post()` และรูปแบบของ path parameter ก็คล้ายกันด้วย

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'

const app = fastify()

app.get('/', (request, reply) => {
    reply.send('Hello World')
})

app.post('/id/:id', (request, reply) => {
    reply.status(201).send(request.params.id)
})

app.listen({ port: 3000 })
```

> Fastify ใช้ `request` และ `reply` เป็น object ของ request และ response

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', 'Hello World')
    .post(
    	'/id/:id',
     	({ status, params: { id } }) => {
      		return status(201, id)
      	}
    )
    .listen(3000)
```

> Elysia ใช้ `context` ตัวเดียว และส่ง response กลับไปตรง ๆ

</div>
</div>

<div class="content-layout">

สไตล์การเขียนก็ต่างกันเล็กน้อย Elysia แนะนำให้ใช้ method chaining และ object destructuring

Elysia ยังรองรับการใส่ค่า response แบบ inline ด้วย ถ้าไม่จำเป็นต้องใช้ context

## Handler

ทั้งสองมี property สำหรับเข้าถึง input อย่าง `headers`, `query`, `params` และ `body` คล้ายกัน Elysia จะ parse body ของ request ทั้งแบบ JSON, ข้อมูล URL-encoded และ formdata ให้อัตโนมัติ ส่วน Fastify parse JSON ได้เอง แต่ต้องใช้ `@fastify/formbody` และ `@fastify/multipart` สำหรับอีกสองแบบ

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'

const app = fastify()

app.post('/user', (request, reply) => {
    const limit = request.query.limit
    const name = request.body.name
    const auth = request.headers.authorization

    reply.send({ limit, name, auth })
})
```

> Fastify parse ข้อมูลแล้วใส่ไว้ใน object `request`

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.post('/user', { body: t.Object({ name: t.String() }) }, (ctx) => {
	    const limit = ctx.query.limit
	    const name = ctx.body.name
	    const auth = ctx.headers.authorization

	    return { limit, name, auth }
	})
```

> Elysia parse ข้อมูลแล้วใส่ไว้ใน object `context`

</div>
</div>

## Subrouter

Fastify ใช้ฟังก์ชัน callback ในการสร้าง subrouter ส่วน Elysia มองทุก instance เป็น component ที่นำมาเสียบต่อกันแล้วใช้งานได้ทันที

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify, { FastifyPluginCallback } from 'fastify'

const subRouter: FastifyPluginCallback = (app, opts, done) => {
	app.get('/user', (request, reply) => {
		reply.send('Hello User')
	})

	done()
}

const app = fastify()

app.register(subRouter, {
	prefix: '/api'
})
```

> Fastify ใช้ฟังก์ชัน callback ในการประกาศ sub router

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia({ prefix: '/api' })
	.get('/user', 'Hello User')

const app = new Elysia()
	.use(subRouter)
```

> Elysia มองทุก instance เป็น component

</div>
</div>

<div class="content-layout">

Elysia กำหนด prefix ใน constructor ส่วน Fastify ต้องกำหนด prefix ผ่านตัวเลือก

## Validation
Elysia รองรับ validation ของ request พร้อม type safety ที่รัดกุมมาในตัวด้วย **TypeBox** ส่วน Fastify ใช้ JSON Schema ในการประกาศ schema และใช้ **ajv** ในการตรวจสอบ

แต่ Fastify ไม่ได้ infer type ให้อัตโนมัติ คุณต้องใช้ type provider อย่าง `@fastify/type-provider-json-schema-to-ts` เพื่อ infer type

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import { JsonSchemaToTsProvider } from '@fastify/type-provider-json-schema-to-ts'

const app = fastify().withTypeProvider<JsonSchemaToTsProvider>()

app.patch(
	'/user/:id',
	{
		schema: {
			params: {
				type: 'object',
				properties: {
					id: {
						type: 'string',
						pattern: '^[0-9]+$'
					}
				},
				required: ['id']
			},
			body: {
				type: 'object',
				properties: {
					name: { type: 'string' }
				},
				required: ['name']
			},
		}
	},
	(request, reply) => {
		// map string to number
		request.params.id = +request.params.id

		reply.send({
			params: request.params,
			body: request.body
		})
	}
)
```

> Fastify ใช้ JSON Schema ในการตรวจสอบ

</div>
<div>

```ts title="Elysia TypeBox"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.patch('/user/:id', {
		params: t.Object({
			id: t.Number()
		}),
		body: t.Object({
			name: t.String()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Zod"
import { Elysia } from 'elysia'
import { z } from 'zod'

const app = new Elysia()
	.patch('/user/:id', {
		params: z.object({
			id: z.coerce.number()
		}),
		body: z.object({
			name: z.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Valibot"
import { Elysia } from 'elysia'
import * as v from 'valibot'

const app = new Elysia()
	.patch('/user/:id', {
		params: v.object({
			id: v.pipe(v.string(), v.transform(Number), v.number())
		}),
		body: v.object({
			name: v.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

> Elysia ใช้ TypeBox ในการตรวจสอบข้อมูล และแปลง type ให้อัตโนมัติ พร้อมรองรับไลบรารี validation อื่น ๆ อย่าง Zod และ Valibot ด้วย syntax เดียวกัน

</div>
</div>

<div class="content-layout">

อีกทางหนึ่ง Fastify ก็ใช้ **TypeBox** หรือ **Zod** ในการตรวจสอบได้เหมือนกัน โดยใช้ `@fastify/type-provider-typebox` เพื่อ infer type ให้อัตโนมัติ

แม้ Elysia จะ **เลือกใช้ TypeBox เป็นหลัก** ในการตรวจสอบ แต่ก็รองรับ Standard Schema ด้วย คุณจึงใช้ไลบรารีอย่าง Zod, Valibot, ArkType, Effect Schema และอื่น ๆ ได้ทันที

## การอัปโหลดไฟล์
Fastify ใช้ `fastify-multipart` ในการจัดการการอัปโหลดไฟล์ ซึ่งเบื้องหลังใช้ `Busboy` ส่วน Elysia ใช้ Web Standard API จัดการ formdata และตรวจสอบ mimetype ด้วย API แบบ declarative

แต่ Fastify ไม่มีวิธีตรวจสอบไฟล์ที่ตรงไปตรงมา เช่น ขนาดไฟล์และ mimetype จึงต้องใช้วิธีอ้อม ๆ ในการตรวจสอบไฟล์

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import multipart from '@fastify/multipart'

import { fileTypeFromBuffer } from 'file-type'

const app = fastify()
app.register(multipart, {
	attachFieldsToBody: 'keyValues'
})

app.post(
	'/upload',
	{
		schema: {
			body: {
				type: 'object',
				properties: {
					file: { type: 'object' }
				},
				required: ['file']
			}
		}
	},
	async (req, res) => {
		const file = req.body.file
		if (!file) return res.status(422).send('No file uploaded')

		const type = await fileTypeFromBuffer(file)
		if (!type || !type.mime.startsWith('image/'))
			return res.status(422).send('File is not a valid image')

		res.header('Content-Type', type.mime)
		res.send(file)
	}
)
```

> Fastify ใช้ `fastify-multipart` จัดการการอัปโหลดไฟล์ และใช้ `type: object` หลอก ๆ เพื่อให้รับ Buffer ได้

</div>
<div>

```ts title="Elysia"
import { Elysia, t, setFileTypeDetector } from 'elysia'
import { fileTypeFromBlob } from 'file-type'

setFileTypeDetector(fileTypeFromBlob)

const app = new Elysia()
	.post('/upload', {
		body: t.Object({
			file: t.File({
				type: 'image/*'
			})
		})
	}, ({ body }) => body.file)
```

> Elysia จัดการไฟล์และตรวจสอบ mimetype ด้วย `t.File`

</div>
</div>

<div class="content-layout">

metadata ของไฟล์ยืนยันเนื้อหาจริงของไฟล์ไม่ได้ ตัวอย่างนี้จึงใช้ **file-type** ตรวจดู byte ของไฟล์

Elysia ตรวจสอบตาม schema ของไฟล์ ส่วนการตรวจ byte ของไฟล์ให้ลงทะเบียน detector ของ `file-type` ตามตัวอย่าง

## Lifecycle Event

ทั้ง Fastify และ Elysia มี lifecycle event ที่ค่อนข้างคล้ายกัน โดยใช้แนวทางแบบอิง event

### Lifecycle ของ Elysia
Elysia เปิดให้เข้าถึงแต่ละขั้นตอนของ [lifecycle ของ request](/essential/life-cycle):

| ขั้นตอน | หน้าที่ |
| --- | --- |
| Request | ตรวจดู request ที่เข้ามาก่อนจะ parse |
| Parse | แปลง body ของ request ให้อยู่ในรูปที่ใช้งานได้ |
| Transform และ validation | ปรับรูปแบบและตรวจสอบ input ของ request |
| Before handle | derive ค่าจาก request หรือส่ง response กลับก่อนถึง handler |
| Handler | สร้าง response ของ route |
| After handle และ map response | ปรับแต่งและ serialize response |
| After response | ทำงานที่เหลือหลังส่ง response ไปแล้ว |

error hook คอยจัดการข้อผิดพลาดที่เกิดขึ้นใน pipeline นี้

### Lifecycle ของ Fastify
lifecycle event ของ Fastify ก็ใช้แนวทางแบบอิง event เหมือนกับ Elysia

ทั้งสองยังมี syntax สำหรับดัก lifecycle event ของ request และ response ที่ค่อนข้างคล้ายกันด้วย แต่ Elysia ไม่ต้องเรียก `done` เพื่อให้ lifecycle event ทำงานต่อ

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'

const app = fastify()

// Global middleware
app.addHook('onRequest', (request, reply, done) => {
	console.log(`${request.method} ${request.url}`)

	done()
})

app.get(
	'/protected',
	{
		// Route-specific middleware
		preHandler(request, reply, done) {
			const token = request.headers.authorization

			if (!token) return reply.status(401).send('Unauthorized')

			done()
		}
	},
	(request, reply) => {
		reply.send('Protected route')
	}
)
```

> Fastify ใช้ `addHook` ในการลงทะเบียน middleware และต้องเรียก `done` เพื่อให้ lifecycle event ทำงานต่อ

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	// Global middleware
	.onRequest(({ request }) => {
		console.log(request.method, new URL(request.url).pathname)
	})
	// Route-specific middleware
	.get('/protected', {
		beforeHandle({ status, headers }) {
  			if (!headers.authorization)
     			return status(401)
		}
	}, () => 'protected')
```

> Elysia ตรวจจับ lifecycle event ให้อัตโนมัติ และไม่ต้องเรียก `done` เพื่อให้ lifecycle event ทำงานต่อ

</div>
</div>

## Type safety ที่รัดกุม
Elysia ออกแบบมาให้มี type safety ที่รัดกุม

ตัวอย่างเช่น [derive](/essential/life-cycle#derive) จะเพิ่ม context เฉพาะของแต่ละ request พร้อม type ที่ infer ให้ ใน v2 ยังรับบทบาทเดิมของ `resolve` ในการเพิ่ม context ที่ผ่าน validation แล้วด้วย

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'

const app = fastify()

app.decorateRequest('version', 2)

app.get('/version', (req, res) => {
	// Error: Property 'version' does not exist on type 'FastifyRequest'
	res.send(req.version)
})

app.get(
	'/token',
	{
		preHandler(req, res, done) {
			const token = req.headers.authorization

			if (!token) return res.status(401).send('Unauthorized')

			// @ts-ignore
			req.token = token.split(' ')[1]

			done()
		}
	},
	(req, res) => {
		// Error: Property 'version' does not exist on type 'FastifyRequest'
		req.version

		// Error: Property 'token' does not exist on type 'FastifyRequest'
		res.send(req.token)
	}
)

app.listen({
	port: 3000
})
```

> Fastify ใช้ `decorateRequest` แต่ไม่ได้ให้ type safety ที่รัดกุม

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	.decorate('version', 2)
	.get('/version', ({ version }) => version)
	.derive(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)

		return {
			token: authorization.split(' ')[1]
		}
	})
	// {  token: string, version: number }
	.get('/token', ({ token, version }) => {
		return token
	})
```

> Elysia ใช้ `decorate` เพื่อขยาย context และใช้ `derive` เพื่อเพิ่ม property ของเราเองลงใน context

</div>
</div>

<div class="content-layout">

แม้ Fastify จะใช้ `declare module` เพื่อขยาย interface `FastifyRequest` ได้ แต่ค่านี้จะมีผลแบบ global ไม่ได้มี type safety ที่รัดกุม และไม่ได้รับประกันว่า property นั้นจะมีอยู่จริงในทุก request handler

```ts
declare module 'fastify' {
  	interface FastifyRequest {
    	version: number
  		token: string
  	}
}
```
> ตัวอย่าง Fastify ด้านบนต้องมีส่วนนี้ถึงจะทำงานได้ ซึ่งก็ไม่ได้ให้ type safety ที่รัดกุม

## Middleware ที่รับ parameter
Fastify ใช้ฟังก์ชันที่ return Fastify plugin ในการสร้าง middleware แบบมีชื่อ ส่วน Elysia ใช้ [macro](/patterns/macro) ในการสร้าง hook ที่กำหนดเอง

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import { findUser } from './users'
import fastify from 'fastify'
import type { FastifyRequest, FastifyReply } from 'fastify'

const app = fastify()

const role =
	(role: 'user' | 'admin') =>
	(request: FastifyRequest, reply: FastifyReply, next: Function) => {
		const user = findUser(request.headers.authorization)

		if (!user || user.role !== role) return reply.status(401).send('Unauthorized')

		// Error: Property 'user' does not exist on type 'FastifyRequest'
		request.user = user

		next()
	}

app.get(
	'/token',
	{
		preHandler: role('admin')
	},
	(request, reply) => {
		// Error: Property 'user' does not exist on type 'FastifyRequest'
		reply.send(request.user)
	}
)
```

> Fastify ใช้ฟังก์ชัน callback เพื่อรับ argument ที่กำหนดเองสำหรับ middleware

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'
import { findUser } from './users'

const app = new Elysia()
	.macro({
		role: (role: 'user' | 'admin') => ({
			derive({ status, headers: { authorization } }) {
				const user = findUser(authorization)

				if (!user || user.role !== role)
					return status(401)

				return {
					user
				}
			}
		})
	})
	// { user: User }
	.get('/token', {
		role: 'admin'
	}, ({ user }) => user)
```

> Elysia ใช้ macro เพื่อส่ง argument ที่กำหนดเองเข้าไปใน middleware ที่เขียนขึ้นเอง

</div>
</div>

<div class="content-layout">

ในตัวอย่างนี้ `findUser` คือโค้ดฝั่งแอปพลิเคชันที่ตรวจสอบ credential ที่ส่งมา แล้วคืนข้อมูลผู้ใช้ที่มี `role` หรือไม่คืนผู้ใช้เลยถ้าตรวจสอบไม่ผ่าน การเช็กแค่ header หรือ prefix Bearer อย่างเดียวยังไม่ถือเป็นการยืนยันตัวตน

Fastify ใช้ฟังก์ชัน callback ก็จริง แต่ต้อง return ฟังก์ชันเพื่อนำไปใส่ใน event handler หรือ object ที่แทน hook ซึ่งจัดการยากเมื่อต้องใช้ฟังก์ชันที่กำหนดเองหลายตัว เพราะต้องรวมทั้งหมดให้เป็น object เดียว

## การจัดการ error

ทั้ง Fastify และ Elysia มี lifecycle event สำหรับจัดการ error

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'

const app = fastify()

class CustomError extends Error {
	constructor(message: string) {
		super(message)
		this.name = 'CustomError'
	}
}

// global error handler
app.setErrorHandler((error, request, reply) => {
	if (error instanceof CustomError)
		reply.status(500).send({
			message: 'Something went wrong!',
			error
		})
})

app.get(
	'/error',
	{
		// route-specific error handler
		errorHandler(error, request, reply) {
			reply.send({
				message: 'Only for this route!',
				error
			})
		}
	},
	(request, reply) => {
		throw new CustomError('oh uh')
	}
)
```

> Fastify ใช้ `setErrorHandler` เป็น error handler แบบ global และใช้ `errorHandler` เป็น error handler เฉพาะ route

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

class CustomError extends Error {
    status = 500
}

const app = new Elysia()
    .onError(CustomError, ({ error, status }) =>
        status(500, { message: 'Something went wrong!', detail: error.message })
    )
    .get('/error', () => {
        throw new CustomError('oh uh')
    })
    .get('/local-error', {
        error({ error, status }) {
            if (error instanceof RangeError)
                return status(500, { message: 'Only for this route!' })
        }
    }, () => {
        throw new RangeError('outside the allowed range')
    })
```

> Elysia มี error handler แยกตาม class และ helper สำหรับส่ง response พร้อม HTTP status

</div>
</div>

<div class="content-layout">

แม้ทั้งสองจะจัดการ error ผ่าน lifecycle event ได้ แต่ Elysia ยังมี:

1. error handler แยกตาม class พร้อม type ของ error ที่ infer ให้อัตโนมัติ
2. helper `status` สำหรับส่ง response พร้อม HTTP status

route `/error` ใช้ handler ของ `CustomError` ที่ลงทะเบียนไว้ ส่วน route `/local-error` จัดการ error อีกแบบไว้ใน route ของตัวเอง error hook จะทำงานตามลำดับที่ลงทะเบียน และ hook ตัวแรกที่ return ค่าจะเป็นตัวส่ง response hook ที่ลงทะเบียนบนแอปก่อน route จะทำงานก่อน hook `error` ของ route นั้น hook ของ route จึง override hook เหล่านั้นไม่ได้

Elysia จะ infer type ของ error ที่ลงทะเบียนไว้ให้ใน handler แบบแยกตาม class

## Encapsulation

Fastify encapsulate side-effect ของ plugin ไว้ ส่วน Elysia ให้คุณควบคุม side-effect ของ plugin ได้เองผ่านกลไก scope ที่ระบุชัดเจนและลำดับของโค้ด

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import type { FastifyPluginCallback } from 'fastify'

const subRouter: FastifyPluginCallback = (app, opts, done) => {
	app.addHook('preHandler', async (request, reply) => {
		if (!request.headers.authorization?.startsWith('Bearer '))
			return reply.code(401).send({ error: 'Unauthorized' })
	})

	done()
}

const app = fastify()
	.get('/', (request, reply) => {
		reply.send('Hello World')
	})
	.register(subRouter)
	// doesn't have side-effect from subRouter
	.get('/side-effect', () => 'hi')
```

> Fastify encapsulate side-effect ของ plugin ไว้

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // doesn't have side-effect from subRouter
    .get('/side-effect', () => 'hi')
```

> Elysia encapsulate side-effect ของ plugin ไว้ เว้นแต่จะระบุไว้ชัดเจน

</div>
</div>

<div class="content-layout">

ทั้งสองมีกลไก encapsulation ของ plugin เพื่อป้องกัน side-effect

แต่ Elysia ระบุได้ชัดเจนว่า plugin ไหนควรมี side-effect ด้วยการประกาศ scope ของ plugin ส่วน Fastify จะ encapsulate เป็นค่าเริ่มต้น และต้องใช้ `fastify-plugin` ถ้าจะแชร์ side-effect

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})
	// Scoped to parent instance but not beyond
	.as('plugin') // [!code ++]

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // [!code ++]
    // now have side-effect from subRouter
    .get('/side-effect', () => 'hi')
```

Elysia มีกลไก scope ให้เลือก 3 แบบ:
1. **local** - มีผลกับ instance นี้และ instance ลูกทั้งหมด (ค่าเริ่มต้น)
2. **plugin** - แชร์ side-effect ให้ instance แม่ แต่ไม่เลยไปกว่านั้น
3. **global** - แชร์ไปถึง instance แม่ทุกระดับ

---

ถ้าจะแชร์ hook ให้ข้ามขอบเขต encapsulation ปกติของ Fastify ตัวอย่างด้านล่างจะสร้างฟังก์ชันสำหรับแต่ละ hook แล้วนำไปใส่เองทีละที่

แต่วิธีนี้อาจทำให้เกิด side-effect ซ้ำซ้อนได้ ถ้าไม่ระวังให้ดี

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import type {
	FastifyRequest,
	FastifyReply,
	FastifyPluginCallback
} from 'fastify'

const log = (request: FastifyRequest, reply: FastifyReply, done: Function) => {
	console.log('Middleware executed')

	done()
}

const app = fastify()

app.addHook('onRequest', log)
app.get('/main', (request, reply) => {
	reply.send('Hello from main!')
})

const subRouter: FastifyPluginCallback = (app, opts, done) => {
	app.addHook('onRequest', log)

	// This would log twice
	app.get('/sub', (request, reply) => {
		return reply.send('Hello from sub router!')
	})

	done()
}

app.register(subRouter, {
	prefix: '/sub'
})

app.listen({
	port: 3000
})
```

</div>
<div>

ในกรณีนี้ Elysia มีกลไก deduplication ของ plugin เพื่อป้องกันไม่ให้เกิด side-effect ซ้ำ

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia({ name: 'subRouter' }) // [!code ++]
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})
	.as('plugin')

const app = new Elysia()
	.get('/', 'Hello World')
	.use(subRouter)
	.use(subRouter) // [!code ++]
	.use(subRouter) // [!code ++]
	.use(subRouter) // [!code ++]
	// side-effect only called once
	.get('/side-effect', () => 'hi')
```

เมื่อตั้ง `name` ที่ไม่ซ้ำกัน Elysia จะใช้ plugin นั้นแค่ครั้งเดียว และไม่ทำให้เกิด side-effect ซ้ำ

</div>
</div>

## Cookie
Fastify ใช้ `@fastify/cookie` ในการ parse cookie ส่วน Elysia รองรับ cookie มาในตัว และใช้แนวทางแบบ signal ในการจัดการ cookie

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import cookie from '@fastify/cookie'

const app = fastify()

app.register(cookie, {
	secret: 'secret',
	hook: 'onRequest'
})

app.get('/', function (request, reply) {
	request.unsignCookie(request.cookies.name)

	reply.setCookie('name', 'value', {
      	path: '/',
      	signed: true
    })
})
```

> Fastify ใช้ `unsignCookie` ตรวจสอบ signature ของ cookie และใช้ `setCookie` ในการตั้ง cookie

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'

const app = new Elysia({
    cookie: {
        secrets: 'replace-with-a-private-secret',
        sign: ['name']
    }
})
    .get('/', {
        cookie: t.Cookie({ name: t.Optional(t.String()) })
    }, ({ cookie: { name } }) => {
        const previous = name.value
        name.set({
            value: 'value',
            maxAge: 60 * 60 * 24,
            httpOnly: true,
            secure: true,
            sameSite: 'lax'
        })
        return previous ?? 'unset'
    })
```

> Elysia จะตรวจสอบและ sign cookie ที่ตั้งค่าไว้ให้อัตโนมัติ หน่วยของ `maxAge` ใน cookie คือวินาที อย่าลืมเปลี่ยน secret ในตัวอย่างเป็นค่าส่วนตัวของคุณเอง และส่ง cookie แบบ secure ผ่าน HTTPS

</div>
</div>

## OpenAPI
ทั้งสองสร้างเอกสาร OpenAPI ด้วย Swagger ได้ แต่ Elysia ใช้ Scalar UI เป็นค่าเริ่มต้น ซึ่งเป็นหน้าตาที่ทันสมัยและใช้งานง่ายกว่าสำหรับเอกสาร OpenAPI

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import swagger from '@fastify/swagger'

const app = fastify()
app.register(swagger, {
	openapi: {
		info: { title: 'My API', version: '1.0.0' }
	}
})

app.addSchema({
	$id: 'user',
	type: 'object',
	properties: {
		name: {
			type: 'string',
			description: 'First name only'
		},
		age: { type: 'integer' }
	},
	required: ['name', 'age']
})

app.post(
	'/users',
	{
		schema: {
			summary: 'Create user',
			body: {
				$ref: 'user#'
			},
			response: {
				'201': {
					$ref: 'user#'
				}
			}
		}
	},
	(req, res) => {
		res.status(201).send(req.body)
	}
)

await app.ready()
app.swagger()
```

> Fastify ใช้ `@fastify/swagger` สร้างเอกสาร OpenAPI ด้วย Swagger

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi' // [!code ++]

const app = new Elysia()
	.use(openapi()) // [!code ++]
	.model({
		user: t.Object({
			name: t.String(),
			age: t.Integer()
		})
	})
	.post('/users', {
		body: 'user',
		response: {
			201: 'user'
		},

			summary: 'Create user'
		}

```

> Elysia ใช้ `@elysia/openapi` สร้างเอกสาร OpenAPI โดยใช้ Scalar เป็นค่าเริ่มต้น

</div>

ทั้งสองอ้างอิง model ด้วย `$ref` ในเอกสาร OpenAPI ได้ แต่ Fastify ไม่มี type safety และ auto-completion ตอนระบุชื่อ model ขณะที่ Elysia มี

## การทดสอบ

Fastify ทดสอบ handler ภายใน process ด้วย `fastify.inject()` ส่วน Elysia รับ `Request` แบบ Web Standard ผ่าน `app.handle()` ทั้งสองวิธีไม่ต้องเปิดเซิร์ฟเวอร์ให้รอรับการเชื่อมต่อจริง

</div>

<div class="code-comparison">
<div>

```ts title="Fastify"
import fastify from 'fastify'
import { describe, it, expect } from 'vitest'

function build(opts = {}) {
  	const app = fastify(opts)

  	app.get('/', async function (request, reply) {
	    reply.send({ hello: 'world' })
	})

  	return app
}

describe('GET /', () => {
	it('should return the greeting', async () => {
  		const app = build()

		const response = await app.inject({
		    url: '/',
		    method: 'GET',
	  })

		expect(response.statusCode).toBe(200)
		expect(response.json()).toEqual({ hello: 'world' })
	})
})
```

> Fastify ใช้ `fastify.inject()` จำลอง request ผ่านเครือข่าย

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'
import { describe, it, expect } from 'vitest'

const app = new Elysia()
	.get('/', () => ({ hello: 'world' }))

describe('GET /', () => {
	it('should return the greeting', async () => {
		const res = await app.handle(
			new Request('http://localhost')
		)

		expect(res.status).toBe(200)
		expect(await res.json()).toEqual({ hello: 'world' })
	})
})
```

> Elysia ใช้ Web Standard API ในการจัดการ request

</div>
</div>

<div class="content-layout">

อีกทางเลือกหนึ่งคือ Elysia มีไลบรารีตัวช่วยชื่อ [Eden](/eden) สำหรับ end-to-end type safety ทำให้เราทดสอบได้พร้อม auto-completion และ type safety เต็มรูปแบบ

```ts title="Elysia"
import { Elysia } from 'elysia'
import { treaty } from '@elysia/eden'
import { describe, expect, it } from 'bun:test'

const app = new Elysia().get('/hello', 'Hello World')
const api = treaty(app)

describe('GET /', () => {
	it('should return Hello World', async () => {
		const { data, error, status } = await api.hello.get()

		expect(status).toBe(200)
		expect(data).toBe('Hello World')
	})
})
```

## End-to-end type safety
Elysia รองรับ **end-to-end type safety** มาในตัวผ่าน [Eden](/eden) โดยไม่ต้องใช้ code generation ส่วน Fastify ไม่มีให้

```ts title="Elysia"
import { Elysia, t } from 'elysia'
import { treaty } from '@elysia/eden'

const app = new Elysia()
	.post('/mirror', {
		body: t.Object({
			message: t.String()
		})
	}, ({ body }) => body)

const api = treaty(app)

const { data, error } = await api.mirror.post({
	message: 'Hello World'
})

if (error)
	// error.status: 422
	// error.value: { type: 'validation', title: 'Validation Error', status: 422, on: 'body', detail, errors: [...] }
	throw error

// { message: 'Hello World' }
console.log(data)
```

ถ้า end-to-end type safety สำคัญกับคุณ Elysia คือตัวเลือกที่ใช่

---

Elysia ให้ประสบการณ์ที่เขียนสบายมือและเป็นมิตรกับนักพัฒนามากกว่า โดยเน้นที่ประสิทธิภาพ, type safety และความเรียบง่าย ส่วน Fastify เป็นหนึ่งในเฟรมเวิร์กที่อยู่คู่ Node.js มานาน แต่ไม่มี **type safety ที่รัดกุม** และ **end-to-end type safety** แบบที่เฟรมเวิร์กยุคใหม่มีให้

ถ้าคุณกำลังมองหาเฟรมเวิร์กที่ใช้งานง่าย มี developer experience ที่ดี และสร้างอยู่บน Web Standard API ล่ะก็ Elysia คือตัวเลือกที่ใช่สำหรับคุณ
