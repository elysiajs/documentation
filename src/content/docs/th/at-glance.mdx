## ประสิทธิภาพ

Elysia ใช้ Bun ร่วมกับการปรับแต่งอย่าง static code analysis เพื่อสร้างโค้ดที่จัดการ request ได้อย่างมีประสิทธิภาพ

ผลลัพธ์ด้านล่างมาจาก [Bun HTTP Framework Benchmark](https://github.com/SaltyAom/bun-http-framework-benchmark/tree/f654bcd175165bce2e3c83b65eaecd8e34294ffd#results) ค่าเฉลี่ยคือค่าเฉลี่ยเลขคณิตของจำนวน request ต่อวินาที เวลาเริ่มต้นมีหน่วยเป็นมิลลิวินาที ส่วนหน่วยความจำคือ RSS ของเซิร์ฟเวอร์ก่อนและหลังการทดสอบโหลด หน่วยเป็น MB ดู[เงื่อนไขการทดสอบ](#ref-1)

Elysia ยังเคยถูกนำไปเทียบกับเฟรมเวิร์กของ Go และ Rust ใน [TechEmpower รอบที่ 22](#ref-2) ด้วย ทั้งนี้ประสิทธิภาพขึ้นอยู่กับลักษณะงาน runtime ฮาร์ดแวร์ และเวอร์ชันของเฟรมเวิร์ก ควรวัดผลกับงานของคุณเองก่อนตัดสินใจเลือกเฟรมเวิร์ก

## TypeScript

Elysia ออกแบบมาให้คุณเขียน TypeScript น้อยลง โดยจะอนุมาน type จาก route ให้เอง คุณจึงโฟกัสกับ business logic ได้เต็มที่ แทนที่จะต้องประกาศ type ซ้ำไปซ้ำมา

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

ส่วน `:id` ใน path จะกลายเป็น `params.id` ทั้งตอน runtime และใน type ของ handler โดยไม่ต้องประกาศเอง และมี type เป็น `string`

แนะนำให้ใช้ TypeScript แต่ไม่จำเป็นต้องใช้ก็ใช้งาน Elysia ได้ การอนุมาน type ช่วยคุณระหว่างเขียนโค้ด ส่วนถ้าต้องการตรวจสอบข้อมูลตอน runtime ด้วย ให้ใช้ schema

## Type integrity

ใช้ `t` จาก Elysia เพื่อสร้าง schema ที่ตรวจสอบค่าตอน runtime และให้ type ของ TypeScript ไปพร้อมกัน ข้อมูลที่รับเข้ามาจึงมีแหล่งความจริงเพียงแหล่งเดียว

ลองเปลี่ยน path parameter จาก string เป็น number กัน:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

ใน Elysia 2 schema จะอยู่ก่อน handler เมื่อส่ง request ไปที่ `/user/123` handler จะได้รับค่าเป็นตัวเลข `123` ส่วน `/user/abc` จะไม่ผ่านการตรวจสอบ ลองเลื่อนเมาส์ไปวางบน `id` ใน editor เพื่อดู type `number` ที่อนุมานได้

schema เดียวกันนี้ใช้ทั้งตรวจสอบตอน runtime และกำหนด type ของข้อมูลที่ handler รับเข้ามา

## Standard Schema

Elysia รองรับ [Standard Schema](https://github.com/standard-schema/standard-schema) คุณจึงใช้ไลบรารี validation ที่ชอบได้ ขอแค่เป็นเวอร์ชันที่รองรับ

ในระบบนิเวศมีทั้ง Zod, Valibot, ArkType, Effect Schema, Yup, Joi และ[ตัวอื่น ๆ ที่รองรับ](https://github.com/standard-schema/standard-schema) ตรวจสอบให้แน่ใจว่าไลบรารีหรือ adapter ที่ใช้ implement interface ของ Standard Schema

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

ในตัวอย่างนี้ Zod แปลง path parameter เป็นตัวเลข ส่วน Valibot บังคับให้ต้องมี `?name=Lilith` และ Elysia ก็อนุมาน type ที่ผ่านการตรวจสอบแล้วจาก schema ทั้งสองได้

## OpenAPI

Elysia ทำงานร่วมกับมาตรฐานอย่าง OpenAPI, WinterTC และ Standard Schema คุณจึงเชื่อมต่อกับเครื่องมือที่ใช้อยู่แล้วได้ทันที

เพิ่ม [ปลั๊กอิน OpenAPI](/plugins/openapi/) เพื่อสร้างเอกสาร API จาก route และ schema ของคุณ:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

ปลั๊กอินนี้สร้างหน้าเอกสารที่แชร์ให้ทีมดูได้ ให้ใช้เวอร์ชันที่รองรับ Elysia 2 และดูวิธีติดตั้งและตั้งค่าได้ในหน้าอ้างอิงของปลั๊กอิน

## OpenAPI Type Gen

Elysia ยังสร้าง OpenAPI schema จาก type ของ TypeScript ได้ด้วย `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

นี่คือแนวทางแบบ FastAPI ในโลก TypeScript คือใช้ type ในโค้ดเป็นข้อมูลตั้งต้นในการสร้างเอกสาร แทนที่จะต้องเขียน annotation ซ้ำด้วยมือ ดูวิธีตั้งค่าและ type ที่รองรับได้ที่ [OpenAPI from types](/patterns/openapi/#openapi-from-types)

## Type safety แบบ end-to-end

type safety ไม่ได้จบแค่ฝั่งเซิร์ฟเวอร์ **Eden** ไลบรารีฝั่ง client ของ Elysia ช่วยให้ frontend ใช้ type ของเซิร์ฟเวอร์ได้ ด้วย workflow ที่คล้ายกับ tRPC

ให้ export type ของเซิร์ฟเวอร์จาก `server.ts` แล้ว import ไปใช้ใน `client.ts`:

<FileCodeBlock>
<TabItem label="server.ts">

```ts

import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)

export type App = typeof app
```

</TabItem>
<TabItem label="client.ts">

```ts
import { treaty } from '@elysia/eden'
import type { App } from './server'

```

</TabItem>

Eden ใช้ type ของ Elysia ที่มีอยู่แล้ว ไม่ต้องมีขั้นตอน generate โค้ดฝั่ง client แยก และเนื่องจาก client import มาแค่ type ของเซิร์ฟเวอร์ โค้ดที่ทำงานบนเซิร์ฟเวอร์จึงไม่หลุดเข้าไปใน bundle

Elysia พร้อมช่วยให้คุณสร้าง backend ได้อย่างมั่นใจ รวมถึงทุกอย่างที่เชื่อมต่อกับมัน

## Type soundness

response ที่สำเร็จเป็นเพียงส่วนหนึ่งของ API เท่านั้น Elysia อนุมาน **response ที่เป็นไปได้ทุกแบบ** รวมถึง error ด้วย client ของคุณจึงจัดการได้อย่างปลอดภัย

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

ตัวอย่างนี้ Elysia คืนค่า `number` เมื่อ request สำเร็จ และยังอนุมาน error `401` หรือ `420` ไว้ในระดับ type ด้วย client จึงจัดการได้ครบทั้งสามกรณีอย่าง type-safe

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

client จัดการได้ทั้งผลลัพธ์ที่สำเร็จและ error ที่มี type กำกับ ดู API ของ client ได้ที่ [Eden](/eden/) และดูวิธีสร้างพฤติกรรมของ route ที่นำกลับมาใช้ซ้ำได้ที่ [macro](/patterns/macro/)

## ใช้ได้หลายแพลตฟอร์ม

Elysia ปรับแต่งมาให้ใช้ความสามารถเฉพาะของ Bun แต่ไม่ได้จำกัดอยู่แค่ Bun เพราะ interface ของ Request/Response ที่[เข้ากันได้กับ WinterTC](https://wintertc.org/) ทำให้เชื่อมต่อกับ runtime อื่นได้

คุณใช้ Elysia ได้กับ:

- Bun
- [Node.js](/integrations/node/)
- [Deno](/integrations/deno/)
- [Cloudflare Workers](/integrations/cloudflare-worker/)
- [Vercel](/integrations/vercel/)
- API routes ของ [Expo](/integrations/expo/)
- API routes ของ [Next.js](/integrations/nextjs/)
- API routes ของ [Astro](/integrations/astro/)

หน้า integration แต่ละหน้าอธิบายทั้ง adapter และการตั้งค่าสำหรับ deploy และยังมีสภาพแวดล้อมอื่น ๆ ที่รองรับอีกในหมวด integration

## คอมมิวนิตี้ของเรา

เราอยากให้ Elysia เป็นมิตรและต้อนรับทุกคน ด้วยดีไซน์ที่สดใส สนุกสนาน และมาสคอตสไตล์อนิเมะที่วาดด้วยมืออย่าง *Elysia chan*

เราเชื่อว่าเทคโนโลยีเข้าถึงง่ายได้ และเติมความสุขเล็ก ๆ ให้ชีวิตผู้คนได้ แต่เราก็ยังจริงจังกับตัวเฟรมเวิร์กเสมอ เพราะความเสถียรและประสิทธิภาพเป็นเรื่องสำคัญเมื่อคุณไว้ใจให้มันดูแลโปรเจกต์ถัดไปของคุณ

สมาชิกในคอมมิวนิตี้ได้แชร์ประสบการณ์การใช้งานจริงบน production ไว้ ทั้ง [X](https://x.com/shlomiatar/status/1822381556142362734), [ธนาคารเพื่อการเกษตรและสหกรณ์การเกษตร (ธ.ก.ส.)](https://github.com/elysiajs/elysia/discussions/1312#discussioncomment-13924470), [Cluely](https://github.com/elysiajs/elysia/discussions/1312#discussioncomment-14420139), [CS.Money](https://github.com/elysiajs/elysia/discussions/1312#discussioncomment-13913513) และ [Abacate Pay](https://github.com/elysiajs/elysia/discussions/1312#discussioncomment-13922081)

ครั้งหนึ่งเคยมีโปรเจกต์โอเพนซอร์สมากกว่า 10,000 โปรเจกต์ที่ใช้ Elysia ดูรายชื่อโปรเจกต์ล่าสุดได้ที่ [GitHub dependents](https://github.com/elysiajs/elysia/network/dependents) Elysia เริ่มพัฒนาตั้งแต่ปี 2022 และพัฒนาต่อเนื่องมาด้วยการมีส่วนร่วมจากคอมมิวนิตี้
