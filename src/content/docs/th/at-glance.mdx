## ประสิทธิภาพ

Elysia ใช้ Bun ร่วมกับการปรับแต่งอย่าง static code analysis เพื่อสร้างโค้ดที่จัดการ request ได้อย่างมีประสิทธิภาพ

ผลลัพธ์ด้านล่างมาจาก [Bun HTTP Framework Benchmark](https://github.com/SaltyAom/bun-http-framework-benchmark/tree/f654bcd175165bce2e3c83b65eaecd8e34294ffd#results)   ค่าเฉลี่ยคือค่าเฉลี่ยเลขคณิตของจำนวน request ต่อวินาที เวลาเริ่มต้นมีหน่วยเป็น (ms) ส่วนหน่วยความจำคือ RSS ของเซิร์ฟเวอร์ก่อนและหลังทดสอบโหลด (หน่วยเป็น MB) ดู [เงื่อนไขการทดสอบ](#ref-1)ได้ที่ท้ายหน้า

Elysia ยังถูกนำไปเทียบกับเฟรมเวิร์กของ Go และ Rust ใน [TechEmpower รอบที่ 22](#ref-2) ด้วย ประสิทธิภาพจริงขึ้นอยู่กับ workload, รันไทม์, ฮาร์ดแวร์ และเวอร์ชันของเฟรมเวิร์ก ก่อนเลือกเฟรมเวิร์ก ลองวัดกับงานของคุณเองดูก่อนนะ

## TypeScript

Elysia ถูกออกแบบมาให้คุณเขียน TypeScript น้อยลง มัน infer type จาก route ให้เอง คุณจะได้โฟกัสกับ business logic แทนการประกาศ type ซ้ำไปซ้ำมา

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

ส่วน `:id` จะกลายเป็น `params.id` ทั้งตอน runtime และใน type ของ handler โดยไม่ต้องประกาศเอง และมี type เป็น `string`

Tแนะนำให้ใช้ TypeScript แต่ไม่ได้บังคับนะ type inference ช่วยตอนเขียนโค้ด ถ้าต้องการ validate ค่าตอน runtime ด้วย ให้ใช้ schema

## Type integrity

import `t` จาก Elysia เพื่อกำหนด schema ที่ทั้ง validate ค่าตอน runtime และให้ type ของ TypeScript ไปพร้อมกัน input ของคุณจะมีแหล่งความจริงเพียงแห่งเดียว

มาลองเปลี่ยน path parameter จาก string เป็น number กัน:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

ใน Elysia 2 จะใส่ schema ไว้ก่อน handler request ไปที่ `/user/123` จะส่งตัวเลข `123` ให้ handler ส่วน `/user/abc` จะไม่ผ่าน validation ลองเอาเมาส์ไปชี้ที่ `id` ใน editor จะเห็นว่า type ที่ infer ได้คือ `number`

schema ตัวเดียวกันนี้ยังสามารถใช้ได้ทั้งตรวจค่าตอน runtime และเป็น type ของ input ใน handler ได้อีกด้วย

## Standard Schema

Elysia รองรับ [Standard Schema](https://github.com/standard-schema/standard-schema) คุณจึงใช้ไลบรารี validation ที่ชอบได้ ขอแค่เป็นเวอร์ชันที่รองรับ

ในระบบนิเวศมีทั้ง Zod, Valibot, ArkType, Effect Schema, Yup, Joi integration และ[ตัวอื่น ๆ อีก](https://github.com/standard-schema/standard-schema) เช็กให้แน่ใจว่าไลบรารีหรือ adapter ที่ใช้ implement interface ของ Standard Schema

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

ตรงนี้ Zod แปลง path parameter เป็นตัวเลข ส่วน Valibot บังคับให้มี `?name=Lilith` และ Elysia ก็ infer type ที่ผ่าน validation แล้วจาก schema ทั้งสองตัวให้เลย

## OpenAPI

Elysia ทำงานร่วมกับมาตรฐานอย่าง OpenAPI, WinterTC และ Standard Schema คุณเลยต่อเข้ากับเครื่องมือที่ใช้อยู่แล้วได้ทันที

เพิ่ม [OpenAPI plugin](/plugins/openapi/) เพื่อสร้างเอกสาร API จาก route และ schema ของคุณ:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

plugin จะสร้างหน้าเอกสารที่แชร์ให้ทีมดูได้ ใช้ release ที่รองรับ Elysia 2 ส่วนวิธีติดตั้งและตั้งค่าดูได้ในหน้า reference ของ plugin

## OpenAPI Type Gen

Elysia ยังสร้าง OpenAPI schema จาก type ของ TypeScript ได้ด้วย `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

นี่คือแนวทางแบบ FastAPI สำหรับ TypeScript: ใช้ type ในโค้ดเป็น input ในการสร้างเอกสาร แทนที่จะต้องเขียน annotation ซ้ำเอง ดูวิธีตั้งค่าและ type ที่รองรับได้ที่ OpenAPI จาก type

## Type safety แบบ end-to-end

Type safety ไม่ได้หยุดอยู่แค่ฝั่งเซิร์ฟเวอร์ Eden ไลบรารีฝั่ง client ของ Elysia ช่วยให้ frontend ใช้ type ของเซิร์ฟเวอร์ได้ด้วย คล้ายกับการทำงานของ tRPC

export type ของเซิร์ฟเวอร์จาก server.ts แล้ว import ไปใช้ใน `client.ts`:

Elysia มีพร้อมอยู่ตรงนี้เพื่อช่วยให้คุณสามารถสร้าง backend ได้อย่างมั่นใจ รวมถึงทุกอย่างที่เชื่อมต่อกับมัน

## Type soundness

response ที่สำเร็จเป็นแค่ส่วนหนึ่งของ API เท่านั้น Elysia infer **response type ที่เป็นไปได้ทั้งหมด** รวมถึง error ด้วย client ของคุณจึงจัดการได้อย่างปลอดภัย

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

ตรงนี้ Elysia คืนค่า `number` เมื่อ request สำเร็จ และยัง infer error `401` หรือ `420` ไว้ในระดับ type ด้วย client จึงจัดการได้ครบทั้งสามกรณีแบบ type-safe

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

client จัดการได้ทั้งผลลัพธ์ที่สำเร็จและ error ที่มี type กำกับ ดู API ฝั่ง client ได้ที่ [Eden](/eden/) และพฤติกรรมของ route ที่ใช้ซ้ำได้ที่ [macros](/patterns/macro/)

## ไม่ผูกกับแพลตฟอร์ม

Elysia ปรับแต่งมาให้ใช้ฟีเจอร์ native ของ Bun ได้เต็มที่ แต่ไม่ได้จำกัดอยู่แค่ Bun เพราะ interface Request/Response ที่รองรับ[WinterTC](https://wintertc.org/) ทำให้ต่อกับรันไทม์อื่นได้ด้วย

คุณสามารถใช้ Elysia ได้กับ::

- Bun.
- [Node.js](/integrations/node/).
- [Deno](/integrations/deno/).
- [Cloudflare Workers](/integrations/cloudflare-worker/).
- [Vercel](/integrations/vercel/).
- [Expo](/integrations/expo/) API routes.
- [Next.js](/integrations/nextjs/) API routes.
- [Astro](/integrations/astro/) API routes.

แต่ละ integration จะอธิบาย adapter และวิธี deploy ไว้ และในหมวด integrations ยังมีสภาพแวดล้อมอื่นที่รองรับอีกนะ

## คอมมูนิตี้ของพวกเรา

พวกเราอยากให้ Elysia เป็นมิตรและอบอุ่น ด้วยดีไซน์สดใสขี้เล่น และมาสคอตอนิเมะวาดมือของเรา *Elysia chan* (˶˃ ᵕ ˂˶)
