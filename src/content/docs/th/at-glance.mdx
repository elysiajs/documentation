## ประสิทธิภาพ

Elysia ใช้ Bun ร่วมกับเทคนิคการ optimize อย่าง static code analysis เพื่อสร้างโค้ดที่จัดการ request ได้อย่างมีประสิทธิภาพ

ผลลัพธ์ด้านล่างมาจาก [Bun HTTP Framework Benchmark](https://github.com/SaltyAom/bun-http-framework-benchmark/tree/f654bcd175165bce2e3c83b65eaecd8e34294ffd#results) ค่าเฉลี่ยในที่นี้คือค่าเฉลี่ยเลขคณิตของจำนวน request ต่อวินาที เวลาเริ่มทำงานมีหน่วยเป็นมิลลิวินาที ส่วนหน่วยความจำที่ใช้คือ RSS ของเซิร์ฟเวอร์ก่อนและหลัง load test หน่วยเป็น MB อ่าน[เงื่อนไขการ benchmark](#ref-1) เพิ่มเติมได้

## TypeScript

Elysia ออกแบบมาให้คุณเขียน TypeScript น้อยลง โดยจะ infer type จาก route ให้เอง คุณจึงโฟกัสกับ business logic ได้เต็มที่ ไม่ต้องคอยประกาศ type ซ้ำไปมา

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

ส่วน `:id` จะกลายเป็น `params.id` ทั้งตอน runtime และใน type ของ handler โดยไม่ต้องประกาศเอง ซึ่งมี type เป็น `string`

แนะนำให้ใช้ TypeScript แต่ถึงไม่ใช้ก็ใช้ Elysia ได้เหมือนกัน type inference จะช่วยระหว่างเขียนโค้ด และถ้าต้องการ validation ตอน runtime ด้วย ก็ใช้ schema ได้เลย

## ความสอดคล้องของ type

ใช้ `t` ที่ import จาก Elysia เพื่อนิยาม schema ที่ตรวจสอบค่าตอน runtime และให้ TypeScript type ของค่านั้นไปพร้อมกัน ทำให้ input ของคุณมีนิยามอยู่ที่เดียว

มาลองเปลี่ยน path parameter จาก string เป็น number กัน:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

ใน Elysia 2 นั้น schema จะมาก่อน handler โดย request ที่ไปยัง `/user/123` จะส่งตัวเลข `123` ให้ handler ส่วน `/user/abc` จะไม่ผ่านการตรวจสอบ ลองเอาเมาส์ไปชี้ที่ `id` ใน editor ดู จะเห็น type `number` ที่ infer ออกมา

schema ตัวเดียวกันนี้กำหนดทั้งการตรวจสอบตอน runtime และ TypeScript type ของ input ใน handler

## Standard Schema

Elysia รองรับ [Standard Schema](https://github.com/standard-schema/standard-schema) คุณจึงใช้ไลบรารี validation ตัวโปรดได้เลย ขอแค่เป็นเวอร์ชันที่รองรับ

ใน ecosystem มีทั้ง Zod, Valibot, ArkType, Effect Schema, integration ของ Yup และ Joi รวมถึง [implementation อื่น ๆ](https://github.com/standard-schema/standard-schema) อย่าลืมเช็กว่าไลบรารีหรือ adapter ที่ใช้ implement interface ของ Standard Schema แล้ว

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

ในตัวอย่างนี้ Zod แปลง path parameter เป็นตัวเลข ส่วน Valibot บังคับว่าต้องมี `?name=Lilith` แล้ว Elysia ก็ infer type ที่ผ่านการตรวจสอบแล้วจาก schema ทั้งสองตัว

## OpenAPI

Elysia ทำงานร่วมกับมาตรฐานอย่าง OpenAPI, WinterTC และ Standard Schema คุณจึงเชื่อมต่อกับเครื่องมือที่ใช้อยู่แล้วได้

เพิ่ม [OpenAPI plugin](/plugins/openapi/) เพื่อสร้างเอกสาร API จาก route และ schema ของคุณ:

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

plugin นี้มีหน้าเอกสารที่แชร์ให้ทีมดูได้ ให้ใช้เวอร์ชันที่รองรับ Elysia 2 และดูวิธีติดตั้งกับการตั้งค่าได้ในหน้าอ้างอิงของ plugin

## OpenAPI Type Gen

Elysia ยังสร้าง OpenAPI schema จาก TypeScript type ได้ด้วย `fromTypes()`:

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

นี่คือแนวทางแบบ FastAPI ในโลกของ TypeScript: ใช้ type ในโค้ดเป็น input ในการสร้างเอกสาร แทนที่จะต้องเขียน annotation ซ้ำเอง ดูวิธีตั้งค่าและ type ที่รองรับได้ที่ [OpenAPI จาก type](/patterns/openapi/#openapi-from-types)

## Type safety แบบ end-to-end

type safety ไม่ได้จบแค่ฝั่งเซิร์ฟเวอร์ ไลบรารีฝั่ง client ของ Elysia อย่าง **Eden** ช่วยให้ frontend ใช้ type ของเซิร์ฟเวอร์ได้ ในแบบที่คล้ายกับ tRPC

ให้ export type ของเซิร์ฟเวอร์จาก `server.ts` แล้ว import ไปใช้ใน `client.ts`:

        references: fromTypes()

    .listen(3000)

Eden ใช้ type ที่ Elysia มีอยู่แล้ว ไม่ต้องมีขั้นตอนสร้างโค้ดฝั่ง client แยก และ client ก็ import แค่ type ของเซิร์ฟเวอร์ โค้ดฝั่งเซิร์ฟเวอร์จึงไม่หลุดเข้าไปอยู่ใน bundle

Elysia พร้อมช่วยให้คุณสร้าง backend ที่มั่นใจได้ ไปจนถึงทุกอย่างที่เชื่อมต่อกับมัน

## ความรัดกุมของ type

response ที่สำเร็จเป็นแค่ส่วนหนึ่งของ API เท่านั้น Elysia สามารถ infer **type ของ response ทุกแบบที่เป็นไปได้** รวมถึง error ด้วย client จึงจัดการได้อย่างปลอดภัย

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

ในตัวอย่างนี้ Elysia คืนค่า `number` เมื่อ request สำเร็จ และยัง infer error `401` หรือ `420` ไว้ในระดับ type ด้วย client จึงจัดการได้ครบทั้งสามกรณีแบบ type-safe

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

client จัดการได้ทั้งผลลัพธ์ที่สำเร็จและ error ซึ่งมี type กำกับ ดู API ฝั่ง client ได้ที่ [Eden](/eden/) และดูวิธีสร้างพฤติกรรมของ route ที่นำกลับมาใช้ซ้ำได้ที่ [macro](/patterns/macro/)

## ไม่ผูกติดกับแพลตฟอร์มใด

Elysia ปรับแต่งมาเพื่อใช้ฟีเจอร์ในตัวของ Bun ได้เต็มที่ แต่ก็ไม่ได้จำกัดอยู่แค่ Bun ด้วย interface ของ Request/Response ที่[รองรับ WinterTC](https://wintertc.org/) ทำให้เชื่อมต่อกับ runtime อื่นได้ด้วย

คุณใช้ Elysia ได้กับ:

- Bun
- [Node.js](/integrations/node/)
- [Deno](/integrations/deno/)
- [Cloudflare Workers](/integrations/cloudflare-worker/)
- [Vercel](/integrations/vercel/)
- API routes ของ [Expo](/integrations/expo/)
- API routes ของ [Next.js](/integrations/nextjs/)
- API routes ของ [Astro](/integrations/astro/)

หน้า integration แต่ละหน้าจะอธิบาย adapter และการตั้งค่าสำหรับ deploy ไว้ ดูสภาพแวดล้อมอื่น ๆ ที่รองรับได้เพิ่มเติมในหมวด integration

## คอมมูนิตี้ของเรา
