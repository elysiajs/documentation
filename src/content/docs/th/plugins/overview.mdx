<h1 id="_top">ภาพรวม plugin</h1>

Elysia ออกแบบมาให้แยกเป็น module และมีน้ำหนักเบา

ยึดแนวคิดเดียวกับ Arch Linux (แอบบอกว่าใช้ Arch อยู่นะ):

> การตัดสินใจเรื่องการออกแบบจะพิจารณาเป็นกรณี ๆ ไป โดยอาศัยฉันทามติของนักพัฒนา

ที่เป็นแบบนี้ก็เพื่อให้นักพัฒนาได้เว็บเซิร์ฟเวอร์ที่มีประสิทธิภาพตามที่ตั้งใจสร้างไว้ ต่อยอดจากแนวคิดนี้ Elysia จึงมี plugin สำเร็จรูปสำหรับ pattern ที่ใช้กันบ่อยมาให้นักพัฒนาใช้ได้สะดวก:

:::note[เวอร์ชันของ plugin]

เลือกใช้ plugin เวอร์ชันที่ peer dependency ของ Elysia ตรงกับแอปพลิเคชันของคุณ สาย Elysia 2 ใช้เวอร์ชันแบบ prerelease ส่วนรุ่นเก่าอาจพึ่ง API ของ Elysia 1 ที่ถูกถอดออกไปแล้ว รายการจากคอมมูนิตี้ด้านล่างเป็นแค่รายชื่อที่รวบรวมไว้ ไม่ได้รับประกันว่าจะใช้ร่วมกันได้

:::

## Plugin จากคอมมูนิตี้

-   [Create ElysiaJS](https://github.com/kravetsone/create-elysiajs) - สร้างโครงโปรเจกต์ Elysia พร้อม environment ได้ง่าย ๆ (ช่วยจัดการเรื่อง ORM, Linter และ Plugin ให้ด้วย)!
-   [Lucia Auth](https://github.com/pilcrowOnPaper/lucia) - ระบบ authentication ที่เรียบง่ายและสะอาดตา
-   [Elysia Clerk](https://github.com/wobsoriano/elysia-clerk) - plugin สำหรับ authentication ด้วย Clerk แบบไม่เป็นทางการ
-   [Elysia Polyfills](https://github.com/bogeychan/elysia-polyfills) - รัน ecosystem ของ Elysia บน Node.js และ Deno
-   [Vite server](https://github.com/kravetsone/elysia-vite-server) - plugin ที่สั่งเริ่มและ decorate dev server ของ [`vite`](https://vitejs.dev/) ทั้งในโหมด `development` และ `production` แถมเสิร์ฟไฟล์ static ให้ด้วย (ถ้าต้องการ)
-   [Vite](https://github.com/timnghg/elysia-vite) - เสิร์ฟไฟล์ HTML ที่เป็น entry พร้อมฉีดสคริปต์ของ Vite ไว้ให้
-   [Nuxt](https://github.com/trylovetom/elysiajs-nuxt) - เชื่อม Elysia เข้ากับ Nuxt ได้ง่าย ๆ!
-   [Remix](https://github.com/kravetsone/elysia-remix) - ใช้ [Remix](https://remix.run/) พร้อมรองรับ `HMR` (ขับเคลื่อนด้วย [`vite`](https://vitejs.dev/))! ปิดคำขอ plugin ที่ค้างมานานมาก ๆ อย่าง [#12](https://github.com/elysiajs/elysia/issues/12) ได้สักที
-   [Sync](https://github.com/johnny-woodtke/elysiajs-sync) - เฟรมเวิร์กซิงก์ข้อมูลแบบ offline-first ที่เบา ขับเคลื่อนด้วย [Dexie.js](https://dexie.org/)
-   [Connect middleware](https://github.com/kravetsone/elysia-connect-middleware) - plugin ที่ให้คุณใช้ middleware ของ [`express`](https://www.npmjs.com/package/express)/[`connect`](https://www.npmjs.com/package/connect) ใน Elysia ได้โดยตรง!
-   [Elysia HTTP Exception](https://github.com/codev911/elysia-http-exception) - plugin ของ Elysia สำหรับจัดการ error HTTP 4xx/5xx ด้วย exception class ที่มีโครงสร้างชัดเจน
-   [Elysia Helmet](https://github.com/DevTobias/elysia-helmet) - เพิ่มความปลอดภัยให้แอป Elysia ด้วย HTTP header ต่าง ๆ
-   [Vite Plugin SSR](https://github.com/timnghg/elysia-vite-plugin-ssr) - plugin SSR ของ Vite ที่ใช้เซิร์ฟเวอร์ Elysia
-   [OAuth 2.0](https://github.com/kravetsone/elysia-oauth2) - plugin สำหรับ Authorization Flow ของ [OAuth 2.0](https://en.wikipedia.org/wiki/OAuth) ที่รองรับ provider มากกว่า **42** เจ้า พร้อม **type-safety**!
-   [OAuth2](https://github.com/bogeychan/elysia-oauth2) - จัดการ authorization code flow ของ OAuth 2.0
-   [OAuth2 Resource Server](https://github.com/ap-1/elysia-oauth2-resource-server) - plugin สำหรับตรวจสอบ JWT token จาก provider ของ OAuth2 กับ endpoint ของ JWKS รองรับการตรวจสอบ issuer, audience และ scope
-   [Elysia OpenID Client](https://github.com/macropygia/elysia-openid-client) - OpenID client ที่สร้างบน [openid-client](https://github.com/panva/node-openid-client)
-   [Rate Limit](https://github.com/rayriffy/elysia-rate-limit) - rate limiter ที่เรียบง่ายและเบา
-   [Elysia Nazli](https://github.com/esbuker/elysia-nazli) - rate limiter ที่ใช้งานสะดวก เปลี่ยน store ได้ตามใจ และตั้งกฎได้ทั้งแบบ global และราย route
-   [LLMs.txt](https://github.com/opuu/elysia-llms-txt) - สร้าง `/llms.txt` จาก OpenAPI/Swagger ให้เอกสารอ่านง่ายสำหรับ LLM
-   [Logysia](https://github.com/tristanisham/logysia) - middleware สำหรับ logging แบบคลาสสิก
-   [Logestic](https://github.com/cybercoder-naj/logestic) - ไลบรารี logging ขั้นสูงที่ปรับแต่งได้สำหรับ ElysiaJS
-   [Logger](https://github.com/bogeychan/elysia-logger) - middleware สำหรับ logging ที่สร้างบน [pino](https://github.com/pinojs/pino)
-   [Elysia Line](https://github.com/KrataiB/elysia-line) - เชื่อมต่อ LINE Messaging API และ LINE Login กับ Elysia (เป็น wrapper ครอบ [@line/bot-sdk](https://github.com/line/line-bot-sdk-nodejs) ตัวทางการ)
-   [Elylog](https://github.com/eajr/elylog) - ไลบรารี logging ออก stdout แบบเรียบง่าย ปรับแต่งได้นิดหน่อย
-   [Logify for Elysia.js](https://github.com/0xrasla/logify) - middleware สำหรับ logging ที่สวย เร็ว และ type-safe สำหรับแอปพลิเคชัน Elysia.js
-   [Nice Logger](https://github.com/tanishqmanuja/nice-logger) - อาจไม่ใช่ logger ที่ดีที่สุด แต่ก็ดีและน่ารักใช้ได้เลยสำหรับ Elysia
-   [LogTape for Elysia](https://logtape.org/manual/integrations#elysia) - middleware สำหรับ structured logging ที่รองรับหลาย sink (transport) ผ่าน [LogTape](https://logtape.org/)
-   [Sentry](https://github.com/johnny-woodtke/elysiajs-sentry) - เก็บ trace และ error ด้วย plugin [Sentry](https://docs.sentry.io/) ตัวนี้
-   [Apitally](https://github.com/apitally/apitally-js) - เก็บ metric, log และ trace ไว้ใน [Apitally](https://apitally.io/elysia) เครื่องมือ monitor และวิเคราะห์ API ที่ใช้ง่าย
-   [Elysia Lambda](https://github.com/TotalTechGeek/elysia-lambda) - deploy บน AWS Lambda

-   [Elysia FSR](https://github.com/deadlinecode/elysia-fsr) - file-system routing ที่สร้าง type ให้ใช้กับ Eden ได้ รองรับ monorepo/workspace และจัดกลุ่ม route เชิงตรรกะได้
-   [Autoload](https://github.com/kravetsone/elysia-autoload) - router แบบ filesystem ตามโครงสร้างโฟลเดอร์ ที่สร้าง type ให้ [Eden](/eden) และรองรับ [`Bun.build`](https://github.com/kravetsone/elysia-autoload?tab=readme-ov-file#bun-build-usage)
