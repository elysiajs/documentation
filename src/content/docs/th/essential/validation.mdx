## TypeBox

Elysia มี `t` ซึ่งเป็น named export จาก `elysia` ไว้เป็นตัวสร้าง schema เริ่มต้น ตัวนี้เป็น wrapper ของ [TypeBox](https://github.com/sinclairzx81/typebox) ที่เพิ่มฟีเจอร์สำหรับตรวจสอบข้อมูลของ API มาให้

schema เหล่านี้รองรับทั้งการตรวจสอบตอน runtime, type inference ของ TypeScript และการสร้าง schema ให้ [OpenAPI](/plugins/openapi/) จึงไม่ต้องเขียน interface แยกอีกชุดสำหรับข้อมูลเดียวกัน

## Standard Schema

นอกจากนี้ยังใช้ไลบรารีที่รองรับ [Standard Schema](https://github.com/standard-schema/standard-schema) ได้ด้วย เช่น **Zod**, **Valibot**, ArkType, Effect Schema, Yup และ Joi ในเวอร์ชันที่เข้ากันได้ แล้วใช้สลับแทนกันได้เลย

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => ({ id, name }))
    .listen(3000)
```

`/id/42?name=Lilith` ผ่านทั้งสอง schema ถ้าอยากแปลง string จาก URL เป็น type อื่น ให้ใช้ coercion API ของไลบรารีที่คุณเลือก

ใส่ property เหล่านี้ไว้ใน argument ตัวที่สองของ route ก่อน handler:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/id/:id', {
        query: t.Object({ name: t.String() }),
        params: t.Object({ id: t.Number() })
    }, () => 'Hello World!')
    .listen(3000)
```

| URL | Schema ของ query | Schema ของ params |
| --- | --- | --- |
| `/id/a` | ไม่ผ่าน | ไม่ผ่าน |
| `/id/1?name=Elysia` | ผ่าน | ผ่าน |
| `/id/1?alias=Elysia` | ไม่ผ่าน | ผ่าน |
| `/id/a?name=Elysia` | ผ่าน | ไม่ผ่าน |
| `/id/a?alias=Elysia` | ไม่ผ่าน | ไม่ผ่าน |

handler จะทำงานก็ต่อเมื่อผ่านทั้งสอง schema ตารางนี้แสดงผลการตรวจแต่ละส่วนแยกกัน ส่วน error response อาจรายงานแค่ส่วนแรกที่ไม่ผ่าน

## Body

body ของ [HTTP Message](https://developer.mozilla.org/en-US/docs/Web/HTTP/Messages) เป็นได้ทั้ง JSON, field ของฟอร์ม หรือไฟล์

<CodePlayground examples={examples.body}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .post('/body', {
        body: t.Object({ name: t.String() })
    }, ({ body }) => body)
    .listen(3000)
```

</CodePlayground>

| JSON body | ผลการตรวจสอบ |
| --- | --- |
| `{ "name": "Elysia" }` | ผ่าน |
| `{ "name": 1 }` | ไม่ผ่าน |
| `{ "alias": "Elysia" }` | ไม่ผ่าน |
| ไม่มี body | ไม่ผ่าน |

### ไฟล์

ใช้ [t.File()](/patterns/typebox/#file) สำหรับไฟล์เดียว และ [t.Files()](/patterns/typebox/#files) สำหรับหลายไฟล์

การตรวจ `type` ต้องใช้ file type detector ด้วย ให้ติดตั้ง `file-type` แล้วลงทะเบียนครั้งเดียวด้วย `setFileTypeDetector` ถ้าไม่มี detector ทุกไฟล์ที่อัปโหลดและตรวจด้วย `type` จะไม่ผ่านการตรวจสอบเลย

```ts
import { Elysia, t, setFileTypeDetector } from 'elysia'
import { fileTypeFromBlob } from 'file-type'

setFileTypeDetector(fileTypeFromBlob)

new Elysia()
    .post('/body', {
        body: t.Object({
            file: t.File({ type: 'image/*' }),
            multipleFiles: t.Files()
        })
    }, ({ body }) => ({
        file: body.file.name,
        count: body.multipleFiles.length
    }))
    .listen(3000)
```

### ไฟล์ (Standard Schema)

ไลบรารี Standard Schema จะไม่ได้การตรวจไฟล์ของ Elysia มาให้อัตโนมัติ ให้เพิ่ม refinement ด้วย helper `fileType()` ซึ่งทำงานแบบ async และระบุให้ parse แบบ multipart อย่างชัดเจน:

```ts
import { Elysia, fileType, setFileTypeDetector } from 'elysia'
import { fileTypeFromBlob } from 'file-type'
import { z } from 'zod'

setFileTypeDetector(fileTypeFromBlob)

new Elysia()
    .post('/body', {
        parse: 'formdata',
        body: z.object({
            file: z.file().refine(
                (file) => fileType(file, 'image/jpeg'),
                'Expected a JPEG file'
            )
        })
    }, ({ body }) => ({ name: body.file.name }))
```

detector ที่ลงทะเบียนไว้จะตรวจไฟล์ระดับ byte ให้ในกรณีนี้ด้วย ส่วน validator ที่อ่านแค่ `file.type` ยืนยันไม่ได้ว่าไฟล์ที่อัปโหลดมามีเนื้อหาจริง ๆ เป็นอะไร

## Query

query parameter คือส่วนที่อยู่หลัง `?` ใน URL ให้กำหนดด้วย object schema:

import { Elysia, t } from 'elysia'

new Elysia()
    .get('/query', {
        query: t.Object({ name: t.String() })

    .listen(3000)

| --- | --- |
| `/query?name=Elysia` | ผ่าน |

| `/query?alias=Elysia` | ไม่ผ่าน |
| `/query?name=ElysiaJS&alias=Elysia` | ผ่าน |
| `/query` | ไม่ผ่าน |

### การแปลง type

Elysia จะแปลงค่าใน `query` ให้อัตโนมัติสำหรับ TypeBox schema ที่แปลงได้ เช่น `t.Number()` จะรับ string ที่เป็นตัวเลข แล้วส่งให้ handler เป็น number:

<CodePlayground examples={examples.coercion}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/query', {
        query: t.Object({ id: t.Number() })
    }, ({ query: { id } }) => id)
    .listen(3000)
```

</CodePlayground>

| Request | ผลลัพธ์ |
| --- | --- |
| `/query?id=1` | ตัวเลข `1` |
| `/query?id=salt` | validation error พร้อม status `422` |

ดูการแปลงอัตโนมัติแบบอื่น ๆ ได้ที่ [พฤติกรรมของ type ใน Elysia](/patterns/typebox/#elysia-behavior)

### Array

ประกาศ array schema เพื่อตรวจสอบทุกค่า และรองรับค่าที่คั่นด้วยคอมมา:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/query', {
        query: t.Object({
            name: t.Array(t.String()),
            squad: t.String()
        })
    }, ({ query }) => query)
    .listen(3000)
```

เมื่อใช้ schema นี้ request ทั้งสองแบบด้านล่างจะได้ `{ name: ['rapi', 'anis', 'neon'], squad: 'counter' }` เหมือนกัน

#### รูปแบบ nuqs

ใช้คอมมาคั่นค่า แบบเดียวกับรูปแบบ array ของ [nuqs](https://nuqs.47ng.com):

```text
/query?name=rapi,anis,neon&squad=counter
```

array schema จะบอกให้ Elysia แยก `name` ออกเป็นหลายค่า ถ้าไม่มี ค่าที่คั่นด้วยคอมมาก็จะยังเป็น string เดียว

#### รูปแบบฟอร์ม HTML

ใส่ key ซ้ำเพื่อส่งหลายค่า แบบที่ฟอร์ม HTML ทำกับ input ที่มีชื่อเดียวกัน:

```text
/query?name=rapi&name=anis&name=neon&squad=counter
```

ประกาศ array schema เพื่อเก็บและตรวจสอบทุกค่าที่ส่งซ้ำมา ถ้าไม่มี property ของ query ทั่วไปจะเป็น string ค่าเดียว และถ้า key ซ้ำก็จะเหลือแค่ค่าสุดท้าย

## Params

path parameter ใช้จับค่าจาก route อย่าง `/id/:id` ใช้ object schema เพื่อตรวจสอบ field ที่จับได้:

<CodePlayground examples={examples.params}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/id/:id', {
        params: t.Object({ id: t.Number() })
    }, ({ params }) => params)
```

</CodePlayground>

| Request | ผลลัพธ์ |
| --- | --- |
| `/id/1` | `{ "id": 1 }` |
| `/id/a` | validation error พร้อม status `422` |

## Headers

ใช้ `headers` เพื่อบังคับให้ request ที่เข้ามาต้องมี header ที่กำหนด:

<CodePlayground examples={examples.headers}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/headers', {
        headers: t.Object({ authorization: t.String() })
    }, ({ headers }) => headers.authorization)
```

</CodePlayground>

โดยค่าเริ่มต้น schema ของ header จะยอมให้มี property อื่นเพิ่มเข้ามาได้ client จึงยังส่ง header อย่าง `accept` ได้ตามปกติ ขอแค่ field ที่ประกาศไว้ผ่าน schema ของมันก็พอ

ถ้าอยากปฏิเสธ header ส่วนเกินทั้งหมด ให้ตั้ง `additionalProperties: false`:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/headers', {
        headers: t.Object(
            { authorization: t.String() },
            { additionalProperties: false }
        )
    }, ({ headers }) => headers.authorization)
```

## Response

ใช้ `response` เพื่อตรวจสอบข้อมูลที่ handler คืนค่ากลับมา:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/response', {
        response: t.Object({ name: t.String() })
    }, () => ({ name: 'Jane Doe (ZZZ)' }))
```

TypeScript จะตรวจ return type ของ handler ส่วน Elysia จะตรวจสอบ response ตอน runtime

### Response แยกตาม status

ถ้าผลลัพธ์แต่ละแบบมีโครงสร้าง response ต่างกัน ให้จับคู่ status code กับ schema ของแต่ละแบบ:

<CodePlayground examples={examples.responseStatus}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/response', {
        response: {
            200: t.Object({ name: t.String() }),
            400: t.Object({ error: t.String() })
        }
    }, ({ query, status }) => {
        if (query.fail === 'true')
            return status(400, { error: 'Something went wrong' })

        return { name: 'Jane Doe (ZZZ)' }
    })
```

</CodePlayground>

`/response` คืนค่าตามโครงสร้างของ `200` ส่วน `/response?fail=true` คืนค่าตามโครงสร้างของ `400` ใช้ `status()` เพื่อให้ status code ผูกกับ type ของ body ไว้เสมอ

## การจัดการ validation error

ปรับแต่ง [ข้อความ validation](/patterns/error-handling/#schema-messages) ของ schema จัดการกรณีไม่ผ่านด้วย [error hook](/patterns/error-handling/#error-hook) หรือดู [รายการ error](/patterns/error-handling/#error-list) ได้

ถ้าต้องการ schema ที่ตั้งชื่อไว้ใช้ร่วมกันหลาย route และในเอกสาร OpenAPI ดูได้ที่ [reference model](/patterns/openapi/#reference-model)

## TypeScript

ใช้ `UnwrapSchema` เพื่อดึง TypeScript type ที่ infer ได้จาก schema:

```ts
import { t, type UnwrapSchema } from 'elysia'

const MyType = t.Object({
    hello: t.Literal('Elysia')
})

type MyType = UnwrapSchema<typeof MyType>
```

schema ตัวเดียวให้ได้ทั้งการตรวจสอบตอน runtime, การแปลง type, TypeScript type และ metadata ของ OpenAPI เก็บนิยามไว้ที่เดียว แล้วให้ทุกที่ที่ใช้อ้างอิงจากนิยามนั้น

## Guard

ใช้ `.guard()` เพื่อใช้ schema กับหลาย route พร้อมกัน โดยจะมีผลกับ route ที่ลงทะเบียนหลัง guard เท่านั้น:

<CodePlayground examples={examples.guard}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/none', () => 'hi')
    .guard({
        query: t.Object({ name: t.String() })
    })
    .get('/query', ({ query: { name } }) => name)
    .listen(3000)
```

</CodePlayground>

| Request | ผลลัพธ์ |
| --- | --- |
| `/none` | `hi` |
| `/none?name=a` | `hi` |
| `/query` | validation error พร้อม status `422` |
| `/query?name=a` | `a` |

ถ้าเป็น schema property เดียวกัน guard ที่มาทีหลังจะมีผลเหนือ guard ก่อนหน้า และ schema ของ route เองจะมีผลเหนือ schema ที่สืบทอดมาจาก guard

### ประเภท schema ของ guard

guard รองรับการจัดการ schema ที่ทับซ้อนกันได้ 2 แบบ

#### Override (ค่าเริ่มต้น)

schema ที่อยู่ใกล้กว่าจะแทนที่ schema ที่สืบทอดมาสำหรับ property นั้น เช่น `body` ของ route จะแทนที่ `body` ของ guard ไปเลย โดยไม่รวม field เข้าด้วยกัน

<CodePlayground examples={examples.override}>

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .guard({ body: t.Object({ name: t.String() }) })
    .post('/age', {
        body: t.Object({ age: t.Number() })
    }, ({ body }) => body)
```

</CodePlayground>

`{ "age": 18 }` ผ่าน `/age` ได้โดยไม่ต้องมี field `name`

#### Merge

ตั้ง `schema: 'merge'` เมื่อต้องการให้ผ่านทั้ง schema ของ guard และของ route:

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .guard({
        schema: 'merge',
        response: t.Object({ title: t.String() })
    })
    .get('/article', {
        response: t.Object({ title: t.String(), author: t.String() })
    }, () => ({ title: 'Hello Elysia', author: 'Nagisa' }))
```

response ต้องผ่านทั้ง schema ของ guard และของ route โดย merge จะสะสมเงื่อนไขของทั้งคู่ไว้ ไม่ได้เอาไปแทน schema ที่สืบทอดมา
