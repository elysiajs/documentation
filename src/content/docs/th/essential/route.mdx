<h1 id="_top">การกำหนด route</h1>

[REST API](https://en.wikipedia.org/wiki/REST) ใช้ path และ method ในการตัดสินว่าจะเรียก handler ตัวไหน

<CodePlayground elysia={demo1}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/', 'Elysia')
    .get('/hi', 'Hello!')
    .listen(3000)
```

</CodePlayground>

> เรียก `.listen` เพื่อเปิดเว็บเซิร์ฟเวอร์ที่พอร์ต 3000

เราเข้าถึงเซิร์ฟเวอร์ได้ที่ http://localhost:3000

- `/` ด้วย method `GET` จะคืนค่า `Elysia`
- `/hi` ด้วย method `GET` จะคืนค่า `Hello!`
- path อื่นนอกจากนี้จะคืนค่า `404`

เวลาเปิด URL ในเบราว์เซอร์ จะเป็นการส่ง request แบบ `GET`

## Path แบบ static

path แบบ static ต้องตรงกันทุกตัวอักษร ไม่มีอะไรให้เซอร์ไพรส์

- `/` ตรงกับ `/` เท่านั้น
- `/hi` ตรงกับ `/hi` เท่านั้น

</InteractiveStep>

<InteractiveStep>

## Path แบบ dynamic

ใส่ `:` ตามด้วยชื่อ เพื่อดึงค่าในตำแหน่งนั้นออกมา

`/user/:id` ตรงกับ `/user/42`, `/user/abc` และ `/user/hello-world`

</InteractiveStep>

<InteractiveStep>

### เข้าถึง params

อ่านค่าที่จับคู่ได้จาก `params` ใน handler

เมื่อ `/user/42/profile` ตรงกับ `/user/:id/profile` ค่า `params.id` จะเป็น `42` แล้ว handler ก็คืนค่านี้กลับไปเป็น response

</InteractiveStep>

<InteractiveStep>

### Params แบบ optional

ใส่ `?` ต่อท้ายชื่อ parameter เพื่อให้เป็น optional

`/user/:id?/profile` ตรงกับทั้ง `/user/42/profile` และ `/user/profile`

ถ้าไม่มี parameter นั้น ค่าจะเป็น `undefined`

</InteractiveStep>

<InteractiveStep>

## Wildcard

ใส่ `*` ไว้ท้าย path เพื่อจับคู่กับ path อะไรก็ได้ที่ตามหลังมา

`/user/*` ตรงกับ path ที่มีหลาย segment อย่าง `/user/hello-world/profile` ในตัวอย่างนี้ `/user/42` จะยังไปที่ `/user/:id` เพราะ path แบบ dynamic มีลำดับความสำคัญสูงกว่า wildcard (ดู[ลำดับความสำคัญของ path](#path-priority))

สำหรับ `/user/hello-world/profile` ค่า `params['*']` จะเป็น `hello-world/profile`

</InteractiveStep>

</InteractiveDoc>

```ts
import { Elysia } from 'elysia'

new Elysia()
	.get('/', 'Hi GET!')
	.post('/', 'Hi POST!')
	.put('/', 'Hi PUT!')
	.patch('/', 'Hi PATCH!')
	.delete('/', 'Hi DELETE!')
	.listen(3000)
```

### Method แบบกำหนดเอง

กำหนดได้ด้วย `.method` โดยใส่ชื่อ method เป็น argument ตัวแรก ที่เหลือใช้เหมือนกับ method อื่น ๆ

```ts
import { Elysia } from 'elysia'

new Elysia()
	.method('PROPFIND', '/', 'Hi PROPFIND!')
	.listen(3000)
```

### ทุก method

รับทุก method ด้วย `.all`:

```ts
import { Elysia } from 'elysia'

new Elysia()
	.all('/', 'Hi ALL!')
	.listen(3000)
```

## Group

path หลายตัวที่มี prefix เดียวกันจัดกลุ่มรวมกันได้ด้วย `.group`:

<CodePlayground elysia={demo3}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .group('/user', (app) =>
        app
            .post('/sign-in', 'Sign in')
            .get('/profile', 'Profile')
    )
    .listen(3000)
```

</CodePlayground>

ผลลัพธ์เหมือนกับการเขียน `/user/sign-in` และ `/user/profile` แยกกัน

### Prefix

ถ้าทั้ง instance ใช้ prefix เดียวกัน เรากำหนดไว้ใน constructor ได้เลย:

<CodePlayground elysia={demo4}>

```ts
import { Elysia } from 'elysia'

new Elysia({ prefix: '/user' })
    .post('/sign-in', 'Sign in')
    .get('/profile', 'Profile')
```

</CodePlayground>

ต่างจาก `.group` ตรงที่ prefix นี้มีผลกับทุก path ใน instance ส่วน group มีผลแค่กับ path ใน callback
