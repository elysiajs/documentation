<h1 id="_top">Bun fullstack dev server</h1>

Bun’s [fullstack dev server](https://bun.com/docs/bundler/fullstack) bundles frontend assets and supports hot module replacement (HMR). This guide uses Bun 1.3 or later and the Elysia v2 static plugin.

This allows us to directly use React without any bundler like Vite or Webpack.

## Set up the server

Install the Elysia v2 static plugin:

```bash
bun add elysia@2.0.0-beta.32 @elysia/static@next react react-dom
bun add -d @types/react @types/react-dom
```

:::tip

Set `bunFullstack: true` and await `staticPlugin()` before starting the server. The plugin defaults to ordinary static-file serving; awaiting it alone does not enable the HTML bundler.

:::

</InteractiveStep>

<InteractiveStep>

### Create the HTML entry point

Create `public/index.html` and load `public/index.tsx` as a module.

</InteractiveStep>

<InteractiveStep>

### Create the React app

Create `public/index.tsx` with a counter component.

</InteractiveStep>

<InteractiveStep>

### Enable JSX

Enable JSX in `tsconfig.json`.

Navigate to `http://localhost:3000/public` and see the result.

Bun handles frontend bundling alongside the API, so you don’t need a separate bundler process.

The source example combines HMR, [Tailwind](#tailwind-css), TanStack Query, [Eden Treaty](/eden/), and path aliases. Use versions compatible with your Bun and Elysia release.

</InteractiveStep>

<InteractiveStep>

## Custom prefix path

We can change the default `/public` prefix by passing the `prefix` option to `staticPlugin`.

This would serve the static files at `/` instead of `/public`.

See [static plugin](/plugins/static/) for more configuration options.

</InteractiveStep>

## Build for production

You can build a fullstack server as if it were a normal Elysia server.

```bash
bun build --compile --target bun --outfile server src/index.ts
```

This creates an executable named `server`. Test the production build as well as development HMR.

When running the **server** executable, make sure to include the **public** folder as in the development environment.

See [Deploy to Production](/patterns/deploy) for more information.
