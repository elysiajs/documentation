<h1 id="_top">从 Hono 迁移到 Elysia</h1>

:::note[Elysia v2]

Elysia 示例使用 v2：路由选项写在处理器之前，生命周期方法使用对应的事件名称，请求派生值则使用 `derive`。其他框架的示例展示了各自典型的配置方式，目的是说明迁移方法，并非罗列其所有当前功能。框架集成包有各自的版本兼容要求；迁移应用时请确认相关包的兼容性。

:::

本指南面向 Hono 用户，通过示例介绍 Hono 与 Elysia 的语法等差异，以及如何将应用从 Hono 迁移到 Elysia。

**Hono** 是基于 Web Standard 构建的快速轻量级 Web 框架，广泛兼容 Deno、Bun、Cloudflare Workers 和 Node.js 等运行时。

**Elysia** 是一款注重开发体验的易用 Web 框架，专注于**健全的类型安全**与性能。Elysia 不局限于 Bun，也支持 Node.js 和 Cloudflare Workers 等多种运行时。

## 如何选择
下面简要对比 Hono 和 Elysia，帮助你做出选择：

**Hono**
- **最初为 Cloudflare Workers 构建**，与 Cloudflare 生态集成更紧密
- 基于 Web Standard 支持多种运行时，包括 **Node.js** 和 **Bun**
- 轻量简洁，适合边缘环境
- 支持 OpenAPI，但描述规范需要额外工作
- 倾向于简单线性的中间件处理方式
- 类型安全优于多数框架，但某些方面并不健全
- 在中间件和插件风格上与 Express、Koa 有些相似

**Elysia**
- **最初为 Bun 原生构建**，充分利用 Bun 的各项特性
- 基于 Web Standard 支持多种运行时，包括 **Node.js** 和 **Cloudflare Workers**
- **性能更好**，通过 JIT 面向长时间运行的服务器进行优化
- **OpenAPI 支持更完善**，集成体验顺畅，尤其是 [OpenAPI Type Gen](/patterns/openapi#openapi-from-types)
- 倾向于基于事件的生命周期方式，以便更好地控制请求处理流程
- 全面提供健全的类型安全，包括中间件和错误处理
- 在中间件、封装和插件风格上与 Fastify 有些相似

“能够兼容”和“专为某个平台构建”之间有很大的**区别**。

如果决定在 Cloudflare Workers 上使用 Elysia，可能无法开箱即用地获得 Hono 提供的一些 Cloudflare 专属功能。同样，在 Bun 上使用 Hono，性能可能不如使用 Elysia。

## 性能
历史基准测试中，Elysia 借助静态代码分析，速度一直快于 Hono。

此处对比的是 2025-02-24 的历史 [TechEmpower 第 23 轮结果](https://www.techempower.com/benchmarks/#section=data-r23&test=json)，测试内容为 JSON 序列化。下列数据是记录中的框架与运行时组合，并非对 Elysia v2 的测量结果。

| 框架 | 每秒请求数 |
| --- | ---: |
| Elysia | 1,837,294 |
| Hono | 740,451 |

## 路由

Hono 和 Elysia 的路由语法相似，都使用 `app.get()` 和 `app.post()` 方法定义路由，路径参数的写法也相近。

两者都使用单个 `Context` 参数处理请求和响应，并直接返回响应。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const app = new Hono()

app.get('/', (c) => {
    return c.text('Hello World')
})

app.post('/id/:id', (c) => {
	c.status(201)
    return c.text(c.req.param('id'))
})

export default app
```

> Hono 使用 `c.text` 和 `c.json` 辅助方法返回响应

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', 'Hello World')
    .post(
    	'/id/:id',
     	({ status, params: { id } }) => {
      		return status(201, id)
      	}
    )
    .listen(3000)
```

> Elysia 使用单个 `context`，并直接返回响应

</div>
</div>

<div class="content-layout">

Hono 使用 `c.text` 和 `c.json` 封装响应，而 Elysia 会自动将返回值转换为响应。

两者的风格略有不同：Elysia 推荐使用方法链和对象解构。

Hono 的端口分配方式取决于运行时和适配器，而 Elysia 使用统一的 `listen` 方法启动服务器。

## 处理器

Hono 需要手动调用函数解析查询参数、请求头和请求体，而 Elysia 会自动解析这些属性。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const app = new Hono()

app.post('/user', async (c) => {
	const limit = c.req.query('limit')
    const { name } = await c.req.json()
    const auth = c.req.header('authorization')

    return c.json({ limit, name, auth })
})
```

> Hono 使用 `c.req.json()` 读取 JSON，并通过 `c.req` 提供查询参数和请求头的访问方法。

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.post('/user', { body: t.Object({ name: t.String() }) }, (ctx) => {
	    const limit = ctx.query.limit
	    const name = ctx.body.name
	    const auth = ctx.headers.authorization

	    return { limit, name, auth }
	})
```

> Elysia 使用静态代码分析来判断需要解析哪些内容

</div>
</div>

<div class="content-layout">

Elysia 使用**静态代码分析**判断需要解析哪些内容，并且只解析必需的属性。

这有助于提升性能和类型安全。

## 子路由

两者都可以将另一个实例作为路由器继承使用，而 Elysia 将每个实例都视为可用作子路由的组件。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const subRouter = new Hono()

subRouter.get('/user', (c) => {
	return c.text('Hello User')
})

const app = new Hono()

app.route('/api', subRouter)
```

> Hono **必须**使用前缀来区分子路由

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia({ prefix: '/api' })
	.get('/user', 'Hello User')

const app = new Elysia()
	.use(subRouter)
```

> Elysia 可以通过构造函数中的可选前缀来定义子路由前缀

</div>
</div>

<div class="content-layout">

Hono 必须使用前缀来区分子路由，而 Elysia 不要求必须设置前缀。

## 校验
Hono 通过外部包支持多种校验器；Elysia 内置基于 **TypeBox** 的校验，并原生支持 Standard Schema，因此无需额外适配即可使用你喜欢的库，例如 Zod、Valibot、ArkType、Effect Schema 等。Elysia 还可无缝集成 OpenAPI，并自动完成类型推断。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { zValidator } from '@hono/zod-validator'
import { z } from 'zod'

const app = new Hono()

app.patch(
	'/user/:id',
	zValidator(
		'param',
		z.object({
			id: z.coerce.number()
		})
	),
	zValidator(
		'json',
		z.object({
			name: z.string()
		})
	),
	(c) => {
		return c.json({
			params: c.req.valid('param'),
			body: c.req.valid('json')
		})
	}
)
```

> Hono 使用管道式处理方式

</div>
<div>

```ts title="Elysia TypeBox"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.patch('/user/:id', {
		params: t.Object({
			id: t.Number()
		}),
		body: t.Object({
			name: t.String()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Zod"
import { Elysia } from 'elysia'
import { z } from 'zod'

const app = new Elysia()
	.patch('/user/:id', {
		params: z.object({
			id: z.coerce.number()
		}),
		body: z.object({
			name: z.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Valibot"
import { Elysia } from 'elysia'
import * as v from 'valibot'

const app = new Elysia()
	.patch('/user/:id', {
		params: v.object({
			id: v.pipe(v.string(), v.transform(Number), v.number())
		}),
		body: v.object({
			name: v.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

> Elysia 使用 TypeBox 进行校验并自动转换类型，同时也支持 Zod、Valibot 等多种校验库，使用方式一致。

</div>
</div>

<div class="content-layout">

两者都能自动将 schema 中的类型推断到上下文中。

## 文件上传
Hono 和 Elysia 都使用 Web Standard API 处理文件上传，并通过 **file-type** 校验 MIME 类型。Elysia 只需注册一次，即可声明式地完成校验。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { z } from 'zod'
import { zValidator } from '@hono/zod-validator'

import { fileTypeFromBlob } from 'file-type'

const app = new Hono()

app.post(
	'/upload',
	zValidator(
		'form',
		z.object({
			file: z.instanceof(File)
		})
	),
	async (c) => {
		const body = c.req.valid('form')

		const type = await fileTypeFromBlob(body.file)
		if (!type || !type.mime.startsWith('image/')) {
			c.status(422)
			return c.text('File is not a valid image')
		}

		return new Response(body.file)
	}
)
```

> Hono 在处理器中调用 `file-type` 校验 MIME 类型

</div>
<div>

```ts title="Elysia"
import { Elysia, t, setFileTypeDetector } from 'elysia'
import { fileTypeFromBlob } from 'file-type'

setFileTypeDetector(fileTypeFromBlob)

const app = new Elysia()
	.post('/upload', {
		body: t.Object({
			file: t.File({
				type: 'image/*'
			})
		})
	}, ({ body }) => body.file)
```

> Elysia 只需注册一次 `file-type`，即可声明式地校验 MIME 类型

</div>
</div>

<div class="content-layout">

Web Standard API 不会校验 MIME 类型，因此信任客户端提供的 `content-type` 存在安全风险。两者都使用 `file-type` 检查文件字节。Elysia 通过 `setFileTypeDetector` 注册一次检测器，然后用 `t.File({ type })` 声明要检查的类型。检测器是必需的：如果没有注册，所有使用 `type` 检查的上传都会校验失败。

## 中间件

Hono 中间件采用类似 Express 的单一队列顺序；Elysia 则通过**基于事件**的生命周期提供更精细的控制。

Elysia 会公开[请求生命周期](/essential/life-cycle)的各个阶段：

| 阶段 | 用途 |
| --- | --- |
| 请求 | 在解析前检查传入请求 |
| 解析 | 解码请求体 |
| 转换与校验 | 规范化并校验请求输入 |
| 处理前 | 派生请求值或提前返回响应 |
| 处理器 | 生成路由响应 |
| 处理后与响应映射 | 调整并序列化响应 |
| 响应后 | 在响应发送后执行任务 |

错误钩子负责处理此流程中的失败。

Hono 的请求处理流程是单一且按顺序执行的，而 Elysia 可以拦截请求流程中的每个事件。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const app = new Hono()

// Global middleware
app.use(async (c, next) => {
	console.log(`${c.req.method} ${c.req.url}`)

	await next()
})

app.get(
	'/protected',
	// Route-specific middleware
	async (c, next) => {
	  	const token = c.req.header('authorization')

	  	if (!token) {
			c.status(401)
	   		return c.text('Unauthorized')
		}

	  	await next()
	},
	(c) => c.text('Protected route')
)
```

> Hono 使用单一队列管理中间件，并按顺序执行

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	// Global middleware
	.onRequest(({ request }) => {
		console.log(request.method, new URL(request.url).pathname)
	})
	// Route-specific middleware
	.get('/protected', {
		beforeHandle({ status, headers }) {
  			if (!headers.authorization)
     			return status(401)
		}
	}, () => 'protected')
```

> Elysia 在请求流程的每个阶段都使用对应的事件拦截器

</div>
</div>

<div class="content-layout">

Hono 使用 `next` 函数调用下一个中间件，而 Elysia 没有这个函数。

## 健全的类型安全
Elysia 的设计目标是提供健全的类型安全。

例如，[derive](/essential/life-cycle#derive) 可以添加请求级上下文，并自动推断类型。在 v2 中，它也接替了此前由 `resolve` 承担的已校验上下文功能。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { createMiddleware } from 'hono/factory'

const app = new Hono()

const getVersion = createMiddleware(async (c, next) => {
	c.set('version', 2)

	await next()
})

app.use(getVersion)

app.get('/version', getVersion, (c) => {
	return c.text(c.get('version') + '')
})

const authenticate = createMiddleware(async (c, next) => {
	const token = c.req.header('authorization')

	if (!token) {
		c.status(401)
		return c.text('Unauthorized')
	}

	c.set('token', token.split(' ')[1])

	await next()
})

app.post('/user', authenticate, async (c) => {
	c.get('version')

	return c.text(c.get('token'))
})
```

> Hono 使用中间件扩展上下文，但不具备类型安全

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	.decorate('version', 2)
	.get('/version', ({ version }) => version)
	.derive(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)

		return {
			token: authorization.split(' ')[1]
		}
	})
	// {  token: string, version: number }
	.get('/token', ({ token, version }) => {
		return token
	})
```

> Elysia 使用 `decorate` 扩展上下文，并通过 `derive` 向上下文添加自定义属性

</div>
</div>

<div class="content-layout">

此处的 Bearer 前缀检查仅作示例，并不等同于真实的凭证验证。单独检查请求头或 Bearer 前缀并不能完成身份验证。

Hono 可以通过 `declare module` 扩展 `ContextVariableMap` 接口，但扩展是全局可见的，类型安全并不健全，也无法保证该属性在所有请求处理器中都可用。

```ts
declare module 'hono' {
  	interface ContextVariableMap {
    	version: number
  		token: string
  	}
}
```
> 上述 Hono 示例需要这段声明才能工作，但它并不能提供健全的类型安全

## 中间件参数
Hono 使用回调函数定义可复用的路由专属中间件，而 Elysia 使用 [macro](/patterns/macro) 定义自定义钩子。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { findUser } from './users'
import { Hono } from 'hono'
import { createMiddleware } from 'hono/factory'

const app = new Hono()

const role = (role: 'user' | 'admin') => createMiddleware(async (c, next) => {
	const user = findUser(c.req.header('Authorization'))

	if(!user || user.role !== role) {
		c.status(401)
		return c.text('Unauthorized')
	}

	c.set('user', user)

	await next()
})

app.get('/user/:id', role('admin'), (c) => {
	// Error: No overload matches this call.
	return c.json(c.get('user'))
})
```

> Hono 通过回调返回 `createMiddleware` 来创建可复用的中间件，但不具备类型安全

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'
import { findUser } from './users'

const app = new Elysia()
	.macro({
		role: (role: 'user' | 'admin') => ({
			derive({ status, headers: { authorization } }) {
				const user = findUser(authorization)

				if (!user || user.role !== role)
					return status(401)

				return {
					user
				}
			}
		})
	})
	// { user: User }
	.get('/token', {
		role: 'admin'
	}, ({ user }) => user)
```

> Elysia 使用宏向自定义中间件传递自定义参数

</div>
</div>

<div class="content-layout">

这里的 `findUser` 是应用代码，用于验证提供的凭证；验证成功时返回带有 `role` 的用户，失败时则不返回用户。单独检查请求头或 Bearer 前缀并不能完成身份验证。

## 错误处理

Hono 提供作用于所有路由的 `onError` 函数，而 Elysia 对错误处理提供了更精细的控制。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const app = new Hono()

class CustomError extends Error {
	constructor(message: string) {
		super(message)
		this.name = 'CustomError'
	}
}

// global error handler
app.onError((error, c) => {
	if(error instanceof CustomError) {
		c.status(500)

		return c.json({
			message: 'Something went wrong!',
			error
		})
	}

	return c.text('Internal Server Error', 500)
})

// This route throws an error handled by onError.
app.get('/error', () => {
	throw new CustomError('oh uh')
})
```

> Hono 使用 `onError` 函数处理错误，由一个错误处理器处理所有路由

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

class CustomError extends Error {
    status = 500
}

const app = new Elysia()
    .onError(CustomError, ({ error, status }) =>
        status(500, { message: 'Something went wrong!', detail: error.message })
    )
    .get('/error', () => {
        throw new CustomError('oh uh')
    })
    .get('/local-error', {
        error({ error, status }) {
            if (error instanceof RangeError)
                return status(500, { message: 'Only for this route!' })
        }
    }, () => {
        throw new RangeError('outside the allowed range')
    })
```

> Elysia 提供更精细的错误处理控制和作用域机制

</div>
</div>

<div class="content-layout">

Hono 在应用级别提供 `onError`，而 Elysia 还提供：

1. 全局和路由专属的错误处理器
2. 用于返回带有 HTTP 状态码响应的 `status` 辅助方法
3. 带有 `status` 的错误（或 `HTTPError`）会映射到对应的 HTTP 状态码

`/error` 路由使用已注册的 `CustomError` 处理器。`/local-error` 路由则在本地处理另一种错误。错误钩子按注册顺序运行，第一个返回值的钩子会发送响应。在路由之前注册到应用上的钩子会先于该路由自己的 `error` 钩子运行，因此路由钩子无法覆盖它们。

Elysia 会在针对特定错误类的处理器中推断已注册的错误类型。

## 封装

Hono 会封装插件的副作用；Elysia 则通过明确的作用域机制和代码顺序，让你控制插件副作用的影响范围。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'

const subRouter = new Hono()

subRouter.use(async (c, next) => {
	if (!c.req.header('authorization')?.startsWith('Bearer '))
		return c.text('Unauthorized', 401)

	await next()
})

subRouter.get('/user', (c) => {
	return c.text('Hello User')
})

const app = new Hono()

app.route('/api', subRouter)
// doesn't have side-effect from subRouter
app.get('/side-effect', (c) => c.text('hi'))
```

> Hono 会封装插件的副作用

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // doesn't have side-effect from subRouter
    .get('/side-effect', () => 'hi')
```

> 除非显式指定，Elysia 会封装插件的副作用

</div>
</div>

<div class="content-layout">

两者都提供插件封装机制，以避免副作用外溢。

不过，Elysia 可以通过声明插件作用域，明确指定哪些插件副作用应当生效；Hono 则将中间件保留在注册它的路由器上。

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})
	// Scoped to parent instance but not beyond
	.as('plugin') // [!code ++]

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // [!code ++]
    // now has side-effects from subRouter
    .get('/side-effect', () => 'hi')
```

Elysia 提供 3 种作用域机制：
1. **local** - 作用于当前实例及其后代（默认）
2. **plugin** - 与父实例共享副作用，但不再向外传播
3. **global** - 在所有父实例之间共享

---

由于 Hono 无法与父级共享子路由器的中间件，下面的示例为每个钩子创建函数并手动添加。

不过，如果处理不慎，这可能导致副作用重复执行。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { createMiddleware } from 'hono/factory'

const middleware = createMiddleware(async (c, next) => {
	console.log('called')

	await next()
})

const app = new Hono()
const subRouter = new Hono()

app.use(middleware)
app.get('/main', (c) => c.text('Hello from main!'))

subRouter.use(middleware)

// This would log twice
subRouter.get('/sub', (c) => c.text('Hello from sub router!'))

app.route('/sub', subRouter)

export default app
```

</div>
<div>

在这种情况下，Elysia 提供插件去重机制，避免副作用重复执行。

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia({ name: 'subRouter' }) // [!code ++]
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})
	.as('plugin')

const app = new Elysia()
	.get('/', 'Hello World')
	.use(subRouter)
	.use(subRouter) // [!code ++]
	.use(subRouter) // [!code ++]
	.use(subRouter) // [!code ++]
	// side-effect only called once
	.get('/side-effect', () => 'hi')
```

使用唯一的 `name` 后，Elysia 只会应用该插件一次，从而避免副作用重复执行。

</div>
</div>

## Cookie 处理
Hono 在 `hono/cookie` 中内置了 Cookie 工具函数，而 Elysia 使用基于信号的方式处理 Cookie。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { getSignedCookie, setSignedCookie } from 'hono/cookie'

const app = new Hono()

app.get('/', async (c) => {
	const name = await getSignedCookie(c, 'secret', 'name')

	await setSignedCookie(
		c,
		'name',
		'value',
		'secret',
		{
			maxAge: 1000,
		}
	)
})
```

> Hono 使用工具函数处理 Cookie

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'

const app = new Elysia({
    cookie: {
        secrets: 'replace-with-a-private-secret',
        sign: ['name']
    }
})
    .get('/', {
        cookie: t.Cookie({ name: t.Optional(t.String()) })
    }, ({ cookie: { name } }) => {
        const previous = name.value
        name.set({
            value: 'value',
            maxAge: 60 * 60 * 24,
            httpOnly: true,
            secure: true,
            sameSite: 'lax'
        })
        return previous ?? 'unset'
    })
```

> Elysia 会自动验证并签名已配置的 Cookie。Cookie 的 `maxAge` 单位为秒；请将示例密钥替换为私密值，并通过 HTTPS 发送安全 Cookie。

</div>
</div>

## OpenAPI
Hono 需要额外工作来描述规范，而 Elysia 可以将规范无缝集成到 schema 中。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { describeRoute, openAPISpecs } from 'hono-openapi'
import { resolver, validator as zodValidator } from 'hono-openapi/zod'
import { swaggerUI } from '@hono/swagger-ui'

import { z } from '@hono/zod-openapi'

const app = new Hono()

const model = z.array(
	z.object({
		name: z.string().openapi({
			description: 'first name only'
		}),
		age: z.number()
	})
)

const detail = await resolver(model).builder()

console.log(detail)

app.post(
	'/',
	zodValidator('json', model),
	describeRoute({
		validateResponse: true,
		summary: 'Create user',
		requestBody: {
			content: {
				'application/json': { schema: detail.schema }
			}
		},
		responses: {
			201: {
				description: 'User created',
				content: {
					'application/json': { schema: resolver(model) }
				}
			}
		}
	}),
	(c) => {
		c.status(201)
		return c.json(c.req.valid('json'))
	}
)

app.get('/ui', swaggerUI({ url: '/doc' }))

app.get(
	'/doc',
	openAPISpecs(app, {
		documentation: {
			info: {
				title: 'Hono API',
				version: '1.0.0',
				description: 'Greeting API'
			},
			components: {
				...detail.components
			}
		}
	})
)

export default app
```

> Hono 需要额外工作来描述规范

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi' // [!code ++]

const app = new Elysia()
	.use(openapi()) // [!code ++]
	.model({
		user: t.Array(
			t.Object({
				name: t.String(),
				age: t.Number()
			})
		)
	})
	.post('/users', {
		body: 'user',
		response: {
			201: 'user'
		},
		detail: {
			summary: 'Create user'
		}
	}, ({ body, status }) => status(201, body))

```

> Elysia 将规范无缝集成到 schema 中

</div>
</div>

<div class="content-layout">

Hono 使用单独的函数描述路由规范并执行校验，需要一些额外工作才能正确配置。

Elysia 使用你提供的 schema 生成 OpenAPI 规范、校验请求和响应，并自动推断类型，所有信息都来自**单一可信来源**。

Elysia 还会将注册在 `model` 中的 schema 添加到 OpenAPI 规范中，让你能在 Swagger 或 Scalar UI 的专属区域引用该模型；Hono 则会将 schema 内联到路由中。

## 端到端类型安全
两者都提供端到端类型安全。不过，Hono 似乎无法根据状态码提供类型安全的错误处理。

</div>

<div class="code-comparison">
<div>

```ts title="Hono"
import { Hono } from 'hono'
import { hc } from 'hono/client'
import { z } from 'zod'
import { zValidator } from '@hono/zod-validator'

const app = new Hono()
	.post(
		'/mirror',
		zValidator(
			'json',
			z.object({
				message: z.string()
			})
		),
		(c) => c.json(c.req.valid('json'))
	)

const client = hc<typeof app>('/')

const response = await client.mirror.$post({
	json: {
		message: 'Hello, world!'
	}
})

// { message: string }
const data = await response.json()
```

> Hono 使用 `hc` 发起请求，并提供端到端类型安全

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'
import { treaty } from '@elysia/eden'

const app = new Elysia()
	.post('/mirror', {
		body: t.Object({
			message: t.String()
		})
	}, ({ body }) => body)

const api = treaty(app)

const { data, error } = await api.mirror.post({
	message: 'Hello World'
})

if (error)
	// error.status: 422
	// error.value: { type: 'validation', title: 'Validation Error', status: 422, on: 'body', detail, errors: [...] }
	throw error

// { message: 'Hello World' }
console.log(data)
```

> Elysia 使用 `treaty` 发起请求，并提供端到端类型安全

</div>
</div>

<div class="content-layout">

虽然两者都提供端到端类型安全，但 Elysia 能基于状态码提供更完善的类型安全错误处理，而 Hono 无法做到这一点。

以下类型推断耗时是根据截图中使用的版本和 schema 记录的历史数据，并非当前版本的基准测试。
