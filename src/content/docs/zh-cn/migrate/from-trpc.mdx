<h1 id="_top">从 tRPC 迁移到 Elysia</h1>

:::note[Elysia v2]

Elysia 示例使用 v2：路由选项写在处理器之前，生命周期方法使用对应的事件名称，请求派生值则使用 `derive`。其他框架的示例展示了各自典型的配置方式，目的是说明迁移方法，并非罗列其所有当前功能。框架集成包有各自的版本兼容要求；迁移应用时请确认相关包的兼容性。

:::

本指南面向 tRPC 用户，通过示例介绍 tRPC 与 Elysia 的语法等差异，以及如何将应用从 tRPC 迁移到 Elysia。

**tRPC** 是一个使用 TypeScript 构建 API 的类型安全 RPC 框架，可通过前后端之间的类型安全契约，构建端到端类型安全的 API。

**Elysia** 是一款易用且对开发者友好的 Web 框架，专注于**健全的类型安全**与性能。

## 概览
tRPC 主要面向 RPC 通信，在 RESTful API 之上提供专有抽象；Elysia 则专注于 RESTful API。

tRPC 的主要特性是前后端之间的端到端类型安全契约，Elysia 也可通过 [Eden](/eden) 提供这一能力。

因此，Elysia 更适合构建通用 API：开发者可以沿用熟悉的 RESTful 标准，无需学习新的专有抽象，同时仍能获得 tRPC 所提供的端到端类型安全。

## 路由

Elysia 使用类似 Express 和 Hono 的语法，通过 `app.get()`、`app.post()` 等方法定义路由，路径参数的写法也相似。

tRPC 则通过嵌套路由器来定义路由。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'
import { createHTTPServer } from '@trpc/server/adapters/standalone'

const t = initTRPC.create()

const appRouter = t.router({
	hello: t.procedure.query(() => 'Hello World'),
	user: t.router({
		getById: t.procedure
			.input((id: string) => id)
			.query(({ input }) => {
				return { id: input }
			})
	})
})

const server = createHTTPServer({
  	router: appRouter
})

server.listen(3000)
```

> tRPC 使用嵌套路由器和 procedure 定义路由

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
    .get('/', 'Hello World')
    .get('/user/:id', ({ params: { id } }) => ({ id }))
    .listen(3000)
```

> Elysia 使用 HTTP 方法和路径参数定义路由

</div>
</div>

<div class="content-layout">

虽然 tRPC 在 RESTful API 之上使用 procedure 和 router 这套专有抽象，Elysia 则采用类似 Express 和 Hono 的语法，通过 `app.get()`、`app.post()` 等方法定义路由，路径参数的写法也相近。

## 处理器

tRPC 的处理器称为 `procedure`，可以是 `query` 或 `mutation`；Elysia 则使用 `get`、`post`、`put`、`delete` 等 HTTP 方法。

tRPC 没有查询参数、请求头、状态码等 HTTP 属性的概念，只有 `input` 和 `output`。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'

const t = initTRPC.create()

const appRouter = t.router({
	user: t.procedure
		.input((val: { limit?: number; name: string; authorization?: string }) => val)
		.mutation(({ input }) => {
			const limit = input.limit
			const name = input.name
			const auth = input.authorization

			return { limit, name, auth }
		})
})
```

> tRPC 使用单一的 `input` 承载所有属性

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.post('/user', { body: t.Object({ name: t.String() }) }, (ctx) => {
	    const limit = ctx.query.limit
	    const name = ctx.body.name
	    const auth = ctx.headers.authorization

	    return { limit, name, auth }
	})
```

> Elysia 为每种 HTTP 属性提供对应的属性

</div>
</div>

<div class="content-layout">

Elysia 使用**静态代码分析**确定需要解析哪些内容，并且只解析必要的属性。

这有助于提升性能并确保类型安全。

## 子路由器

tRPC 使用嵌套路由器定义子路由器，Elysia 则使用 `.use()` 方法。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'

const t = initTRPC.create()

const subRouter = t.router({
	user: t.procedure.query(() => 'Hello User')
})

const appRouter = t.router({
	api: subRouter
})
```

> tRPC 使用嵌套路由器定义子路由器

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia({ prefix: '/api' })
	.get('/user', 'Hello User')

const app = new Elysia()
	.use(subRouter)
```

> Elysia 使用 `.use()` 方法定义子路由器

</div>
</div>

<div class="content-layout">

在 tRPC 中可以内联子路由器；Elysia 则通过 `.use()` 方法定义子路由器。

## 校验
两者都支持 Standard Schema，因此你可以使用 Zod、Yup、Valibot 等各种校验库。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'
import { z } from 'zod'

const t = initTRPC.create()

const appRouter = t.router({
	user: t.procedure
		.input(
			z.object({
				id: z.number(),
				name: z.string()
			})
		)
		.mutation(({ input }) => input)
//                    ^?
})
```

> tRPC 使用 `input` 定义校验 Schema

</div>
<div>

```ts title="Elysia TypeBox"
import { Elysia, t } from 'elysia'

const app = new Elysia()
	.patch('/user/:id', {
		params: t.Object({
			id: t.Number()
		}),
		body: t.Object({
			name: t.String()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Zod"
import { Elysia } from 'elysia'
import { z } from 'zod'

const app = new Elysia()
	.patch('/user/:id', {
		params: z.object({
			id: z.coerce.number()
		}),
		body: z.object({
			name: z.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

```ts title="Elysia Valibot"
import { Elysia } from 'elysia'
import * as v from 'valibot'

const app = new Elysia()
	.patch('/user/:id', {
		params: v.object({
			id: v.pipe(v.string(), v.transform(Number), v.number())
		}),
		body: v.object({
			name: v.string()
		})
	}, ({ params, body }) => ({
		params,
		body
	}))
```

> Elysia 使用对应的属性定义校验 Schema

</div>
</div>

<div class="content-layout">

两者都能根据 Schema 自动推导上下文类型。

## 文件上传
这个 tRPC 示例将文件编码为 base64 字符串传输，并显式检查文件字节。这会增加编码开销；可用的上传方式取决于 tRPC 版本和传输层。

Elysia 使用 Web Standard API 处理文件上传，并通过同一个 `file-type` 库检查文件字节；检测器只需注册一次。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC, TRPCError } from '@trpc/server'
import { z } from 'zod'

import { fileTypeFromBuffer } from 'file-type'
import { Buffer } from 'node:buffer'

const t = initTRPC.create()

export const uploadRouter = t.router({
	uploadImage: t.procedure
		.input(z.base64())
		.mutation(async ({ input }) => {
			const buffer = Buffer.from(input, 'base64')

			const type = await fileTypeFromBuffer(buffer)
			if (!type || !type.mime.startsWith('image/'))
				throw new TRPCError({
      				code: 'UNPROCESSABLE_CONTENT',
       				message: 'Invalid file type',
    			})

			return input
		})
})
```

> tRPC 以 base64 发送文件，并在 procedure 中调用 `file-type`

</div>
<div>

```ts title="Elysia"
import { Elysia, t, setFileTypeDetector } from 'elysia'
import { fileTypeFromBlob } from 'file-type'

setFileTypeDetector(fileTypeFromBlob)

const app = new Elysia()
	.post('/upload', {
		body: t.Object({
			file: t.File({
				type: 'image/*'
			})
		})
	}, ({ body }) => body.file)
```

> Elysia 只需注册一次 `file-type`，即可通过声明式方式校验 MIME 类型

</div>
</div>

<div class="content-layout">

两者都不会自行检查文件字节，因此都使用 `file-type`。Elysia 通过 `setFileTypeDetector` 注册一次检测器，再用 `t.File({ type })` 声明式地检查类型。检测器不可省略：否则，所有根据 `type` 检查的上传都会校验失败。

## 中间件

tRPC 中间件像 Express 一样通过 `next` 按单一队列顺序执行；Elysia 则通过**基于事件**的生命周期提供更细粒度的控制。

Elysia 将[请求生命周期](/essential/life-cycle)划分为以下阶段：

| 阶段 | 用途 |
| --- | --- |
| Request | 在解析前检查传入请求 |
| Parse | 解码请求体 |
| Transform and validation | 规范化并校验请求输入 |
| Before handle | 派生请求值或提前返回响应 |
| Handler | 生成路由响应 |
| After handle and map response | 调整并序列化响应 |
| After response | 在发送响应后执行任务 |

错误钩子用于处理此流程中的失败。

tRPC 的请求管线只有一条按序执行的流程；Elysia 则可以拦截管线中的每个事件。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'

const t = initTRPC.create()

const log = t.middleware(async ({ ctx, next }) => {
	console.log('Request started')

	const result = await next()

	console.log('Request ended')

	return result
})

const appRouter = t.router({
	hello: t.procedure.use(log).query(() => 'Hello World')
})
```

> tRPC 以 procedure 定义单一的中间件队列

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	// Global middleware
	.onRequest(({ request }) => {
		console.log(request.method, new URL(request.url).pathname)
	})
	// Route-specific middleware
	.get('/protected', {
		beforeHandle({ status, headers }) {
  			if (!headers.authorization)
     			return status(401)
		}
	}, () => 'protected')
```

> Elysia 为请求管线中的每个阶段提供对应的事件拦截器

</div>
</div>

<div class="content-layout">

tRPC 使用 `next` 函数调用队列中的下一个中间件；Elysia 则为请求管线中的每个阶段提供对应的事件拦截器。

## 可靠的类型安全
Elysia 致力于提供可靠的类型安全。

例如，[derive](/essential/life-cycle#derive) 可以添加请求级上下文，并自动推导类型。在 v2 中，它也接替了此前由 `resolve` 承担的已校验上下文功能。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'

const t = initTRPC.context<{
	version: number
	token: string
}>().create()

const appRouter = t.router({
	version: t.procedure.query(({ ctx: { version } }) => version),
	token: t.procedure.query(({ ctx: { token, version } }) => {
		return token
	})
})
```

> tRPC 使用 `context` 扩展上下文，但不具备可靠的类型安全

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const app = new Elysia()
	.decorate('version', 2)
	.get('/version', ({ version }) => version)
	.derive(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)

		return {
			token: authorization.split(' ')[1]
		}
	})
	// {  token: string, version: number }
	.get('/token', ({ token, version }) => {
		return token
	})
```

> Elysia 使用 `decorate` 扩展上下文，并用 `derive` 向上下文添加自定义属性

</div>
</div>

<div class="content-layout">

## 中间件参数
两者都支持自定义中间件，但 Elysia 使用 macro 向自定义中间件传入参数，tRPC 则使用高阶函数。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC, TRPCError } from '@trpc/server'
import { findUser } from './users'

const t = initTRPC.context<{ authorization?: string }>().create()

const role = (role: 'user' | 'admin') =>
	t.middleware(({ ctx, next }) => {
		const user = findUser(ctx.authorization)

		if (!user || user.role !== role)
			throw new TRPCError({
      			code: 'UNAUTHORIZED',
      			message: 'Unauthorized',
    		})

		return next({
			ctx: {
				user
			}
		})
	})

const appRouter = t.router({
	token: t.procedure
		.use(role('admin'))
		.query(({ ctx: { user } }) => user)
})
```

> tRPC 使用高阶函数向自定义中间件传入参数

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'
import { findUser } from './users'

const app = new Elysia()
	.macro({
		role: (role: 'user' | 'admin') => ({
			derive({ status, headers: { authorization } }) {
				const user = findUser(authorization)

				if (!user || user.role !== role)
					return status(401)

				return {
					user
				}
			}
		})
	})
	// The handler receives the user returned by the macro.
	.get('/token', {
		role: 'admin'
	}, ({ user }) => user)
```

> Elysia 使用 macro 向自定义中间件传入参数

</div>
</div>

<div class="content-layout">

这里的 `findUser` 是应用代码，用于验证所提供的凭据；验证成功时返回带有 `role` 的用户，失败时则不返回用户。仅检查请求头是否存在或是否带有 Bearer 前缀，并不构成身份验证。

## 错误处理

tRPC 采用类似中间件的方式处理错误；Elysia 则提供类型安全的自定义错误，以及全局和路由级别的错误拦截器。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC, TRPCError } from '@trpc/server'

const t = initTRPC.create()

class CustomError extends Error {
	constructor(message: string) {
		super(message)
		this.name = 'CustomError'
	}
}

const procedure = t.procedure.use(async ({ next }) => {
	const result = await next()

	if (!result.ok) {
		console.log(result.error)

		throw new TRPCError({
			code: 'INTERNAL_SERVER_ERROR',
			message: result.error.message
		})
	}

	return result
})

const appRouter = t.router({
	error: procedure.query(() => {
		throw new CustomError('oh uh')
	})
})
```

> tRPC 采用类似中间件的方式处理错误

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

class CustomError extends Error {
    status = 500
}

const app = new Elysia()
    .onError(CustomError, ({ error, status }) =>
        status(500, { message: 'Something went wrong!', detail: error.message })
    )
    .get('/error', () => {
        throw new CustomError('oh uh')
    })
    .get('/local-error', {
        error({ error, status }) {
            if (error instanceof RangeError)
                return status(500, { message: 'Only for this route!' })
        }
    }, () => {
        throw new RangeError('outside the allowed range')
    })
```

> Elysia 提供更细粒度的错误处理控制和作用域机制

</div>
</div>

<div class="content-layout">

与采用类似中间件方式处理错误的 tRPC 不同，Elysia 提供：

1. 全局和路由级别的错误处理器
2. 用于返回指定 HTTP 状态码响应的 `status` 辅助函数
3. 带有 `status` 的错误（或 `HTTPError`）会映射到对应的 HTTP 状态码

`/error` 路由使用已注册的 `CustomError` 处理器。`/local-error` 路由则在本地处理另一种错误。错误钩子按注册顺序运行，第一个返回值的钩子会发送响应。在路由之前注册到 app 上的钩子会先于该路由自己的 `error` 钩子运行，因此路由钩子无法覆盖它们。

Elysia 会在针对特定错误类的处理器中推导已注册的错误类型。

## 封装

tRPC 会封装 procedure 或 router 的副作用，使其始终相互隔离；Elysia 则通过显式作用域机制和代码顺序，让你控制插件的副作用。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC, TRPCError } from '@trpc/server'

// Supply these headers from your adapter's createContext callback.
type Context = { headers: { authorization?: string } }
const t = initTRPC.context<Context>().create()

const protectedProcedure = t.procedure.use(({ ctx, next }) => {
    if (!ctx.headers.authorization?.startsWith('Bearer '))
        throw new TRPCError({
            code: 'UNAUTHORIZED',
            message: 'Unauthorized'
        })

    return next()
})

const subRouter = t.router({
    sideEffect: protectedProcedure.mutation(() => 'hi')
})

const appRouter = t.router({
    // This procedure does not use the protected middleware.
    hello: t.procedure.query(() => 'Hello World'),
    api: subRouter
})
```

> tRPC 将插件副作用封装在 procedure 或 router 中

</div>
<div>

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // doesn't have side-effect from subRouter
    .get('/side-effect', () => 'hi')
```

> 除非显式指定，否则 Elysia 会封装插件的副作用

</div>
</div>

<div class="content-layout">

两者都通过插件封装机制避免副作用扩散。

不过，Elysia 可以声明插件作用域，明确指定哪些插件可以产生副作用；tRPC 则始终会封装副作用。

```ts title="Elysia"
import { Elysia } from 'elysia'

const subRouter = new Elysia()
	.onBeforeHandle(({ status, headers: { authorization } }) => {
		if(!authorization?.startsWith('Bearer '))
			return status(401)
   	})
	// Scoped to parent instance but not beyond
	.as('plugin') // [!code ++]

const app = new Elysia()
    .get('/', 'Hello World')
    .use(subRouter)
    // [!code ++]
    // now have side-effect from subRouter
    .get('/side-effect', () => 'hi')
```

Elysia 提供 3 种作用域机制：
1. **local** - 作用于当前实例及其后代（默认）
2. **plugin** - 与父实例共享副作用，但不再向外传播
3. **global** - 在所有父实例之间共享

## OpenAPI
tRPC 没有内置 OpenAPI 支持，需要依赖 `trpc-to-openapi` 等第三方库，集成流程并不简洁。

Elysia 只需一行代码，通过 [@elysia/openapi](/plugins/openapi) 插件即可集成 OpenAPI。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'
import { z } from 'zod'

import { generateOpenApiDocument, type OpenApiMeta } from 'trpc-to-openapi'

const t = initTRPC.meta<OpenApiMeta>().create()

const appRouter = t.router({
	user: t.procedure
		.meta({
			openapi: {
				method: 'POST',
				path: '/users',
				tags: ['User'],
				summary: 'Create user',
			}
		})
		.input(z.object({
			users: z.array(z.object({
				name: z.string(),
				age: z.number()
			}))
		}))
		.output(
			z.array(
				z.object({
					name: z.string(),
					age: z.number()
				})
			)
		)
		.mutation(({ input }) => input.users)
})

export const openApiDocument = generateOpenApiDocument(appRouter, {
  	title: 'tRPC OpenAPI',
  	version: '1.0.0',
  	baseUrl: 'http://localhost:3000'
})
```

> tRPC 依赖第三方库生成 OpenAPI 规范。该插件要求 mutation 的输入为对象，因此示例将用户数组包装在 `users` 中。

</div>
<div>

```ts title="Elysia"
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi' // [!code ++]

const app = new Elysia()
	.use(openapi()) // [!code ++]
	.model({
		user: t.Array(
			t.Object({
				name: t.String(),
				age: t.Number()
			})
		)
	})
	.post('/users', {
		body: 'user',
		response: {
			201: 'user'
		},
		detail: {
			summary: 'Create user'
		}
	}, ({ body, status }) => status(201, body))
```

> Elysia 可将 OpenAPI 规范无缝集成到 Schema 中

</div>
</div>

<div class="content-layout">

tRPC 依赖第三方库生成 OpenAPI 规范，并且**必须**在元数据中定义正确的路径名称和 HTTP 方法。这迫使你必须**时刻留意** router 和 procedure 的组织方式。

Elysia 根据你提供的 Schema 生成 OpenAPI 规范、校验请求和响应，并自动推导类型，所有信息都来自**单一事实来源**。

Elysia 还会将通过 `model` 注册的 Schema 添加到 OpenAPI 规范中，让你可以在 Swagger 或 Scalar UI 的专属区块中引用模型。tRPC 则缺少此功能，会将 Schema 内联到路由中。

import { describe, it, expect } from 'vitest'

import { initTRPC } from '@trpc/server'
import { z } from 'zod'

const t = initTRPC.create()

const publicProcedure = t.procedure
const { createCallerFactory, router } = t

## 端到端类型安全
两者都为客户端与服务器之间的通信提供端到端类型安全。

</div>

<div class="code-comparison">
<div>

```ts title="tRPC"
import { initTRPC } from '@trpc/server'
import { createHTTPServer } from '@trpc/server/adapters/standalone'
import { z }  from 'zod'

import { createTRPCProxyClient, httpBatchLink } from '@trpc/client'

const t = initTRPC.create()

const appRouter = t.router({
	mirror: t.procedure
		.input(
			z.object({
				message: z.string()
			})
		)
		.output(
			z.object({
				message: z.string()
			})
		)
		.mutation(({ input }) => input)
})

const server = createHTTPServer({
  	router: appRouter
})

server.listen(3000)

const client = createTRPCProxyClient<typeof appRouter>({
	links: [
		httpBatchLink({
			url: 'http://localhost:3000'
		})
	]
})

const { message } = await client.mirror.mutate({
	message: 'Hello World'
})

message
```

虽然两者都提供端到端类型安全，但 tRPC 只覆盖请求成功的**正常路径**，错误处理不具备可靠的类型安全，因此整体并不可靠。

如果你看重可靠的类型安全，Elysia 会是更合适的选择。

---

虽然 tRPC 是构建类型安全 API 的优秀框架，但它在 RESTful 规范兼容性和类型安全可靠性方面仍有局限。

Elysia 注重开发体验，力求易用且对开发者友好，并强调**可靠的类型安全**。它遵循 RESTful、OpenAPI 和 WinterCG 标准，因此更适合构建通用 API。
