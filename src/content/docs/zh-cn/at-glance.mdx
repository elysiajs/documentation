## TypeScript

Elysia 帮你减少需要手写的 TypeScript。它会从路由中推断类型，让你专注于业务逻辑，不必反复声明类型。

<CodePlayground
    elysia={paramsDemo}
    alias={{ '/user/:id': '/user/123' }}
    mock={{ '/user/:id': { GET: '123' } }}
>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/user/:id', ({ params: { id } }) => id)
    .get('/user/abc', () => 'abc')
    .listen(3000)
```

</CodePlayground>

`:id` 路径段在运行时会成为 `params.id`，在处理器类型中也会对应为 `params.id`，无需手动声明。它的类型是 `string`。

我们推荐使用 TypeScript，但使用 Elysia 并不以此为前提。类型推断能在编写代码时提供帮助；如果还需要在运行时校验数据，就使用 schema。

## 类型完整性

从 Elysia 导入 `t`，定义一个既能在运行时校验数据、又能提供对应 TypeScript 类型的 schema。这样，输入数据的校验规则和类型就有了同一个可信来源。

我们来把路径参数从字符串改为数字：

```ts
import { Elysia, t } from 'elysia'

new Elysia()
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

在 Elysia 2 中，schema 写在处理器之前。请求 `/user/123` 时，处理器会收到数字 `123`；请求 `/user/abc` 则无法通过校验。在编辑器中将鼠标悬停在 `id` 上，就能看到推断出的 `number` 类型。

同一个 schema 既定义运行时校验规则，也决定处理器输入值的 TypeScript 类型。

## Standard Schema

Elysia 支持 [Standard Schema](https://github.com/standard-schema/standard-schema)，因此你可以使用实现了该标准的验证库版本。

生态中有 Zod、Valibot、ArkType、Effect Schema、Yup、Joi 的集成，以及[其他实现](https://github.com/standard-schema/standard-schema)。请确认你使用的库或适配器实现了 Standard Schema 接口。

```ts
import { Elysia } from 'elysia'
import { z } from 'zod'
import * as v from 'valibot'

new Elysia()
    .get('/id/:id', {
        params: z.object({
            id: z.coerce.number()
        }),
        query: v.object({
            name: v.literal('Lilith')
        })
    }, ({ params: { id }, query: { name } }) => id)
    .listen(3000)
```

这里 Zod 会把路径参数转换为数字，而 Valibot 要求查询参数为 `?name=Lilith`。Elysia 会根据两个 schema 推断校验后的类型。

## OpenAPI

Elysia 支持 OpenAPI、WinterTC 和 Standard Schema 等标准，方便你将它接入熟悉的工具。

添加 [OpenAPI 插件](/plugins/openapi/)，即可根据路由和 schema 生成 API 文档：

```ts
import { Elysia, t } from 'elysia'
import { openapi } from '@elysia/openapi'

new Elysia()
    .use(openapi())
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

该插件会生成一个可与团队分享的文档页面。请使用兼容 Elysia 2 的版本，安装和配置方法请参阅插件文档。

## OpenAPI 类型生成

Elysia 还支持通过 `fromTypes()` 根据 TypeScript 类型生成 OpenAPI schema：

```ts {6}
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)
```

这为 TypeScript 带来了类似 FastAPI 的方式：直接使用代码中的类型生成文档，不必在手写注解中重复定义。设置方法和支持的类型请参阅[从类型生成 OpenAPI](/patterns/openapi/#openapi-from-types)。

## 端到端类型安全

类型安全不止于服务器端。Elysia 的客户端库 **Eden** 能让前端使用服务器端的类型，工作方式与 tRPC 类似。

在 `server.ts` 中导出服务器类型，再在 `client.ts` 中导入：

<FileCodeBlock>
<TabItem label="server.ts">

```ts
import { Elysia, t } from 'elysia'
import { openapi, fromTypes } from '@elysia/openapi'

export const app = new Elysia()
    .use(openapi({
        references: fromTypes()
    }))
    .get('/user/:id', {
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id } }) => id)
    .listen(3000)

export type App = typeof app
```

</TabItem>
<TabItem label="client.ts">

```ts
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

// Request /user/617
const { data } = await app.user({ id: 617 }).get()

console.log(data)
```

</TabItem>
</FileCodeBlock>

Eden 直接使用 Elysia 已有的类型，无需单独生成客户端代码。客户端只导入服务器的类型，因此服务器实现代码不会进入客户端打包产物。

Elysia 帮你构建可靠的后端，以及与之相连的一切。

## 类型健全性

成功响应只是 API 响应的一部分。Elysia 能推断出**所有可能的响应类型**，包括错误响应，让客户端也能安全地处理每一种情况。

```ts title="server.ts"
import { Elysia, t } from 'elysia'

const plugin = new Elysia()
    .macro({
        auth: {
            cookie: t.Cookie({
                session: t.String()
            }),
            beforeHandle({ cookie: { session }, status }) {
                if (session.value !== 'valid')
                    return status(401)
            }
        }
    })

const app = new Elysia()
    .use(plugin)
    .get('/user/:id', {
        auth: true,
        params: t.Object({
            id: t.Number()
        })
    }, ({ params: { id }, status }) => {
        if (Math.random() > 0.1)
            return status(420)

        return id
    })
    .listen(3000)

export type App = typeof app
```

这里，请求成功时 Elysia 会返回 `number`；同时，类型系统也能推断出 `401` 和 `420` 两种错误响应，让客户端可以类型安全地处理这三种结果。

```ts title="client.ts"
import { treaty } from '@elysia/eden'
import type { App } from './server'

const app = treaty<App>('localhost:3000')

const { data, error } = await app.user({ id: 617 }).get()

if (error)
    console.log(error.status, error.value)
else
    console.log(data)
```

客户端可以分别处理带有类型信息的成功和错误结果。客户端 API 请参阅 [Eden](/eden/)，可复用的路由行为请参阅 [宏](/patterns/macro/)。

## 不限于特定平台

Elysia 针对 Bun 的原生特性进行了优化，但并不局限于 Bun。它兼容 [WinterTC](https://wintertc.org/) 的 Request/Response 接口，因此也能集成到其他运行时。

Elysia 也可以运行在：

- Bun
- [Node.js](/integrations/node/)
- [Deno](/integrations/deno/)
- [Cloudflare Workers](/integrations/cloudflare-worker/)
- [Vercel](/integrations/vercel/)
- [Expo](/integrations/expo/) API 路由
- [Next.js](/integrations/nextjs/) API 路由
- [Astro](/integrations/astro/) API 路由

每个集成都介绍了对应的适配器和部署方式。更多受支持的环境，请查看集成指南。
