<h1 id="_top">Routing</h1>

A [REST API](https://en.wikipedia.org/wiki/REST) takes a path and method to decide which handler to run.

<CodePlayground elysia={demo1}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .get('/', 'Elysia')
    .get('/hi', 'Hello!')
    .listen(3000)
```

</CodePlayground>

> Calling `.listen` will start a web server at port 3000.

We can access our server by going to http://localhost:3000.

- `/` with the `GET` method will return `Elysia`.
- `/hi` with the `GET` method will return `Hello!`.
- Any other path will return a `404`.

Visiting a URL in your browser sends a `GET` request.

<InteractiveStep>

## Static path

A static path is an exact match, with no surprises.

- `/` matches only `/`
- `/hi` matches only `/hi`

</InteractiveStep>

<InteractiveStep>

## Dynamic path

Add `:` followed by a name to capture its value.

`/user/:id` matches `/user/42`, `/user/abc`, and `/user/hello-world`.

</InteractiveStep>

<InteractiveStep>

### Access params

Read the matched value from `params` in your handler.

When `/user/42/profile` matches `/user/:id/profile`, `params.id` is `42`. The handler returns it as the response.

</InteractiveStep>

<InteractiveStep>

### Optional params

Add `?` after a parameter name to make it optional.

`/user/:id?/profile` matches both `/user/42/profile` and `/user/profile`.

The value will be `undefined` if the parameter is not present.

</InteractiveStep>

<InteractiveStep>

## Wildcard

Adding `*` at the end of a path will match any path after it.

`/user/*` matches multi-segment paths such as `/user/hello-world/profile`. In this example, `/user/42` still goes to `/user/:id`, because dynamic paths take priority over wildcards (see [path priority](#path-priority)).

For `/user/hello-world/profile`, `params['*']` is `hello-world/profile`.

</InteractiveStep>

</InteractiveDoc>

## Path priority

Elysia will resolve paths in the following order:

1. static paths
2. dynamic paths
3. wildcards

## HTTP verbs

[HTTP verbs](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods) are the methods of requests, such as `GET`, `POST`, or `PUT`.

To define a standard method, use the corresponding method on the Elysia instance:

```ts
import { Elysia } from 'elysia'

new Elysia()
	.get('/', 'Hi GET!')
	.post('/', 'Hi POST!')
	.put('/', 'Hi PUT!')
	.patch('/', 'Hi PATCH!')
	.delete('/', 'Hi DELETE!')
	.listen(3000)
```

<section class="content-layout">

### Custom method

Define using `.method` with the method name as the first argument. The rest is the same as other methods.

```ts
import { Elysia } from 'elysia'

new Elysia()
	.method('PROPFIND', '/', 'Hi PROPFIND!')
	.listen(3000)
```

### All methods

Catch all methods using `.all`:

```ts
import { Elysia } from 'elysia'

new Elysia()
	.all('/', 'Hi ALL!')
	.listen(3000)
```

## Group

Many paths with the same prefix can be grouped using `.group`:

<CodePlayground elysia={demo3}>

```ts
import { Elysia } from 'elysia'

new Elysia()
    .group('/user', (app) =>
        app
            .post('/sign-in', 'Sign in')
            .get('/profile', 'Profile')
    )
    .listen(3000)
```

</CodePlayground>

It's similar to writing `/user/sign-in` and `/user/profile` separately.

### Prefix

If the entire instance has the same prefix, we can define it in the constructor:

<CodePlayground elysia={demo4}>

```ts
import { Elysia } from 'elysia'

new Elysia({ prefix: '/user' })
    .post('/sign-in', 'Sign in')
    .get('/profile', 'Profile')
```

</CodePlayground>

This is different from `.group` because the prefix is applied to all paths in the instance while group applies to the paths in the callback.
