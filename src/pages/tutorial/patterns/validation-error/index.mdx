# Validation error

If you use `t` from `elysia` for validation, you can provide a custom error message based on the field that fails the validation.

```typescript ins={10,13}
import { Elysia, t } from 'elysia'

new Elysia()
	.post(
		'/',
		{
			body: t.Object({
				age: t.Number({
					error: 'Age must be a number'
				})
			}, {
				error: 'Body must be an object'
			})
		}, ({ body }) => body
	)
	.listen(3000)
```

Elysia will override the default error message with the custom one you provide, see <DocLink href="/patterns/error-handling/#custom-validation-message">Custom validation message</DocLink>.

## Validation detail

By default Elysia also provides a <DocLink href="/patterns/error-handling/#validation-detail">Validation detail</DocLink> to explain what's wrong with the validation as follows:

```json
{
	"type": "validation",
	"code": "validation",
	"title": "Validation Error",
	"status": 422,
	"detail": "must be number",
	"on": "params",
	"property": "/id",
	"found": {
		"id": "string"
	},
	"expected": {
		"id": 0
	},
	"errors": [
		{
			"keyword": "type",
			"schemaPath": "#/properties/id",
			"instancePath": "/id",
			"params": {
				"type": "number"
			},
			"message": "must be number"
		}
	]
}
```

However, when you provide a custom error message, it will completely override <DocLink href="/patterns/error-handling/#validation-detail">Validation detail</DocLink>

To bring back the validation detail, you can wrap your custom error message in a <DocLink href="/patterns/error-handling/#validation-detail">Validation detail</DocLink> function.

```typescript ins={1,10,13}
import { Elysia, t, validationDetail } from 'elysia'

new Elysia()
	.post(
		'/',
		{
			body: t.Object({
				age: t.Number({
					error: validationDetail('Age must be a number')
				})
			}, {
				error: validationDetail('Body must be an object')
			})
		}, ({ body }) => body
	)
	.listen(3000)
```
